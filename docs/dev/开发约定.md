# 开发约定

> 来源：PRD 5.6 技术规范 + 本项目已落地的实践。**偏离前请先在本文补一条决策记录**，否则后续协作者无法判断哪条是约定、哪条是随手写的。

## 1. 命名与数据格式（PRD 5.6.1）

- **全链路 camelCase**：API JSON 字段、JSON 文件存储、未来的 SQLite 列名（`coverUrl`、`uploadedAt`）——**不做存储层与接口层的命名映射**。
- 时间：ISO 8601 字符串（UTC）；时长：秒（number）；文件大小：字节（number）。
- ID：`nanoid` 随机；在线音源曲目在引用场景用 `provider:id`（如 `netease:123456`）。
- 需求编号是通用语言：注释里写清对应的编号，如 `// AC-03：访客级接口`。
- **人为改过的数据要记账，别让自动流程一回冲掉它**（v5.61，AD-02）：曲目元信息可以在控制台手动改（`PUT /api/songs/:id`，只接受 `title/artist/album`），改的是**曲库索引**、不重写音频容器里的标签；索引里同时记下 `editedFields`，**重建索引时保住这些字段**（其余字段照旧按标签重抽）。同类场景（导入覆盖、自动同步、外部拉取回写）都要先问一句：**这份数据是用户改过的吗？我这一写会不会把它冲掉？**
- **只提交真正改过的字段**（v5.61，配套上一条）：元信息编辑的客户端把草稿与原值 trim 后逐字段对比，无改动就返回 null（不发请求）。每次都把整组字段发上去，会把没动过的字段也标成“手动”——它们从此**永久脱离**标签，将来补了标签也不会自动刷新（实现：`client/src/utils/songMeta.ts` 的 `diffSongMeta`，有单测）。

## 2. TypeScript

- **strict 全开**，**禁用 `any`**；确实需要动态类型时用 `unknown` + 类型收窄（现有 `api/http.ts` 的 `isOk<T>` 是范例）。
- 类型导入用 `import type { ... }`（两个包都开了 `verbatimModuleSyntax`）。
- 后端相对导入必须带 `.js` 后缀（`moduleResolution: NodeNext`），例如 `import { sendOk } from "./http.js"`；前端走 bundler 解析，不带后缀。
- 公共导出函数写一行 JSDoc；**注释解释"为什么"而不是"做什么"**（例：`// 载荷不存过期时间——有效期在验签时按当前配置判定`）。
- 不要为了少写类型而放宽 tsconfig；也不要新增 `// @ts-expect-error` 除非同时写明原因。

## 3. 文件与代码组织

- Vue 组件 PascalCase（`PlayerBar.vue`），视图以 `View` 结尾（`LibraryView.vue`），控制台视图放 `views/console/`。
- composable 命名 `useXxx`；其余标识符 camelCase；**文件名与主导出体一致**。
- Pinia store 统一用 **setup 语法**（`defineStore("x", () => { ... })`），返回 ref/computed/函数；派生的布尔量（如 `canUseServer`）放 store 里，不要在每个组件重复推导。
- 一个函数只做一件事；服务端把可测的纯逻辑放 `src/services/`，路由只做"取参 → 调服务 → 回响应"。

## 4. API 设计（PRD 5.6.2）

- 成功 `{ code: 0, data }`；失败用**正确的 HTTP 状态码** + `{ code, message }`（message 给人读）。业务码只在前端需要分支处理时定义（如 `SONG_DUPLICATE`）。
- 分页（LB-08 启用时）：请求 `?page=&pageSize=`，响应 `{ items, total, page, pageSize }`。
- 路径：资源用复数名词（`/songs`、`/playlists`），动作用动词（`/upload`、`/reindex`、`/auth/login`）；音频流走 `/audio`（非 `/api`）。
- 服务端一律用 `sendOk` / `sendFail`，禁止手写 `res.json({code:0,...})`。
- 前端一律经 `client/src/api/*` 封装 + `ApiError`，**不要在组件里直接 `fetch`**。

## 5. CSS（PRD 5.6.5 + VS-08）

- **令牌分组**：`--color-*`（语义色）、`--glass-*`（玻璃拟态）、`--space-*` / `--radius-*` / `--font-*`（当前已落地 `--radius-*` 与 `--glass-*`；新增令牌请归入既有分组风格）。
- 主题变量只定义在 `tokens.css` 的 `:root`（深色默认）与 `:root[data-theme="light"]`；**组件样式只引用变量、不写死颜色**——这是双主题（VS-08）的实现前提。
- **两种材质二选一，不要乱叠**：一级容器（侧栏/内容区/控制台主区/播放条，直接贴着页面背景）用 `.glass`；放在 `.glass` 岛**里面**的卡片用 `.card`（无 backdrop-filter）。玻璃叠玻璃会互相稀释成一片灰糊，也违反 VS-07"模糊层数克制"。`.card` 的投影用 `--card-shadow` 令牌：深色下投影几乎不可见、只当轻压边；浅色下"白卡片 + 白岛面"靠它才能分出层次（去掉投影用户会立刻看得出问题）。
- **悬浮层（弹层/浮窗）**：样式配方已按 v4.59/v4.60 更新，看上面“复杂交互件用 Reka UI”那条的第 ④⑤ 点（行为层用 Reka，样式自己写；材质按“背后有没有内容”选 chrome 玻璃或实底）。旧的“近实底 + 描边 + 投影”手写方案、以及音量浮层那个 `::after` 透明桥接补丁**都已退役**，不要再写回来：Reka HoverCard 的开合延迟 + 可交互内容判定已经把那个 bug 解决了。
- **悬浮反馈用“光”，不用“动”（v4.67）**：控件悬浮时**不要放大/位移**（鼠标刚落上去目标就变，像在躲；且位移会带动周边布局观感）。改用主题色柔光：`filter: drop-shadow(0 0 6px var(--glow-halo))`（**SVG 图标只能用 drop-shadow 上光**，`text-shadow` 对图标无效；`filter` 不改盒子尺寸，天然不扑布局）。注意：一个元素上两条 `filter` 会互相覆盖（`brightness()` 与 `drop-shadow()` 必须写在同一条里）。
- **光效只表达状态（v4.67）**：`--glow-ring` / `--glow-halo` 只用在“可交互（悬浮/聚焦）”与“播放中/选中”两种状态上，两套令牌由 `--accent` 派生（别再写一份 `color-mix(… var(--accent) …)`）。不要用光做纯装饰（光条、光斑、随机的呼吸光），那是 v4.30 “颜色只用于表达状态”的反面。
- **不要旋转原生 `input[type=range]`（v4.64 实测）**：旋转后**点击映射正确、但拖动不跟手**——浏览器用未旋转的几何算拖动位移，看起来就是“拖不动”。需要竖向滑杆就**自绘**（pointer 事件 + 自己算比例，参考 `VolumeControl` 与播放条进度条），并自己补键盘（↑↓/←→/Home/End）与 `role="slider"` + `aria-valuenow`/`aria-orientation`：原生输入框的 a11y 是随旋转一起丢的。`writing-mode: vertical-lr` 是现代替代方案，但 Firefox 兼容性待查，暂不用。
- **换自绘时把原生“白送”的东西逐个对一遍（v4.65 教训）**：换成自绘的那一次，我漏了**底轨**（灰轨本来是原生 range 的轨道，靠 tokens.css 画，自绘后不画就没有），需求方一眼看出“音量轨道不显示了”。清单：底轨 / 已完成填充 / 滑块 / 焦点环 / 键盘 / `role`+`aria-*` / 命中区宽度。
- **复杂交互件用 Reka UI（铁律 1，v4.59 首次落地）**：弹层 / 对话框 / Tab / 菜单 / Tooltip 这类“行为比样式难”的件，行为层一律用 Reka，样式自己写（它是无样式行为层，不是组件库）。落地细则：① 触发元素由**调用方**经插槽传入（Reka 的 `as-child`），不要为了包一个弹层就在新组件里复制一份触发按钮的样式（`QueuePopover` 就这么做的，参考它）；② 列表内滚仍用原生滚动，不要引 `ScrollArea`——全站滚动条是一套自绘样式，两套会打架；④ **弹层的样式必须写在非 scoped 的 `<style>` 里**（v4.60 实测纠正）：Reka 把内容 Teleport 到 body，**Vue 的 scoped 属性不会跟过去**——类名在、选择器带 `[data-v-x]` 永远匹配不上，表现是“弹层能弹出来但完全没样式”（本次两个弹层都因此静默失效过）。隔离靠类名前缀（如 `q-` / `vol-pop-`），一个 SFC 里可以同时存在一个 scoped 块 + 一个非 scoped 块。 **补充判据（v5.40）**：这条只约束“**给别人的元素**写样式”（Reka 自动生成的容器 / 别的组件根元素）。**自己渲染的元素照旧可以 scoped** —— `QueuePanel.vue` 的 class 全部由它自己渲染，元素一定带自己的 `data-v`，所以它写 `<style scoped>` 是安全的，且 Teleport 不影响它（scoped 属性在渲染时就贴上去了，Teleport 只是后来搬 DOM）。要包别人的元素、又确实需要隔离时，优先用 `:deep()`；⑤ **同一按键有多层监听时，层级语义要由最上层“吃掉”事件**（v5.40）：沉浸页在 `window` 上听 Esc（收起整页），Reka 弹层也在 `window` 上听 Esc（关自己）—— 两者同级时“谁先注册谁先跑”，靠 `@escape-key-down` 里 `stopPropagation()` 拦不住（它跑在冒泡里，太晚）。正确做法是最上层挂**捕获阶段**的监听（`addEventListener(..., true)`）：拦住事件 + 自己关掉最上层，保证“Esc 只关最上面那层”；
  ⑤ **材质是阶梯，不是二选一（v4.60 → v4.63 修正）**：页面底 → 岛 / 播放条（`--chrome-bg` / `--chrome-blur`）→ **弹出的临时面板**（`--panel-bg` / `--panel-blur`，更实一档、糊得更强、带 `--panel-sheen` 内高光与自己的 `--panel-shadow`）。越靠上的层越实，这是 iOS 的做法。
  **v4.60 我写过“背后是平坦底色就用实底 `--plane-2`”，那个结论是错的**：真正的毛病是**面板与它下面的层用了同一个填充值**（音量面板浮在同样是 `--chrome-bg` 的播放条上），同色叠同色等于没画。修正后两处弹层都用 `--panel-*`，仍然是玻璃。
  另：`--shadow` 在 flat 模式被归零（那是“岛浮起来”的语言）——**浮层的投影不要用它**，用 `--panel-shadow`（“浮层该浮起来”在两种材质模式下都成立）。④ 浮层材质用 `--chrome-bg` / `--chrome-blur`（内容会从它下面经过，玻璃在这里才成立）。
- **列表内滚动不要包 ScrollArea**：同上一–②。
  - `--shadow` = “岛浮在页面上”（页面级、大扩散）；`--card-shadow` = “这张卡片是表面上的一个分组”（岛内、贴边）。撤页面级投影时**不要顺手把 `--card-shadow` 也归零**（需求方 v4.56 当场指出）——但**影与边不是二选一**：影管深度、边管边界。
  - **几何事实（别再踩）**：我们的投影全是**朝下**的偏移（`0 1px 2px` / `0 10px 22px -16px`），所以**上边缘永远没有影**。白卡落在白面板上时，上半部分必然融进背景（需求方 v4.57 实拍：“卡片上部阴影不清楚”）；白色没法再提亮，这条边界只能由描边给。别用“给投影加负偏移造上影”去糊——那会把下边缘的深度感一起做脏。
  - **判据：看相邻两层的色差**。色差足够大（白岛 vs 灰页）不用线；色差为零（白卡 vs 白岛）必须有线。深色下卡面 `--plane-2` 比岛面亮一档，色差本身就说明分组，细线只负责收边。
- **沉浸页三布局只放版式，页面级差异写进一张表**（v4.74）：`views/ImmersiveView.vue` 用 `LAYOUTS` 表把“组件 + 该布局要不要页面级右下环境光”一起声明（海报布局下彩胶的有机光晕是画面唯一主光源，右下那束同色环境光会读作色渍，PRD v4.3）。**不要**让布局组件盖一层不透明底去关掉页面背景——那会在顶栏/底栏处留一条接缝；也**不要**给 `<html>` 挂 `data-im-layout` 用类切换布局（v4.0 决策：布局是组件切换，不是类切换）。
- **位置与尺寸必须“同源派生”**（v4.75，通用规则）：一个元素（彩胶盘、背景光晕、任何吸附角落的装饰）**只能有一个尺寸驱动源**，偏移量再从该尺寸派生（`calc(var(--d) * -0.31)`）。混用 `vh` / `vw` / `min(...)` 会让“尺寸”“上偏移”“右偏移”各有各的缩放率，窗口纵横比一变就各漂各的（实测：彩胶盘心在窗口宽的 88%～94.8% 之间摆，需求方描述为“到处跑”）。需求方说“位置飘 / 到处跑”时先查这条。窄屏媒体查询里**只改尺寸**，偏移跟着派生，不要手写第二份。**更彻底的做法（v5.85）**：能交给版式就别算偏移 —— 彩胶从“右上角溢出的背景盘”改成栅格的一列后，两个偏移直接删掉，盘的位置由栅格给，连“同源派生”都不需要了。判断一个吸附角落的装饰是“真装饰”还是“在占位子”：需要唱臂、标签、连体阴影这类与它对齐的东西时，它就是版式的一部分，该进栅格。
  **会摆动的元素要留出“扫过的空间”，不是它静止时的那点地方（v5.88）**：唱臂抬起时扫到盘径的 125%（唱头壳 132%），静止在盘上时只占 100% —— 按静止位置给右侧余量（0.08 盘径），一暂停针就被窗口裁掉。同类的还有抽屉、菜单的方向性动效、会转的装饰。判据：**量动效两端的位置**，按最远的那个给地方。**而且余量要对称留**（v5.88 补）：只在右侧留、左侧为零时，容器中心与主体中心不重合 —— 窄屏直接居中容器，主体就偏了；两列布局里主体也偏半格。左右各留一份、上下各留一份（哪怕其中一份是“配重”），主体才能在各处都正中。最后：**所有派生自留白的偏移都要一起改**（光晕、阴影、装饰层）—— 忘了就跑到一边去，看上去像“主体发灰发虚”。
  **一张图做不到的“活”，用多团渐变叠（v5.89）**：固定形状的 mask/图片只能整团转，看着是硬的；把柔光拆成 3 团带不同圆心、不同大小、不同转速（且转速互质）的 `radial-gradient` 叠起来，形状就在持续变形，周期还长到人看不出来（这里 8/13/17 → LCM ≈ 30 分钟）。颜色仍然只取一次（放 `currentColor` 到容器上），三团共用；暂停/减动效要三团一起管 —— 只写容器会漏掉伪元素那两团。
  **能只用合成层属性表达的效果，就别开画布（v5.91）**：节奏起伏从 v5.90 的 canvas 加法光改成“JS 每帧只写一个 CSS 变量，`transform` / `opacity` 用 `calc()` 表达”（`--beat` → `scale` / `opacity`）—— 逐帧改变量不重绘渐层，比逐帧光栅化便宜得多。判断顺序：先问“这个效果能不能只靠 transform / opacity 说清”，能就别画布；canvas 留给“任意形状、随机分布”这类 CSS 真做不到的事。**“没有音频时天然为零”仍然要保证**：拿不到频谱 / 关了开关 / 减动效时变量恒为 0（就是纯底光）—— 于是不需要任何降级分支（同 v5.90 的原则）。
  **动效的“幅度”要量，不能凭感觉定（v5.91）**：第一版把低频**均值**直接缩放上去，看着像没动 —— 实测 `--beat` 挤在 0.70~0.89，缩放只差 1.3%。两条通用做法：① 指标要挑“对事件敏感”的那一个（取频段**峰值**而不是均值，均值会把鼓点摊平）；② 慢跟随估出“常态 + 常态波动”，只表达**相对常态的变化量**（自动量程）—— 于是与音量、段落无关，安静的歌与响的歌都有一致的起伏，也不用给每首歌调参。
  **开销大的东西只能有一份，消费者去订阅（v5.90）**：音频分析（要 FFT）全局只跑一个 rAF 循环，画面按帧回调去画；两处各跑一圈既重复又难同步。开启条件（在播 / 开关 / 减动效）只在循环那一处判。
- **取色管线的三条落地规则**（v4.77，VS-02 落地时实测得出）：
  - **JS 只写原始色源**（`--cover-src / --cover-src-2`），调校全在 CSS（铁律 3）；`--accent/-2/-soft`、`--glow1/2`、`--cv1/2`、`--vinyl-gradient` 全是派生，不许 JS 写。
  - **主题色的彩度地板要比彩胶高**（0.11 vs 0.07）：主题色落在悬浮行 / 进度 / 主按钮这类小面积交互件上，灰调封面取出来的暖灰会把整页染“脏”，连“这是个按钮”都读不出来；彩胶是大面积装饰色，按 PRD 保持“不强行提艳”（晨雾那类低饱和配色有理）。两者诉求不同，不要用一个书。
  - **填在主题色底上的文字用 `--on-accent`，不要写 `white`**：主题色现在由封面决定，深色主题下它是浅色，白字实测只有 1.91:1；`--on-accent` 取主题底色（深色主题近黑 / 浅色主题纯白），实测 ≥ 5.3:1。
- **手机底栏要铺满时，“距两边多远”只留一处（v5.93）**：沉浸页底栏原来两侧各空 71px（控制区自己 `min(560px, 74vw)` + 容器 20px 内边距两处叠加）。改法：容器只给侧内边距（`14px`，不贴边是因为进度条手柄画在填充末端、贴边会被裁掉半个）、控制区写 `min(560px, 100%)`（**宽度只认容器一处**，同“同源派生”）。三组控件均分到两端用 `grid-template-columns: 1fr auto 1fr`，**不要用 `space-between`**：后者按两侧内容宽度分配空间，左组 22px / 右组 66px 时中间那组会被推偏 22px —— “播放键中心与进度条中心对齐”（v5.70）这类对齐契约在手机上同样要成立。另外子项要显式 `width: 100%`：父级是 `align-items: center` 的列时子项默认收缩成内容宽，会与相邻那行错开（实测 324 vs 362）。桌面档不动（聚拢的一簇在那里更好点）。
- **媒体查询写在基础规则之后（v5.94 实测踩到）**：两者特异性相同时靠**源码顺序**分胜负 —— 把 `.im-progress` / `.time` 的基础规则留在文件末尾（媒体查询之后）时，手机档那句 `display: grid` 被压回 `flex`，而同一块里的 `grid-template-areas` 却照常生效，量出来是 `display: flex` + `grid-template-areas: "bar bar" …` 这种**不可能的组合**（半套生效最难查：几个属性生效、另一个没生效，看代码怎么也看不出问题）。写 SFC 的 `<style>` 时按“**基础规则 → 媒体查询 → 装饰性补充**”排；要覆盖就让自己**写在后面**，而不是指望特异性。
  **特异性也会分胜负，别只靠顺序**：`.row:hover`（0,2,0）会盖掉 `.row--active`（0,1,0）的底色 —— 悬浮到当前曲目那一行时它会从主题色淡底（α .14）掉成更淡的通用悬浮底（α .06），越 hover 越不像当前曲目；“当前项”的强调要保住就得补一条 `.row--active:hover`（v5.95 实测）。
- **底部控制栏的控件数取奇数，正中那枚必须是播放键（v5.98）**：需求方：“是控件数量不是奇数个带来不对称”。偶数个控件时“正中”落在两组之间，谁也到位不了（彩胶底栏曾是 模式/上一首/播放/下一首/音量/收藏 = 6 个，实测播放键比进度条中心偏左 21px）；改成 5 个后偏差为 0。两条配套：① “居中”要的是**左右同时对称**（数量奇 + 两侧宽度相等，例：模式 22px ↔ 音量 22px）；② 要加一个控件时先问它该不该在这一排 —— 歌曲强相关的动作（收藏）归**歌名旁边**，别往走带那一排塞。：页面级摘要（总数 / 总占用）归**页头**，工具栏那个位置只负责**筛选结果**（“找到 N 首”，没筛就不说）—— 需求方对着音乐库截图指出页头与工具栏各报了一遍“14 首”。两条配套：① 那种“右侧一行字”的位置要留一个常驻 spacer（`margin-left: auto`，空着也占位），直接删元素会把右边的按钮带到上一组控件旁边（曲库管理的批量删除按钮）；② 卡片的数字**没读到就给破折号，不给 0** —— “没数”与“真的是 0”必须能区分（概览页原先写死 `0`，页面一直在说假话，v5.97 接上 `/api/stats`）。
- **同一件事不要在列表行里再说一遍（v5.95）：更彻底的一步（v5.96）**：行内的“正在播放”不要靠“把那一行的操作键钉成常显”来表达 —— 行自己已经说了（歌名主题色 + 加粗 + `--accent-soft` 底色），底部播放条也一直在说；**而且行里连播放/暂停键都不放**：点整行就是播这首（触摸从 v5.32 起就是这样，v5.96 扩到鼠标，同时去掉“桌面双击”那层 —— 播放键没了，双击不再是必要的兵底，而且它会让第二下把这首歌从头再放一遍），行尾那列只放**对这首歌的动作**（收藏、从列表移除）。定调：列表是“选播哪一首”的地方，播放/暂停归底部播放条与沉浸页（“再点一下即暂停”这类分支也一并删掉）。两个附带条件：① 行要有可点的指示（`cursor: pointer` + `播放 <歌名>` 的 `title`，**当前曲目那行不给** —— 它没有“播这首”的语义）；② 点**已经是当前曲目**那行**不做事**（不重启、不暂停）。
- **渐隐遮罩（mask）只能罩「内容」，不能罩「浮在内容上的控件」**（v4.79）：上下渐隐那层 `mask-image` 原来挂在歌词外壳上，结果底部的「回到当前句」按钮被一起淡掉（实测几乎看不见）。拆成两层——外壳只负责定位并承载按钮、内层 `.ly-view` 负责渐隐与裁剪。同类的地方（列表渐隐 + 悬浮操作条 / 回到顶部按钮）都按这个来。
- **歌词引擎：机制参考，代码自己写（v4.86）**：歌词的渲染、景深、填充、交互与弹簧都是我们自己的代码（`components/immersive/LyricsView.vue` + `utils/lyrics.ts` / `utils/spring.ts` / `utils/lyricEmphasis.ts`）。AMLL 的作用是**参系对象**：v4.82 对照它的机制自研、v4.85 按需求方意思“拄代码”、v4.86 又把拄来的部分改成**按公式/按效果自行实现**（弹簧是阻尼简谐振子的解析解、辉光爆发按峰形曲线自己生成）。规则：**想做一个效果，先看它怎么做（思路可以学），然后按自己的数据模型与令牌写（代码不要拄）**——这样许可干净、后续也能随便改。
- **依赖许可每次都要查（铁律 9）**：本项目不含 AGPL / GPL 代码（现状：无 `LICENSE`、`package.json` 无 license 字段）。装新依赖前先 `npm view <pkg> license`，确认宽松许可；**强拷贝依赖一个都不要引入**。
- **遮罩渐隐带与「留白 / 内缩」必须同源（v4.82 → v4.83 修正）**：写了渐隐遮罩的地方，若还需要留白来避开这条带，**宽度只能有一份**（写成 CSS 变量，JS 用 `getComputedStyle` 读同一个值，不要在 JS 里另写一份）。**但更根本的解法是不留白**（v4.83）：上一版为了把当前句推出顶端渐隐带，在列表顶部垫了 57px 留白，结果在标题与第一句之间凭空多出一条空当（需求方圈图，DevTools 直接圈出 `padding-top: 57px`）。现在的做法：**顶端渐隐按需开关**（`--ly-fade-top`，列表没滚动就完全不淡——顶上本来就没有正在离开的行），留白随之取消；留白只在真的有用途的地方才加（列表底部半屏，是为了让末句能走到中线）。教训：**用空白去规避一个视觉副作用之前，先问这个副作用在当前状态下是否真的存在**。
- **歌词列表的位移口径：正值 = 列表上移（v4.86 实测踩坑）**：`centerShift` / `clampManualShift` 的位移都是**正值代表列表往上走**（DOM 那边写 `translateY(-shift)`），取值范围 `[0, 可达上限]`。**上限不是“内容总高 − 窗口高”**：列表末端垫了半屏留白（为了让末句能走到中线），末句到中线时内容反而比窗口矮，那样算出来的上限是 0——表现为整个列表永远不动（自动居中与手动滚动一起废）。正确口径：**上限 = 末句中心到窗口中线所需的位移**（`lastCenter − viewH/2`）。同类“列表靠 transform 位移”的场景照此办理。
- **封面的动效语言：摆正 + 用缩放表达状态（v4.89）**：音乐播放器的封面参考实现（AMLL 的 `react-full/Cover`，Apple Music 同形态）都是**平面**的——没有 rotate、没有指针跟随，也不做“呼吸浮动”；播/停的差别用**缩放**说（暂停 `scale(0.9)` + 投影收紧，曲线带一点回弹）。3D 倾斜/视差是**影音与电视类**封面的语言，不要搬到音乐封面上。圆形彩胶盘的旋转是另一回事（海报布局的专属视觉层）。
- **同一列内的文字只能有一条左边界（v4.88）**：沉浸页的标题与歌词共用同一个横向内缩令牌（`--im-text-pad-x`）——两处各写一份 padding 迟晚会错开。想给某一块“加呼吸”就改令牌，不要只改那一块。
- **带模糊/发光的内容配 `overflow` 裁剪时，裁剪框要比内容宽出一圈（v4.88）**：写法是“负外边距 + 等量内边距”（内容位置分毫不动），否则模糊出来的软边会被齐着切掉、在边缘形成一道硬线。同理，裁剪框不要紧贴文字。
- **导入外部文本文件一定要做编码回退（v4.87）**：中文歌词文件相当一部分是 GBK（老播放器导出的都是），硬按 UTF-8 读是满屏乱码。统一口径：先认 UTF-16 的 BOM → 试 UTF-8 → 出现替换字符（U+FFFD）就换 GBK 再试一次；解码器不存在时宁可返回原文也不要抛出去（实现见 `utils/lyricsLibrary.ts` 的 `decodeLyricsBytes`，有单测）。同类的“用户提供的文本文件”场景（导入、粘贴、拖入）照此办理。
- **跨页面传递不可序列化的东西（File / Blob / 类实例）用一次性交接 store**（v4.80，LC-07）：不塞路由 query、不塞 URL、也不靠模块级全局变量裸传——本地页 `queue(files)`、上传页挂载时 `take()` 取走并清空，刷新或后退都不会重复触发。**与它配套的登记处（如原始 File）生命周期必须与它标记的资源对齐**：`releaseTrack()` 里 `revokeObjectURL` 的同时忘掉 File，否则会拿着一个早已移除的曲目的文件去上传。
- **本地图片资源放 `client/src/assets/<主题>/`，CSS 里用相对 `url()` 引用**（v4.74，如彩胶四张素材）：Vite 会构建期哈希打包、路径跟着文件走；别写 `/public` 绝对路径（改目录就断），也别内联 base64（大图会撑爆 CSS）。
- **材质的可读性只加一层**（v4.74）：沉浸页已经有页面级薄雾保证文字可读，布局**不要**再加第二层方向性遮罩——多层叠起来既会把主视觉（如彩胶左缘）掠白，也违反“同一页面只保留一套分隔/压暗语言”。
- **材质双模式（v4.55，不要新增第三种写法）**：`<html data-material>` 只有 `islands`（默认，玻璃浮岛）与 `flat`（中性底色 + 实心面板）两个值，**只在 `client/src/styles/material.css` 里按模式重定义令牌**（`--bg-base` / `--plane` / `--glow*` / `--shadow` / `--card-shadow`），并只覆盖三个外壳类：`.glass`（页面级容器）、`.card`、`.playerbar`。规则：① 组件不得用 `data-material` 选择器分叉自己的样式，也不得写死颜色——想“在两种材质下都好看”就只用令牌；② `.glass` 是“页面级容器”，玻璃在该模式下不成立时就由 material.css 统一改成实心面板，不要在组件里另写一套；③ **玻璃只用在“内容会从它下面经过”的层**（浮层、沉浸页浮件）——玻璃后面没有高频细节（平滑渐变背景）时，模糊等于没有，效果只剩描边+投影，那就成了卡片，不是玻璃（v4.55 实测结论）；④ 新颜色一律先用 `--plane` / `--chrome-*` 之类的语义令牌，不要往组件里写 `#fff`；⑤ **flat 下“实心”是彻底的（v5.92）**：连 chrome（播放条）也是实心面，不留任何 `backdrop-filter` —— 原先给播放条留的 chrome 玻璃在浅色下叠在页底上只差 **3/255**（需求方：“音乐控件那块都快和背景融为一体了”），所以 flat 的面板色取 `--plane-2`、模糊全撤，**层级改由一条朝上的投影给**（`--chrome-shadow`：播放条贴在页面下沿，而本仓的投影全是朝下的偏移，它一条都吃不到 —— 见上面“几何事实”那条）。**但这层影不能“深”（v6.7）**：需求方对着浅色设置页说“上半部分的阴影是不是没有播放控件那块的深，给我的感觉是播放控件的层级比它们高”——原值 `0 -14px 34px -20px` + α .32/.6 是**宽、柔、深**的“浮得很高”语言（与浮层同一族），于是同屏上它比卡片高出一大截。**层级感来自模糊半径 + 偏移（贴得近 = 紧），不是浓度**：常驻面（岛内卡片 / 播放条）用**同一族几何**（`1px 2px` 贴层 + 浅色再给一片 `10px 22px -16px`），播放条只把方向翻上来；大柔影（`20px 46px -16px` 那一档）**只给真的浮起来的菜单 / 弹窗 / 提示条**。判据：同页的**常驻面投影应该长度相同、只差方向**；发现某一面比别人深一档，就是在暗示一个不存在的层级。⑥ **两套语言的分工（v6.2 需求方定稿：“实心面板：实心、阴影；玻璃浮岛：透明、光效”）**：光效（`--glow-halo` 系的悬浮光与光晕、播放键那圈 `--glow-ring` 描边、`--soft-btn-glow`）**只属玻璃浮岛**；flat 下把这三个令牌换成 transparent / none 即可（组件仍不动），层级全交给投影。播放键那层阴影是**写死的**、不受令牌约束，flat 下要单独覆盖（并把悬浮反馈从“光”换成中性投影，否则主按钮悬停毫无反应）。**软底与淡边两种材质都保留** —— 它们表达状态，不算光效。
- **列表页骨架是“岛不滚、只有内层滚”（page-frame，v4.36 定稿）**：页面根元素用 `<section class="page-frame">`，页头与操作区是它的普通子元素，列表放进 `.page-frame__scroll`（只有这一层 `overflow-y: auto`；它靠负的左右外边距铺到岛边，滚动条贴岛）。要生效必须满足两条：① 岛（`.content` / `.cs-main`）在该页是 `overflow: hidden`；② 从岛到页框的**每一层包装都要把高度传下去**（`height: 100%` / `min-height: 0`）。⚠️ 判“岛里有没有页框”一律用**后代匹配**（`.cs-main:has(section.page-frame)`）—— 直接子选择器一旦被新包装层隔开就静默失配，症状是**页头跟着列表一起滚**（v5.79 实测：控制台多一层 `.cs-body` 后页头 top 从 14 滚到 −226，而音乐库稳定在 36）。加/改布局包装层后，按“**页头位置 / 岛能不能滚 / 内层能不能滚**”三项量一遍。
  **表头（“说明”行）必须在滚动区外面**：曲目列表的做法是 `TrackListHead` 当页框的直接子元素（不吸顶、不加底色）；控制台那张“表”本身是卡（`.songs.card`），做法是把滚动区**放进卡里**、表头留在卡顶 —— 两者共享卡的同一套内边距，天然对齐（卡里的滚动区要撤掉全局那条“负边距铺到岛边”，并由表头让出滚动条宽度）。**行距要加在滚动区内部**：窄屏不画行间细线、改用间距分隔时，间距必须落在行与行之间 —— 行现在住在滚动区里，加在卡上的 gap 只能分开「表头 / 滚动区」两段（v5.80 就是这么把窄屏行距弄丢的，v5.82 补回）。**别用吸顶**：吸顶要不透明底，而玻璃岛上它一定露成色带（v4.41）。表头与行的列宽必须逐列一致，**空占位格也要与行里对应的内容同宽** —— 否则 `1fr` 列会多吞一段、整排标签漂移（v5.79 实测错位 48px）。
  表头是**说明行**，高度与曲目列表同档（`34px`，11.5px 标签、不加底色）；表头若与行共用同一个网格类，必须显式关掉行那条 `min-height` —— **`min-height` 压得住 `height`**，只写 height 的话表头实际仍是行高（v5.80 实测 64px，看着就是一大块空白）。
  **列表页骨架现已全部统一（v5.81）**：音乐库、本地、在线、控制台曲库管理、我的收藏、最近播放、歌单详情七页都是「页头 + 唯一滚动区」，状态一律进 `.page-frame__fill`。**歌单详情的封面 / 名称 / 操作区也是页头**（钉住不滚）—— 判据是“你还会不会再用它”：纯标题性的封面块可以跟着滚，带操作的一律钉住（播放全部 / 添加曲目 / 重命名 / 导出 / 删除都还在用）。
  **`flex: 1` 就是 `flex: 1 1 0%`，与一组按钮同排时会被压成 0 宽**（v5.81 实测：歌单名“一个字一行”竖着排，因为 `.pl-info` 的基准宽度是 0，按钮组一挤就归零）—— 这种“撑满剩余空间”的块要用 `flex: 1 1 auto` 再给一个保底宽度（`min-width`），宁可让按钮组内部换行，也不要让这一块消失。
- **浮层材质只有两档，别自己拼（v5.78）**：① `--panel-bg` + `--panel-blur` + `--glass-border` + `var(--panel-sheen), var(--panel-shadow)` = **列表类浮层**（队列、音量、提示条、对话框）；② `--tray-bg` + `--tray-blur` + 同一套边/高光/投影 = **成片文本与大面**（菜单、抽屉）。两档都靠“描边 + 顶部内高光 + 投影（含主题色光晕）”说明层级（v5.2 定调），**不要**再写 `blur(18px)` / `--shadow-N` / `--line` 这类散件；`--chrome-*` 是给**无边无影的常驻条**（播放条）用的，拿它当菜单底就是一块平板（v5.78 实测：歌词来源菜单就是这么写歪的，与旁边两个菜单对不上）。
  **flat（纯色）下都是实心（v5.81 / v5.92）**：判据是本文件开头那条 —— 没有内容可模糊时，玻璃剩下的只有“半透明”这个副作用。原先只有菜单/抽屉/对话框退了，音量、队列、提示条还留着玻璃，同一页上就是两套观感（v5.81）；**v5.92 起连 chrome 也退实心**（播放条不再读 `--chrome-blur`，改读 `--chrome-shadow`），flat 下再没有任何 `backdrop-filter`。实现只在 `material.css` 的 flat 块里改令牌（`--panel-bg: var(--plane-2)`、`--panel-blur: none`、`--tray-bg: var(--plane)`、`--tray-blur: none`、`--chrome-bg: var(--plane-2)`、`--chrome-blur: none`），**组件一行不用改**（它们只读令牌）。注意 `--panel-sheen` 不要置 `none` —— 它是被 `box-shadow: var(--panel-sheen), var(--panel-shadow)` 拼进列表的，`none` 会让整条声明失效。**菜单与抽屉不必再拆档**：两者的玻璃取值本来就相同，flat 下的区别已经落在各自读的阴影令牌里。
- **悬浮展开的浮层必须“桥接”触发器与面板之间的空隙**：鼠标从触发器移向面板时会经过一段不属于两者的空白，`mouseleave` 会先把浮层收起（用户实测报过这个 bug）。解法：面板上挂一个覆盖空隙的透明伪元素（`::after`，高度=间距），再在底部加一个指向触发器的小三角（旋转 45° 的方块，`background: inherit` + 朝外两条边着色）。不要靠缩小间距来躲这个问题。
- **Service Worker 只缓存构建产物，后端的东西一条都不进缓存**（v5.65，RT-07）：`vite-plugin-pwa` 的 `globPatterns` 只覆盖 `dist/`；`/api`、`/audio`、`/covers` 同时写进 `navigateFallbackDenylist` —— 它们是后端挂在根路径下的路由，漏了就会在离线时被兜底成一份 `index.html`（与开发代理漏配 `/covers` 是同一个毛病，见 AGENTS 坑 11）。**以后后端再加根路径路由（如 `/lyrics`），这两处一起补。**
- **静态托管的缓存策略：入口与 SW 不缓存，只有哈希产物长缓存**（v5.66）：`index.html` / `sw.js` / `manifest.webmanifest` / 图标一律 `no-cache`（一旦被缓存住，下次更新就推不下去，用户永远看到旧版本）；`assets/` 下带内容哈希的产物才给 `immutable`。判断交给 `server/src/static.ts` 的 `staticCacheControl`（纯函数、有单测），别在别处再写一套。
- **什么时候用提示条、什么时候就地提示（v5.72）**：提示条（`utils/toast` 的 `showToast`，宿主 `components/AppToast.vue` 全站一份）只装**与用户当前操作无关、或者消失掉也不影响继续操作**的消息 —— 播放异常、后台任务的结果、一次性的回执。**绑在某个控件或表单项上的错误留在原地**：表单校验（均衡器存名字失败）、上传队列里某一行的失败、曲库加载失败那种带“重试”的失败面板 —— 它们要一直看得见，而且就该出现在出问题的地方。两条实现约定：① 提示条容器（`.toast-vp`）必须 `pointer-events: none`，只有提示本身 `auto` —— 否则一块隐形容器会挡住窗口右下角那一片（与坑 21 同一族）；② 它要落在播放条**上方**，位置读令牌 `--playerbar-h`（外壳栅格用同一个值），别写死像素。`tone` 只在**出错**时用 `danger`（颜色只表达状态）。
- **触摸反馈自己画，UA 那两层都得关（v6.16 / v6.17）**：手机上有两层不是我们画的东西 —— ① **点按高亮**（UA 的 `-webkit-tap-highlight-color`，Chrome 默认 `rgba(0,0,0,0.18)`，盖在按钮/导航项/tab 上就是一层蓝灰光斑，各平台颜色还不一样）；② **长按选文字**（我们的 `::selection` 是 30% 主题色，按住按钮不放系统就开始选它里面的字，看着像“这枚键被选中了”）。两条都在 `global.css` 里一次性关掉：`html { -webkit-tap-highlight-color: transparent }`（继承属性，写根上）+ 交互件（`button` / `a` / `label` / `[role=button|tab|radio|switch|slider]`）统一 `user-select: none` + `-webkit-touch-callout: none`（顺带关掉 iOS 长按的“复制/查询”浮层）。**新增交互件不要再各写一份**；同时**必须**给 `input` / `textarea` / `[contenteditable]` 显式写回 `user-select: text` —— `user-select` 是**继承**属性，不写这一条会一路传进输入框（Chromium 对可编辑元素有特殊处理，实测照旧能选，别的引擎不保证）。反馈不会因此丢：`.btn:hover` / `.ctl:hover` / `.tab:hover` 这些自绘状态在触摸设备上由浏览器在 touchstart 时套用。判据：量“能不能选中”要用真选区（`window.getSelection()` / `input.selectionStart`），量点按高亮看 `getComputedStyle(el).webkitTapHighlightColor`，别只看截图。
- **全屏页/弹层里的高度只能用“剩余空间”算，绝不能用固定 vh（v6.15 实测）**：沉浸页三布局窄屏原先给歌词窗口写的是 `38vh / 30vh / 40vh` —— 它们只知道屏多高、不知道上面已经被封面与标题占掉多少，于是在 375×667（iPhone SE）上比容器高 48px；而 `overflow: hidden` **只管窗口内部**（列表不会溢出窗口），管不住**窗口本身**越过容器边界 —— 下半截就画到了进度条背后（`.im-bottom` 在后面，正好盖住它）。写法固定为：① 先把高度拆干净（`grid-template-rows: auto minmax(0, 1fr)` / `flex: 1; min-height: 0`）；② 让要伸缩的那一层 `flex: 1 1 auto; height: auto; min-height: 0`（只给**下限**，不给固定高）；③ 确实需要上限时用 `max-height`（它不会把容器顶破）。
  **同族坑（同一个坑里挖到的）**：`align-items: center` 的栅格里，**栅格项默认不拉伸**，高度还是内容高 —— 里面那些 `flex: 1` 因此没有“剩余空间”可分，直接按内容撑开（实测海报布局的歌词窗口变成 **8502px**）。所以“给某一层一个确定高度”这一步必须显式做（栅格行是 definite 时 `height: 100%` 就够）。判据：量**要伸缩那一层的盒子**，别只看它的子元素。
- **快照字段只用于兜底，显示一律先问实时数据（v5.58 / v6.13 / v6.14）**：`PlaylistItem` / `RecentEntry` 这类“引用 + 一份展示快照”的结构里，`title` / `artist` / `cover` 都是**加入那一刻**的值，之后可能过期 —— 曲名被手动改过、封面被手动换过（v6.13 起换封面是**新文件**，旧 URL 直接 404）、曲目被删过。所以解析层（`utils/playlistEntries` 的 `displayMeta`）统一输出“实时优先、快照兜底”的三元组（`title` / `artist` / `cover`），页面只读解析结果，不再碰 `entry.item.xxx`。**新增任何快照字段都照这一条办**：先问实时，拿不到再退快照；直接渲染快照的结果不是“旧”，而是**破图**（实测旧封面 URL 404）。
- **同一套控件出现在两处宿主时：逻辑共用、版式各留（v6.12）**：播放条与沉浸页原本各写一遍“模式图标映射 / 播放图标 / 总时长 / 指针拖进度 / 键盘 ±5 秒 / `role=slider` 与 `aria-*`”，只靠一句“改一处记得同步另一处”的注释拴着 —— 新增一种播放模式就会只改一边。拆法固定为三层：
  - **状态与图标**进 composable（`composables/usePlayback.ts`），图标映射写成 `Record<PlayMode, Component>`：漏一种模式**当场类型报错**，比断言更硬；
  - **单一控件本体**进组件（`components/ProgressBar.vue`：轨道 + 填充 + 手柄 + 指针捕获 + 键盘 + `role`/`aria-*`），**但它只管自己在容器里怎么画、不负责周围那一圈**（两侧时间、桌面一行 flex / 手机两行 grid 都留在宿主）—— 这样两处版式一行不用改就能共用；
  - **有算法的收进 `utils/` 纯函数**（`utils/seek.ts`），实现与测试同次提交。
    反例记一笔：**别把“看起来像滑杆”的东西直接拄到 `utils/slider.ts` 上** —— `stepValue` 会把值对齐到步长整数倍（绝对控件正合适），而“快进 5 秒”是**相对位移**，从 7 秒按一下会跳到 10（只走了 3 秒）。形状相同 ≠ 语义相同。
- **“读取失败”不等于“真的没有”（v6.11）**：请求失败**不许**退化成一个业务上的否定结论，更不许永久锁死。反例（健康度体检抓到）：
  - `stores/config` 原先在 `catch` 里也把状态置成“读到了”、`onlineEnabled = false` —— 后端没起来时界面会说“在线音源未配置、去改环境变量”，把人指错方向；现在 store 给 `status: idle / loading / ready / error` + `load(force)` 可重试，**“未配置”只在真读到配置后才说**；
  - 音乐库的**收藏状态**读失败时，行尾的心会一律显示成“未收藏” —— 看着像“这首歌没收藏过”，点一下还会发出一次**错的写请求**。
    规则：凡是“读失败会让界面显示成另一种事实”的地方（配置、收藏、歌单引用、权限），一要**明说读失败**（可重试的提示条 / 失败空态），二要留一个**重新拉取**的入口；失败态与空态是两种状态，不要共用一个变量。
- **批量文件处理一律带并发上限（v6.10）**：拖入文件夹 = 几百个文件，而每个都要走一遍**整文件解析**（读标签 / 探时长）。`forEach + void promise` 那种无上限并行会让几百个解析同时开工（内存峰值 + 主线程调度）。统一走 `utils/concurrency.ts` 的 `mapWithConcurrency(items, limit, worker)`（本地播放用 **4** 路）：结果与入参一一对应、单件失败不连坐、`limit` 边界值都安全（都有单测）。
- **列表页的搜索框：输入值即时，过滤值防抖（v6.10）**：过滤是“每敲一个字全量 filter + map / 排序”，369 首就是每次按键几百次 `encodeURIComponent` 或 `localeCompare`。写法固定为“输入框绑即时 `keyword` + 过滤读防抖 `query`（`utils/debounce.ts`，150ms）+ 卸载时 `cancel()`”——**别把输入框直接绑在防抖值上**：那会让输入框显示旧值、光标乱跳。列表项转换用 `songToTrackCached`（按 `Song` 对象缓存）：同一条曲目只要对象没换就拿到同一条 `Track`，行组件的浅比较才挡得住重渲染。
- **JSON 数据的唯一实现是 `services/jsonStore.ts`（v6.8）**：曲库索引（`services/storage.ts`）/ 歌单（`services/playlists.ts`）/ 收藏与最近播放（`services/listening.ts`）都只是它的薄封装，**新加一份 JSON 数据也走它**，不要再手写“读文件 → JSON.parse → 写 .tmp → rename”：
  - 写入用 `save`（临时名带**随机后缀**，固定 `.tmp` 名在并发写时会交错）；
  - **路由里的“读一份、改一份、写回”一律用 `update(dataDir, mutator)`** —— 同一份文件的操作在进程内排队，否则两个并发写会互相覆盖（lost update）。mutator **原样返回同一个引用 = “没什么要改的”，不落盘**（幂等请求就靠这条少写一次盘）；
  - 解析失败（非法 JSON 或形状不对）会把原文件改名成 `<名>.bad-<时间戳>` 留证再当空 —— **绝不能直接返回兜底值**：下一次写入就把现场盖掉，整份数据永久丢失。
- **流式响应一律用 `services/fileStream.ts` 的 `pipeFile`（v6.8）**：`createReadStream(...).pipe(res)` 不转发源流的 `'error'` —— 文件在 `stat` 之后被删（一边放歌一边删歌 / 重建索引）就是未捕获异常，**整个进程退出**；客户端 abort 时也不会销毁源流（fd 泄漏）。`pipeFile` 同时管住“源流出错 → 回 500 或掐断”与“响应结束/出错 → 销毁源流”。注：没用 `pipeline()` —— 它在出错时会连响应一起销毁，“文件打不开”就永远回不出那个 500。
- **只有图标的键才用提示（v5.71/v5.75），且 `label` 同时就是提示内容与 `aria-label`**（图标键没有可见文字，名字不能丢）；有文字的控件**不要**加（截断时看全文仍用原生 `title`）；**自己带“悬浮就出面板”行为的键也不要加**（音量键，v6.6）：提示会与面板同时出现、而面板底边离键往往只有几像素 —— 提示正好压在上面挡住滑杆（实拍就是挡住音量条下段）；推而广之，**同一个键不要两套悬浮反馈**（悬浮光/面板/提示只留一套）。三条硬要求：① **每个触发器要离自己的 `PopperRoot` 最近**：`PopperAnchor` 把锚点登记给**最近的**那个 Root（`injectPopperRootContext()`），而 `TooltipRoot` 自己就渲染一个 `PopperRoot` —— 所以把 `AppTooltip` 套在 `PopoverTrigger` **外面**时，Popover 的锚点被登记进了 Tooltip 的 Root，`PopoverContent` 便没有参考元素、浮层被摆到屏幕外（实测 `translate(0, -200%)`，而 `data-state` 仍是 `open`）。判据：对照量两份浮层的位置（那一版里提示是对的、只有浮层错），别拿“两层锚点抢一个元素”当解释 —— 一个元素上叠两层 `as-child` 是允许的（AGENTS 坑 25）；② 触发键本体也**由壳层组件自己渲染**（`.ctl` + 图标），调用方只传 `label` —— 别把按钮做成插槽：那样“按钮”与“包住它的提示/触发器”就分在两个文件里，`as-child` 链要求触发器的孩子就是一个**元素**，两边版本一旦不一致（改了一半、HMR 半新半旧）就会去合并一个组件，表现是**点了完全没反应**（v5.73 实测）；**中间夹组件同样中招（v6.6）**：`<HoverCardTrigger as-child><AppTooltip><button/></AppTooltip></HoverCardTrigger>` 会让悬浮面板**永远打不开**（提示照旧，所以很容易以为键是好的）—— 任何 `as-child` 触发器（Popover / Dialog / Tooltip / HoverCard / DropdownMenu）都适用这条；③ 内容样式写在**非 scoped** 块（Teleport，坑 6）；④ 动画挂 `[data-state]`、别写基础类（坑 24：音量面板就是这么赖在 DOM 里的）；⑤ **组合触发键（队列 / 歌词来源）的写法**（v5.75）：`<button class="ctl" :aria-label="label"><AppTooltip :label="label"><IconX class="icon" /></AppTooltip></button>` —— 提示挂在按钮**里面的图标**上：Popover 的触发器仍在自己的 Root 下、提示又有个真元素当锚点（代价：`aria-describedby` 落在图标上，名字仍由按钮的 `aria-label` 给）。判据：**验证“浮层开了没有”要量它的盒子在不在视口内**，别只读 `data-state`。
  ⑥ **图标永远不画焦点环**（v5.76）：指针点一下会把 DOM 焦点落在图标自己身上，浏览器会给它画默认焦点环（深色下是一个黑框）。焦点环属于控件，图标只是图形 —— `global.css` 里 `.icon` 统一 `outline: none`，别再给图标写 `outline: auto` / `-webkit-focus-ring` 之类。
- **滑杆只有一份实现**（v5.69）：`components/Slider.vue`（自绘 pointer + 键盘 + `role="slider"`，`orientation` 给竖/横，尺寸由 `--sld-thickness` / `--sld-length` / `--sld-track` 给，`centered` 控制是从底往上还是从中线向两侧；几何与步进在 `utils/slider.ts`，有单测）。音量条、均衡器十根竖杆（竖）与整体增益（横）共用它。两条理由：① 原生 range 旋转后拖动不跟手（AGENTS 坑 7）；② 原生填充从 min 端起算 —— 双极控件会被读成 0~100% 的进度条，而且它没有「从中线往两侧长」这回事（坑 23）。**不要**再照原型那样用 `rotate(-90deg)` 的原生 range，也不要用未旋转的原生 range 做 ± 控件。
- 类名用简化 BEM（`block__element--modifier`）；共用外壳类（`.glass`、`.card`、`.dropzone`、`.app`、`.playerbar`、`.btn`、`.tab`…）放 `global.css`，组件私有样式放 `<style scoped>`。
- **状态类要压得住 `:hover`**（v5.63 实测踩坑）：`.pl-row:hover` 与 `.pl-row.is-dragging` **特异性相同**，靠源码顺序决定胜负 —— 拖拽行自己也满足 `:hover`（指针就在它上面），于是悬浮底色盖掉了拖拽态要求的**不透明底**，被盖住的那一行从下面浮上来，看着就是两行字叠在一起。规则：任何“当前状态”的样式要么写得更具体（`.pl-list .pl-row.is-dragging`），要么把它要排除的伪类写清楚（`.pl-row:hover:not(.is-dragging)`）；不要指望“后写的会赢”。
- **给 Reka 浮层做 `force-mount` 时，要连它的包装层一起关掉命中区**（v5.62 实测踩坑）：我们只给自己的面板写了 `visibility: hidden` + `pointer-events: none`，但 Reka 还会在外面套一层自己的元素（`[data-reka-popper-content-wrapper]`，只存在于 Popover / Tooltip 这类带定位的浮层），它是 `pointer-events: auto`、且盒子就是面板大小（`visibility: hidden` 的子树照样占位）—— 于是收起状态下仍有一块隐形矩形**吞掉那块区域的点击**（实测：音乐库列表下部的「播放」按钮点不动，Playwright 报它 `intercepts pointer events`）。因为我们拿不到那层的类名，只能从里面反着关：`[data-reka-popper-content-wrapper]:has(> .q-pop[data-state="closed"]) { pointer-events: none }`。判据：**“浮层收起了”不能只看它的 transform / opacity，要拿 `document.elementFromPoint()` 量一下那块地方到底能点到谁**。（反过来也要记一句：**不需要退场动画的浮层就别 `force-mount`** —— 菜单这类关上就卸载的，包装层跟着一起消失，根本不会留命中区；v5.64 的导出菜单为此刻意不加。）
- **文本可读性优先于原型数值**：深色下正文/说明文字不得低于 `--text-2`；原型里的 `--text-3` 已因实机偏暗上调（v4.16）。
- **取色禁写内联 background**：JS 只写 `--cover-src` / `--cover-src-2`；一切调校在 CSS 用 OKLCH 相对颜色语法派生（每条派生先写降级声明）。
- 新样式同步考虑：深浅双主题、`prefers-reduced-motion`、移动端不崩（RT-08）。

## 5.1 文案（界面上的字）

- **面向使用者，不面向开发者**：不写接口名（`GET /api/xxx`）、不写需求编号（`LB-04`）、不写"下一步接入"这类工程内部语言；编号只留在注释、提交信息与文档里。
- **未接入的功能不假装可用**：不渲染点了没反应的假控件（禁用态的搜索框/按钮一律先不渲染）；必须告知状态时，用一整块空态把"现在是什么 / 以后会怎样"说清楚。
- 空态文案结构：一句短标题（现在没有）+ 一句说明（会自动出现什么 or 怎么开始）。
- **文案自检四条**（v4.76 定稿，写完逐条对照，改不动就删掉整句）：① 有没有**需求编号**（`VS-08`、`AC-01/03`）或**里程碑名**（“M2”）；② 有没有**实现细节**（“CSS 变量”“接口”“state”）；③ 有没有**承诺尚未实现的能力**（实例：说明里写着“盘面颜色跟着封面走”，而取色管线还没接——需求方一句“这个还没做吧”就抓住了）；④ 有没有**与控件重复的说明**（缩略图/标签已经把选项讲清了，不要再逐条列一遍）。控件与说明各管一件事：控件说“能选什么”，说明只说“选了会怎样”。

## 6. 组件

- **长文本溢出的滚动（marquee）**：只在**明显溢出**时才滚（阈值 `MARQUEE_MIN_OVERFLOW_PX` = 24px）——只溢出一两个字就滚，会长时间停在断层上、看着像渲染坏了（v4.25 用户报过），这种情况用省略号 + `title` 悬浮提示；用**离屏探针**量文字宽度（`measureTextWidth()`，比 canvas 可靠），不要为了测量在模板里常驻隐藏元素（v4.22 踩过：多一个隐藏 span 就让 vue-tsc 生成坏代码）；滚动时渲染**两份相同文本 + `translateX(-50%)`** 实现无缝单向循环，间隔用副本自己的 `padding-right`（**不要用 flex `gap`**，否则 -50% 少走半个间隔、接缝处会跳），并给容器加两端 `mask-image` 渐隐；不滚时退回**单行 + 省略号**；时长用 `utils/marquee.ts` 按恒定速度换算并夹区间，靠全局 `prefers-reduced-motion` 降级。统一实现见 `components/ScrollingText.vue`。
- **把“是否需要滚动”变成可预期的**：承载长文本的容器必须是**固定宽度**（如播放条左侧 `--pb-left-width`，封面与信息块都固定），不要用随窗口漂移的弹性列——同一首歌一会儿溢出一会儿不溢出，滚动行为看着就像随机故障（v4.25 用户定稿）。
- **播放状态以 `<audio>` 元素为准**：`playing` 这类状态由 `play`/`pause` 事件驱动，不要只用命令式赋值（会出现“进度在走但图标仍是播放”的脱节，v4.21 踩过）。
- **静音只有一种样子，且不能清灰**：语义上 **音量为 0 就是静音**——`setVolume(0)` 同时置 `muted`，UI 侧统一用 `player.muted || player.volume === 0` 推导“静音”，四处必须一致：斜杠图标、滑杆按 0 显示（旋钮落底 + `--p: 0%`）、读数走百分比（静音时就是“0%”，不另写“已静音”）、**样式保持正常颜色**（降透明度/去饱和会被当成“禁用、点不了”，v4.23 用户反馈）；静音后再点静音键是**恢复音量**（`lastAudibleVolume`），不是再翻一次 `muted`。
- **进度条只在真正进行时出现**：不要给“等待中/已完成/失败”的行都摊上一条空进度条——一整排长灰线既无信息也无美感（v4.26 用户反馈）；进度与状态共用一列，空闲时只显示文字，行内也不因出现进度条而抽动。
- **“添加文件”不占一行**（v4.37 定稿）：列表 / 队列已有内容时，添加动作并进**页头操作组**（`.page-head__actions`，如 `[选择文件] [清空列表]`），不要再渲染“紧凑投放条”——那只是把同一个按钮换成换一种流式占用：一行。投放卡只留给空态（它承载格式 / 上限 / 重名 / 隐私这类**一次性说明**）；拖入反馈改用 `.drag-veil` 浮层（`position: absolute; inset: 0`，**必须 `pointer-events: none`**，不然会吞掉拖拽事件）：不挤动列表、拖拽结束即消失。拖拽监听挂 `window` 并先判 `event.dataTransfer.types.includes("Files")`，否则以后的页内拖拽（如排序）会被误接管。
- **表头与行共用一套栅格**（v4.38 定稿）：列宽写在全局 `--row-grid`（含 ≤1024px 的同断点覆盖），`TrackRow` 与 `TrackListHead` 都读它——各写一份 `grid-template-columns` 一定会漂。**最后一列用固定宽，不要用 `auto`**：`auto` 会随“本行有几个操作键”变化，有操作键的行把 `fr` 列挤窄、表头（空单元格）另行计算，实测列左边界差 27~46px。**表头住在滚动区外面**（v4.41 定稿，取代 v4.38 的“吸顶 + 不透明底”）：表头是“说明”，放进固定帧的普通子元素（`.page-frame` 直子）即可——标签常驻、列表在它下面滚，而且**不需要底色**（没有重叠就不需遮挡）。吸顶路线已废弃：吸顶必须有不透明底，而岛是玻璃材质，任何不透明色都会在岛面上露成一条**色带**（用户实拍：“是不是有个背景色”“不然看着很突兵”）。
  宽度对齐**不用再补**了（v6.18）：滚动条浮在内容上、不占位，滚动区与固定层天然同宽（旧写法“给固定层补一条 `margin-right: var(--scrollbar-size)`”已删）。实测表头与行的内容宽度相等（1122 / 1122）。表头只放“说明”，排序 / 筛选入口统一放工具栏。表头**不给封面列留空位**：封面不是可读的信息列，“曲目”应当直接用 `grid-column: 1 / 3` 跨过封面列、与封面左边缘对齐（顶着一个空格子看着像漏了内容）。
- **歌单曲目用“整表替换”，别加一堆 add/remove 接口（v5.58）**：歌单是**有序列表**，添加、移除、拖动排序本质都是“新的一份顺序”——客户端把结果整份发回（`PUT /api/playlists/:id/items`）、服务端拿同一套纯函数再去重一次（`dedupePlaylistItems`，前后端共用）。好处：排序将来不用再加接口，也不用担心“服务端顺序与客户端不一致”。**引用口径要记牢**：云端存 `Song.id`、在线存 `provider:id`（铁律 4）、本地存“歌手|曲名”稳定键（本地 id 每次重新导入都会变，与歌词库同一口径）——身份键统一走 `playlistItemKey`，别在页面里另写一份比较。
- **“一个东西能不能用”的判断收进纯函数（v5.58）**：歌单里的一条可能“云端被删 / 本地不在当前列表 / 在线音源没接”——三种情况要显示三种说法，但都同样点不动。这类判断写在 `utils/playlistEntries` 一处（返回 `state` + `track` + `reason`），页面只管把 `reason` 显示在歌手那一行；不要把“能不能播”写成模板里的一串三元。
- **破坏性动作要红 + 二次确认**（v4.46 修订，**取代** v4.38 的"就地改写按钮区"）：批量或不可逆动作（清空列表、批量删除、单曲删除）用 `btn-danger`，确认统一走 `utils/confirm.ts` 的 `confirmAction({ title, description, confirmText?, tone? })`（文案带**数量 / 名字**，别让用户猜删的是哪首）。**不要**各页面自己弹窗，也不要再写 `.confirm-hint` 那套就地确认：确认必须有唯一入口，否则将来换应用内弹窗要一处处改、还会出现两套确认语言。
  **v5.53 落地**：界面已经是应用内对话框（`components/ConfirmDialog.vue`，Reka Dialog 行为层 + 自绘玻璃，挂在 `App.vue` 全站一份）——调用方只写 `if (!(await confirmAction({...}))) return;`，**别写成 `if (!confirmAction(...))`**（Promise 永远为真 → 点取消也照做，v5.53 就抓到一处）。写文案时“标题 = 一句短问句，`description` = 会发生什么 / 能不能撤销”（如“会和服务器上的文件一起删掉，且无法撤销”）；破坏性动作不传 `confirmText`，普通批量动作（如上传）传 `tone: "primary"` 与自己的确认键文案。对话框里**默认焦点给取消键**（回车 = 取消）：破坏性动作里“回车 = 确定”太容易误删，别改。
  **层级：同一按键只由最上面那层响应**（v5.40 踩过，v5.53 抽成 `utils/topLayer.ts`）：沉浸页整页、队列抽屉、确认对话框都在 `window` 上听 Esc，同一阶段里监听器按**注册顺序**跑（= 组件挂载顺序，不可控）。做法：每层打开时 `pushTopLayer()` 领层号、关闭时交回，处理按键前先 `isTopLayer(id)`——不是最上层就**放行**，是最上层才 `stopPropagation()` + 干自己的事。任何新的“全屏层 / 弹层”都要登记，否则又会出现“按一下关掉两层”。
- **主操作按钮不铺不透明主题色块**（v4.52 定稿）：播放/上传这类主操作用**半透明软件色底**表达——`--accent-soft` 底 + `--accent` 图标 + 一圈极淡描边 + 一层主题色光晕（与 `EmptyState` 的圆徽同一套语言，光晕参数按控件尺寸缩，不要照搬）。悬浮只 `brightness(1.12)`，不要叠更重的底色（软底本身就是主题色，会发闷）。光晕要**克制**：本项目最终用的是 `0 3px 14px -7px accent 45%`（半径小、不透明度低），它只是“坐得稳一点”的一层，不要做成发光按钮。
  **光晕要按尺寸缩，别照搬（v6.0）**：42/48px 的播放键用 `0 3px 14px -7px accent 45%`，30~34px 的扁按钮（`.btn-primary`、音效药丸）共用 `--soft-btn-glow`（半径减半、负 spread 收一半）；悬浮那一档用 `--glow-halo` 铺 2 层就够（矩形带描边，轮廓像素比 14% 不透明度的圆盘多，照搬四层会糊边）。**轨道里的选中底板不加光晕**：分段控件的 `.seg` 没有 `overflow: hidden`，光会溢到轨道外。
  **状态键＝图标的“形”与“色”，不要给它加包围它的东西（v6.5 定形）**：收藏这类“开着”的键只由 `.ctl.is-on` 一条规则给颜色（三处共用：播放条 / 沉浸页歌名旁 / 列表行），**不铺底、不加描边圈、不给常驻光**。需求方六条反馈（v6.1 软底 + 光晕 → v6.3 islands 专属软底圆 → v6.4 整颗心半透明 → v6.5“不要吧这个收藏图案套进这个透明圆形里面”→“心的中间要填充透明主题色”→“边框变成半透明的吧”）合起来的判据就是这一句。**两层故意不同档**（描边 65% / 心内 20%，试过“两层同档 65%”，需求方：“之前那个透明度刚好”）：心内比边框淡，形状读得出来、又不像半选。**两态的差别落在图标自己**：同一个轮廓的两款 —— `ph/heart-straight`（未收藏，`--text-2` 细描边、里面全空）↔ `ph/heart-straight-duotone`（已收藏，**描边 65% 半透明 + 心内一条更淡的填充**，即图标集那层 20% 副路径；`color` 是两层唯一的颜色源，跟着封面变）。⚠️ 选渲染路径靠“哪条带 `opacity` 属性”（`.icon path:not([opacity])` 选描边）—— 换图标集要重核。以后要加“点亮”样式，先自问“我是不是又给这个键套了个框”。**不可用/空闲态要把状态色收掉**：一个有色却点不动的按钮最像“坏了”（用户之前就根过“一排灰按钮 + 一个点不动的亮色主按钮”）。
  **软底那一档收在令牌里（v6.5）**：`--accent-soft`（14% 底）、`--accent-line`（30% 淡边）、`--soft-btn-glow`（那层光晕）—— 主按钮 / 分段底板 / 音效药丸共用；**别在组件里再写一遍 `color-mix(in srgb, var(--accent) 30%, transparent)`**（原先四处各写一遍，改一处忘一处就会出来两种轮廓浓度）。。
  **v5.99 补齐范围**：只说“主操作按钮”不够 —— 当时漏了 `.btn-primary` 那一族（播放全部 / 上传 / 登录 / 保存 / 重试），后来又漏了**选中态底板**（分段控件 `.seg__pill`、音效药丸 `.fx__pill.is-on`）。凡**可点控件**（按钮、选项底板、开关）都用软底 + 色相文字 + 一圈淡边；**实心主题色只留给状态标记**（复选框打勾、进度/滑杆填充、选中指示条、品牌标记）。排查时的一个抓手：`.btn-danger` 早就是软底，`.btn-primary` 曾是全局唯一一档实心按钮。
- **ResizeObserver 回调里不要改布局**（v4.53）：回调里插入/移除元素、改宽高都会让本帧的 RO 通知“送不出去”，控制台刷 `ResizeObserver loop completed with undelivered notifications`。需要量尺寸就**合并到下一帧**再量（`rAF` + 合并，卸载时 `cancelAnimationFrame`）——`ScrollingText` 的离屏探针就是踩过这个坑的实例。
- **全局 reset 的边界**（v4.51）：`global.css` 只做**最小 reset**——`* { box-sizing: border-box; margin: 0; padding: 0 }` + `button/input/select` 继承字体与颜色 + `a { color: inherit; text-decoration: none }`；其余 UA 默认（`select` 外观、`h1` 字号、`line-height`）**有意保留**，由组件自己定。改样式前先看一眼这里：比如给某元素加 padding 时不要假定 `box-sizing: content-box`（全站都是 border-box）；正文里真要有下划线的链接，给那个链接单独加类，别把 `a` 规则改回去。
- **服务端数据落盘**（v4.49）：索引写 JSON 一律**先写 `.tmp` 再 `rename`**（原子替换，半路被杀不会留半个 JSON）；每次请求现读现写，**不上内存缓存**（文件小，缓存失效的坑更贵）；**删除先写索引再删文件**——最坏留个孤儿文件（`reindex` 能捞回），反过来会留下指向已删文件的鬼影。
- **不要用 `express.static` 托管 `uploads/`**（v4.49）：否则 `/covers/x.mp3` 就能直接拿到音频，绕过 AC-03 的访客级门禁。媒体统一走 `/audio`、`/covers`，先过文件名形状白名单（挡 `../`）再查扩展名。
- **multipart 里的中文文件名要转码**（v4.49）：busboy/multer 按 latin1 读 `filename`，`BEYOND-海阔天空` 会变 `æµ·éå¤©ç©º`。统一过 `services/metadata.ts` 的 `decodeUploadFileName()`（取回字节再按 UTF-8 解），别在每个路由里各写一遍。
- **解析失败要回退，不要编造**（v4.49）：元数据解析失败 -> 退到**文件名解析**（与客户端共用 shared 的 `parseTrackFileName`）；索引重建时原文件名已无从得知，就只能退到落盘名——这是诚实的降级，不要凭空造句。
- **错误呈现三原则**（v4.27 定稿，上传队列为范例）：① **结果紧贴对象**——成功/失败的结果行就叠在文件名下面，不要让用户横跨整行去找原因；② **区分可重试**——文件不合规（400/413/415）不给重试按钮（重试永远不会成功），网络/5xx/429 才给，并提供「全部重试」；③ **给汇总**——顶部一句话说清“完成 x · 重复 y · 失败 z”（有失败标警示色）并挂 `aria-live`，别让用户逐行数。
- **表头与行的几何全部走共享令牌**（v4.38/v4.41/v4.44）：列宽 `--row-grid`、列间距 `--row-gap`、行内边距 `--row-pad-x`，`TrackRow` 与 `TrackListHead` 都读同一份（各写一份就会漂）；列表容器统一用 `TrackList`（它的根元素带 `.row-list`：`flex` 列 + `gap: var(--row-list-gap)`，行间**只靠间距分隔、不画线**，见下面那条）。高亮/在播曲目**按 id 判定**（`activeId`），不要用索引——列表被搜索/排序后索引会错位。表头的宽度对齐由 `.page-frame > *` 的统一补偿给（见“固定帧”那条），别再单独写一份。
- **列表行节奏：先分清两个旋钮**（v4.48）：① **行盒子高**＝封面 + 上下内边距（`min-height` 64px / `padding` 10px）——它决定悬浮/选中底色块的大小；② **行与行的间距**＝`.row-list` 的 `gap`（`--row-list-gap`，13px；它同时承担“行距”与“行间分隔”两件事）。这档调过 2 → 10 → 6 → **13**（v4.90 去掉 1px 分隔线后把 gap 从 6 补到 13，行距一格没变）。用户说“拥挤”时，指的很可能是 ②，而我只动了 ①，把行拱到 76px 反而“行高太大”——两个旋钮一定要分清。行内呼吸（两行文字 5px、列间距 `--row-gap` 20px）另算，不要再硬改 `padding`。封面 44px 正好填满封面列。
- **列表行节奏统一**：带两行文字的行（歌名+歌手、文件名+结果、标题+副标题）行高**不少于 76px**、上下内边距 12px、封面 44px，两行文字之间留 5px（v4.42/v4.43 从 62px/8px/3px 两次上调——用户连提两次“拥挤”：**行高与行内呼吸是两件事**，只加行高、不放开行内的行间距与列间距，看着依旧挤）；**任何行列表都用这一套行节奏**——队列弹层的行距就是 `.q-list` 的 flex `gap: 6px`（v4.73，用户报“这个挨的有点紧了”：两行底色贴在一起），**别改成给行加 `margin`**（首尾会多出半格、滚动位置也不好算）；列间距（曲目列表 20px）写在共享令牌 `--row-gap` 里，表头与行必须同值，否则列对不上；单行表格行可以矮些；行与行**用间距或底色分隔，不要又贴紧又画 1px 细线**（贴紧 + 细线会显挤，v4.28 用户反馈）；有底色的行必须给悬浮反馈，否则看着像点不动。
- **简约优先的检查顺序**（v4.30 定调）：先问“这块信息能不能靠**层级 / 间距**解决” → 再考虑**一条分隔线** → 最后才是底色 / 描边 / 图标；同一页面只保留一套分隔语言；颜色只用于表达状态，不做装饰；每加一个元素都要能回答“它承载什么信息”，答不出就删掉。
- **同一类控件只留一份视觉配方（v4.95）**：进度条与音量条是同一件东西（轨道 + 填充 + 手柄），配方写在 `global.css` 的一条共用规则里（`.progress .knob, .vol-pop__thumb`），两个宿主**各自只写定位**。分开写的后果实测过两次：v4.93/v4.94 刚把进度条那枚修好（去黑圈、加播放光晕），音量条那边仍是 6px 轨道 + 13px 无光圆点（需求方：“音量条样式也优化一下吧”）。同一个组件的两份实现也是同理（音量控件本身在 v4.62 就因为两处各写一套而走偏过）。
- **“呼吸光 / 光晕”用合成层动画：只动 `transform` 与 `opacity`（v4.94）**：进度手柄的播放光晕是一个 `::after` + `radial-gradient(var(--accent-soft), transparent)`，动画只改 `transform: scale()` 与 `opacity`；**不要动 `box-shadow`**（每帧重绘）或 `filter: blur()`（每帧重算）——这是“呼吸光”最常见的性能坑。另外两条：只让**播放中**呼吸（v4.30：动效只表达状态），并在 `prefers-reduced-motion` 下降级为**静态**光晕（状态仍可见）。
- **离场动画期间不要清内容，否则看到的是“布局塌下去”（v5.55）**：弹层内容常由“当前请求 / 当前选中”这类数据驱动，而用户一作答、那份数据就没了 —— 模板直接绑它的话，标题/正文当场变空，卡片高度从 169 塌到 79，看上去就是“**窗口先收缩再消失**”（需求方实拍；它和 `transform` 无关，不要把两件事混着当同一个 bug）。做法：组件里留一份“**正在展示的那份**”副本（`watch(source, next => { if (next) shown = next })`，只进不出，下一段数据来了再整块替换），并把“层登记 / 聚焦”这类副作用挂在 `open`、请求 `id` 上，而不是那份数据本体。收完后它只是 `visibility: hidden`，不在无障碍树里。
- **页面级装饰图层（背景光晕）三条（v5.52，实例见 `ImmersiveView.vue` 的 `.im-glow`）**：① **通配子选择器会把它的定位压掉** —— `.im > * { position: relative }`（"给每个子元素建绘制层"）与 `.im-glow` 的规则**特异性相同、源码顺序在后**，实测把它的 `position: absolute` 压成 `relative`，空 div 高度塌成 0、什么都不画（表面症状就是"光晕没了"；我一度误判成父级是 flex 列容器，白查半天）。写法：**通配规则给装饰层留例外**（`.im > :not(.im-glow)`），别指望源码顺序或 `!important`。② **图层要比可见区域大一圈**（`inset: -12%`），否则位移会让边缘露出一条**没染上色的硬边**（渐变在四角通常最浓，看得出来）；代价是层内百分比要按放大倍数折算（视口上的 `120% 90% at 16% 0%` → 层内的 `96.8% 72.6% at 22.6% 9.7%`），**折算关系写进注释**，别留一堆魔法数字。③ **幅度与周期要实测定，"看得出在动"就是验收标准**：判据可以很土——把动画两端各截一张摆一起看，看不出区别就是不够（实测 ±2.5%/scale 1.08 两端只差 3.4/255，两张图几乎一模一样 = 还是"死板"；改到 ±7% / scale 1↔1.3 / opacity .65↔1 / 16s 才成立）。动画本身仍守上一条：只动 `transform` / `opacity`，`prefers-reduced-motion` 下降级为静态（这里正好等于改造前的观感）。
- **带 `backdrop-filter` 的面板：不要用 transform 做进出场（v5.54）**。上面那条只说“只动 `transform` / `opacity` 就是合成层”，但有个例外：元素**自带背景模糊**时，`transform` 会逼着浏览器每帧重算模糊区域、并把面板里的文字重新栅格化 —— 实测（真实 Chromium，关闭动画逐步采样：`scale(.989)+translateY(4.35)` → `scale(.983)+translateY(6.98)`）帧间隔并不长，但观感就是“卡一下”（重活摆在那，不是丢帧）。所以这类面板（对话框、浮层、抽屉）的进出场**优先只做 `opacity`**；需要位移/缩放时问一句“这个位移是不是它自身的语义”（手机底抽屉“从底部升起”是，所以它保留；对话框不是，改成原地淡出）。关闭曲线用 `ease`（开头就慢慢淡），不要用 `--ease-ios`（一上来就掉一半，不像“逐渐为 0”）。
- **不为了一个名字开对话框，也不回头用 `window.prompt`（v5.58）**：需要用户填一个短名字时用**行内输入**（`InlineNameInput.vue`：回车提交、Esc 取消、旁边两枚小键给触屏）——侧栏新建与详情页重命名共用一份。全站的确认/输入都在应用内（v5.53 起）。
- **`visibility` 不能“按时长过渡”，要写 `visibility 0s <时长>`（v5.53 实测踩到）**：`force-mount` 的弹层用 `visibility: hidden` 做关闭态（它比 `opacity: 0` 多一个能力：**真的不可点、也不可聚焦**，v5.50 靠它修好了“关闭态遮罩拦住全页点击”）。但它是**离散属性**，现代引擎按“过渡过半才翻转”处理 —— 写 `transition: opacity .2s, visibility .2s` 时，**打开后的前 100ms 元素仍然是 hidden**：渐变看着正常（`opacity` 在动），但 `focus()` 会**静默失败**（实测：刚打开时调两次 `focus()` 都不产生任何 focusin，100ms 后手动聚焦就成功；症状是“焦点还留在背后的触发按钮上”，后果是回车会把弹层再叫一次）。写法：关闭态 `visibility 0s .2s`（先播完淡出、再隐藏）、打开态 `visibility 0s`（立即可见）；`opacity` / `transform` 两档时长照旧。手机左抽屉与队列抽屉同时修正。
- **对话框（模态）用“大面”那一档材质**（v5.53）：它背后往往是**成片的正文**（队列抽屉的文字、列表页的标题、沉浸页的歌名），小浮层那档 `--panel-bg`（0.52/0.46）会让两层文字叠成一片；取与手机左抽屉同一档的 `--tray-bg` / `--tray-blur`（0.88/0.80）。“真不透”不是目的，“背影不干扰阅读”才是 —— 测试环境（无头 Firefox / Electron）不合成 `backdrop-filter`，截图看到的就是最坏情况，正好拿来当判据。
- **滑杆手柄默认不显示，指针在轨道上 / 键盘聚焦 / 拖动中才出现（v4.96）**：常驻圆点会把注意力从“进度/音量本身”拽到那个点上。可见性**写成一条共用规则**（两个滑杆共用，别在组件里各写一份）：`.progress:hover .knob`、`.progress:focus-within .knob`、`.progress.seeking .knob`（自绘滑杆同理是 `.sld:hover .sld__thumb` / `:focus-within` / `.dragging` 三条，v5.69）。**拖动那一条必须有状态类兜底**——指针捕获不保证 `:hover` 还在，按住手柄拖到轨道外时手柄会凭空消失（实测过）。出现/消失用 0.15s `opacity` 过渡；`prefers-reduced-motion` 下直接切换。
- **同一条轨道上的光效共用同一份配方（v4.97）**：进度条“走过的部分”在播放中散一圈柔光（`.progress.playing .fill { box-shadow: 0 0 8px var(--accent-soft) }`），**与手柄的柔光是同一个值**——手柄是灯芯、走过的部分是灯身，同一画面里两个光值不一致会显脏（顺带：长条形的柔光要比 9px 圆点更宽/更亮才“看起来一样亮”，真嫌淡就**两处一起调**，别给轨道单开一个值）。只做“亮/不亮”的 0.3s 过渡，**不做呼吸**：一幅画面只让一个东西脉动（要呼吸的是手柄那层 `::after`），而 `box-shadow` 逐帧动就是逐帧重绘（见上一条）。
- **通用悬停规则要排除主按钮（v4.98）**：`.ctl` 是全站图标按钮的通用类，播放条与沉浸页的主按钮是 `.ctl.play`。`.ctl:hover:not(:disabled) { color: var(--text-1) }` 这类“顺带把文字色提一档”的规则会**连主按钮一起改**（(0,3,0) 压过 `.ctl.play` 的 (0,2,0)），表现是鼠标一放上去主题色图标就变成近黑/近白（需求方：“鼠标放在播放按钮上时中间图标的颜色不应该变成白色或者黑色”）。写法：通用规则加 `:not(.play)`；主按钮的悬停反馈**只有光**（`filter: drop-shadow(...)`），不换色、也不叠 `brightness()`（乘性提亮同样属于“颜色变了”）。
  **v5.70 补充（状态键同理）**：`.is-on`（收藏中等）也要排除 —— 实测收藏着的心，指针一放上去就从主题色变成 `rgba(18,24,38,.94)`（`--text-1`），看起来像“一悬停就变成没收藏”。悬停因此拆成两半：**光**（`drop-shadow`）给**所有**图标键（含状态键 —— 悬停总得有反馈）、**提色**只给**没有状态**的键（`:not(.is-on)`）。另：状态色（主题色）只由 `.ctl.is-on` 一条规则给，播放条 / 沉浸页控制栏 / 列表行**三处共用**；各组件不要再写一份 `xxx.is-on { color: var(--accent) }`（沉浸页那枚就是因为没写而“收藏了只换图标、不变色”，同一个键两处两种表现）。
- **`drop-shadow` 的浓度跟着内容的 alpha 走（v4.98）**：给**半透明软底**的元素加光时，一层大 blur 几乎看不见——shadow 的有效 alpha ≈ 内容 alpha × 光色 alpha，散开就被摊平（`.ctl.play` 的圆盘只有 14% 不透明度，实测单层 10px 在浅色主题峰值差只剩 4/255）。做法是**两层同一令牌**：4px 贴着轮廓（把浓度压在边上）+ 14px 向外散（实测峰值差 60/255、5100+ 像素可见）。反过来，不透明的图标（旁边那几枚 6px 光）本来就看得见，别把两处的参数混着抄。
- **“透不透”是面板色与背后底色的对比问题，不是 alpha 问题（v5.2）**：平坦底色上把 alpha 从 0.74 降到 0.55 只差 4/255（面板色与背景几乎同色，透不透一个样）；只有背后真有色块/文字（封面渐变、列表、封面图）时 alpha 才看得出来（沉浸页平均差 22/255）。所以**“浮在上面”这件事交给描边 + 投影 + 一圈主题色光晕**，不要靠把填充堆得更实（v4.60 的老结论“面板不能和底下的玻璃同一个填充值”仍然成立，只是解法换了）。另外：`--panel-*` 是所有浮层面板（音量、队列）**共用的一份材质**，改一处三处一起变。**主题色光晕的浓度要按“最亮的那一档封面”定（v5.3）**：`--accent` 的亮度跟着封面变，同一个浓度在黄/亮色封面上看着比深色封面浓很多（需求方实拍黄色封面：“光效再低一点”）——所以浮层面板的光晕只留 25%/30% 这种“暖边”量级，真正需要“亮”的地方（播放按钮悬停）才堆层数。
- **悬浮反馈“进慢出快”（v5.0）**：`transition` 取的是**目标状态**那份声明，所以“亮起”与“熄灭”可以给不同时长——静止态写熄灭那一程（`filter 0.12s ease`，移开立即收、不黏手）、`:hover` 里写亮起那一程（`filter 0.22s ease-out`，快起慢收）。注意：`:hover` 里重写 `transition` 是**整条替换**，其它还要过渡的属性（如 `color`）得一起写上，否则一进 hover 那个属性就失去过渡、直接跳变。
- **“光更明显”靠加层与收紧，不要指望 HDR / 超白（v4.99）**：先把事实记清楚 —— ① 浏览器只对**视频与图片**做真 HDR 输出（PQ/HLG），CSS 颜色一律映射回 SDR，“只让某个元素进 HDR”是做不到的；② `(color-gamut: p3)` / `(dynamic-range: high)` 要按设备判断，`color(rec2100-pq …)` 目前在 Chrome 不支持（实测本机三个都是 false）；③ `oklch(1.2 …)` 这种“超白”语法**会被接受但会被裁到屏幕白点**，在 SDR 屏上等价于**加白**。所以在 SDR 上做“灯丝感”的办法是**同一颜色多铺几层**（`.ctl.play` 的悬停光是 2px 灯芯 + 9/20/32px 三层 `--glow-halo`：亮核 / 过渡 / 散开），而不是去找一个“更亮的颜色”。**“再亮点”的标准配方是“灯芯加密 + 最外再铺一层”（v5.1）**：只把半径推大反而会因为摊薄而**变暗**（实测峰值 88 → 74）；灯芯（同一颜色、浓度 55% → 90%）管“亮”、最外那层管“大”，两个旋钮各管一头。另：量悬停光效时**先确认过渡已停稳**（相隔 220ms 的两张截图完全一致）再取数，否则量到的是 0.22s 动画的中间态（v5.1 实测过一次，深色峰值差被读成 66 而不是 77）。配套经验：**加白的亮芯只在深色主题成立** —— 浅色主题里的“光”是暗色的主题色，白芯落在浅色圆盘上看不见（实测浅色峰值反而从 60 掉到 46），所以要么两主题都用彩色层，要么就明确“灯丝只在深色主题”。
- **验证颜色 / 过渡时先看页面可不可见（v4.97、v5.8 各误判过一次）**：页面 `hidden`（面板被挡住、窗口切走）时 **CSS transition 不推进**，`getComputedStyle` 读到的是过渡的**起点**。最典型的一次：切换主题后 `.set-card > b` 的颜色“恰好落后一个主题”—— 其实 `body { transition: color 0.3s }` 冻在原值上，看着很像 bug。要读真实值就先确认 `document.visibilityState === "visible"`，或者用 `document.getAnimations()` 看过渡本身在不在。
- **两种状态用不同字号时，把 `line-height` 写死（v5.12）**：字号一变，默认行高（`normal`）跟着变，盒子高度就变 —— 侧栏折叠态把 logo 字号 17 → 20px，logo 盒子 44 → 48，**下面所有图标在点击那一帧瞬跳 4px**（实测 `[38, 86.4]` → `[38.5, 90.4]`），肉眼看就是“图标在跳”。需要不同字号又要布局不动，就给容器一个确定的盒（写死 `line-height` 或固定 `height` + `align-items: center`）。
- **同一类列表项用同一个“项间距”（v5.11）**：贴在一起时，悬浮/选中的圆角底色会上下连成一块（侧栏折叠态最明显，需求方：“又挤在一起了”）；而同一份 UI 里两种节奏并存（主体 0、页脚 2px）只会让人当成 bug。侧栏取 4px（对齐 shadcn 的 `SidebarMenu` 的 `gap-1`），并**写成一条共用规则**给导航与页脚。
- **宽度动画期间内容会跟着回流：让内层宽度跟着一起动画，而不是“点一下换布局”（v5.10 → v5.13 修正）**：侧栏折叠是网格列 224 → 68。第一版把内层宽度**瞬时**切成 68（想避免文字回流），结果选中高亮（项自己的底色）在点击那一帧从 200px 瞬变 44px —— “高亮的背景会前后动”。正确解法：**让内层宽度与内边距跟列宽用同一时长/缓动一起动画**（文字仍然不会回流，因为标签 `nowrap` + 外层 `overflow: hidden` 会把多出来的部分裁掉）；并且折叠态**只改宽度**，任何 `justify-content` / `padding` / 外边距的切换都会让元素在点击那一帧横跳（实测：分组标题一藏，右上角加号被 `space-between` 推到最左，一跳 161px —— 最后按 shadcn 的做法在 icon 态直接 `display: none`）。
- **别用“过渡期间覆盖 animation、结束后撤掉”来压动画（v5.21）**：写 `html[data-vt="on"] .im { animation: none }`，过渡结束时把 `data-vt` 一撤 —— 被取消的动画会**从第一帧重新开播**（需求方看到的就是“动画结束后闪一下”）。压动画要用**持久标记**：把“要不要动画”在页面创建时定下来（`ImmersiveView` 在 setup 里读一次 `data-vt`，是就给自己挂 `no-enter`），而不是跟着某个变量的生死开关。同一条也适用于任何“临时给元素加个类或属性去改动画”的写法。
- **看得见的入口必须真的能进（v5.20）**：侧栏在未登录时也显示「设置」，但 `/settings` 当时没有 `meta.anonymous` —— 点进去就被守卫送到登录页要密码（需求方：“为什么点击设置需要密码？”）。规矩：**渲染出来的入口**（导航、按钮、卡片里的链接）与**路由可达性**必须一致：要么按角色把它藏掉，要么让目标页面在未登录下也能进（并把服务端相关的分组/块按角色裁掉）。代价是“本地偏好”类页面（主题/布局/快捷键）不该被门禁挡住 —— 未登录模式（AC-01）同样需要它们。另：身份变化会把分组抽走，**当前选中项若不存在要退回默认项**，否则面板会停在一个不存在的值上（白屏）。
- **Vue `<Transition>` 的两个坑（v5.27）**：① **过渡名要在“导航发生的那一刻”算出来** —— 只看当前 route 会把离场那一侧算错：`/now` → 主壳时 `route` 已经是主壳了，名字变成空字符串（实测表现：升上去有动画，沉下去没有）。做法是 `watch(layer, (now, was) => pair = now === "/now" || was === "/now")`，并在 `@after-enter/@after-leave` 里清掉（否则“上一次”会泄漏给下一次换层）。② **想让某一侧“原地留住”就只声明时长、不改属性**：Vue 根据元素上算出来的 `transition-duration` 决定何时拆除离场元素，所以 `.app.im-sheet-leave-active { transition: transform 0.42s }` 能把它按住 0.42s 而不产生任何视觉变化 —— 不写这条，离场的主壳会在一开场就被移除（sheet 就会升到一片空白上）。另外：过渡类写在**目标组件的 scoped 样式**里，就天然只命中它自己（主壳拿不到那枚 scope id），不用再给两侧分别起名字。③ **想要“sheet 只在该动的时候圆角”就把圆角一起放进 transition**（v5.28）：只在 `-enter-from/-leave-to` 里写圆角、不插值，落地那一帧会把圆角“啪”地弹平；把 `border-radius` 也写进 `transition` 就能在升起的过程里从 18px 平滑收到 0（实测 5.7 → 0.24px），退回时反向。④ **要从“留下”变成“压暗”只需 filter**：`-leave-to/-enter-from { filter: brightness(0.68) }`（时长写进 `-active` 即可），不必新加一层遮罩元素；两级状态（矩形/圆角、亮/暗）都能这么表达。⑤ **内页互切只做进场**（v5.28）：`<RouterView v-slot="{ Component }"><Transition name="page"><component :is="Component"/></Transition></RouterView>`，**故意不给 leave 类** —— 两页同时在场会把内容高度撑成两份、文字还叠在一起；旧页直接让位（时长 0 → 下一帧移除）反而干净。
- **“首次出现”的动画要拿持久标记闸住（v5.29）**：沉浸页是顶层路由 —— 进它时**主壳连同当前页一起被卸载**，退回时整页重挂。于是页内所有“靠重建才会播”的动画都会**白播一次**：设置页的 Tab 面板滑入（`tab-panel-in` 挂在面板内容上）就是被这个坑到的 —— 退回设置页时内容从右边滑进来，像刚切过 Tab 一样（需求方：“假设主页内容是设置界面，从歌词界面返回时，TabsContent 会出现从右向左的过渡动画”）。规矩：这类动画不要只靠“元素被创建”触发，要再加一枚**持久标记**说明“这是用户真的操作了”（这里 `is-switching`，下划线那边是 `is-ready`）—— v5.21 的 `no-enter` 讲的是同一件事的另一面。另：**@media 不增加优先级**，同优先级的 `prefers-reduced-motion` 覆盖如果写在原规则**前面**，会被按源码顺序压掉（v5.29 实测：那两条 Tab 覆盖一直是死的）——覆盖块要跟在被覆盖的那组规则后面，别丢到文件开头的“通用 reduced-motion 块”里。
- **在后台标签里验过渡/动画会看到假故障（v5.29）**：页面 `hidden` 时 rAF 不跑，而 Vue 的 `<Transition>` 正是靠 rAF 去 `getTransitionInfo` 的 —— 于是过渡**根本没注册上**：元素会卡在 `xxx-enter-from` + `xxx-leave-active` 这种中间态（实测：两张页卡在 `translateY(747px)` / `brightness(0.68)`，`getAnimations()` 为空），看代码怎么都找不到原因。验过渡、验逐帧动画（弹簧、marquee）先把页面拉到前台（`document.visibilityState === "visible"`）；后台时只能看 DOM/类名这类静态事实。
- **后台页面里截图也会是过期帧（v5.34 实测）**：这是同一套陷阱的第三个面孔 —— **测量是实时的，截图不是**（`getBoundingClientRect` / `getComputedStyle` 立刻反映新状态，而截图可能还是点击前那一帧；内置浏览器与无头 Firefox 都遇到过）。所以“元素到底在不在、有没有被盖住”别拿截图判断，用 `document.elementFromPoint(x, y)` + 计算样式：实测抽屉在截图里看不见，但 `visibility: visible` / `z-index: 90` / `elementFromPoint` 返回 `ASIDE.nav-drawer`，证明它一直在最上层 —— 差点因此去改一个根本没坏的样式。
- **“引擎给的”尺寸要实测，不要写死（v5.30）** —— **v6.18 起这条在本仓退休**：滚动条改成浮层条、不再占位，也就不需要知道它多宽（`--scrollbar-size` 只剩下少数仍在用原生条的地方当观感尺寸，**不再由 JS 实测**，`syncScrollbarSize` 已删）。原规则对别的“引擎给的”尺寸仍然适用：实测手法：离屏探针 `overflow: scroll`（+ `scrollbar-gutter: stable`），读 `offsetWidth − clientWidth`；把计算写成纯函数（`scrollbarSizeFrom(外框, 内容盒)`）就能在 node 环境里单测（client 的 vitest 不跑 jsdom），DOM 那半只干“建探针 / 删探针”。与 `--dpr` 同一个原则：JS 只写原始值，怎么用留在 CSS。
- **`calc(var(--x))` 里缺值会让整条声明失效（v5.31）**：`margin-right: calc(var(--scrollbar-size) * -1)` 在令牌没写进来时会被**整条丢弃** —— 表现不是“算成 0”，而是“这条规则像没写过”（需求方在 DevTools 里圈着这一行，并在 `<html>` 的 `style` 上看到只有 `--dpr`、没有 `--scrollbar-size`）。所以：**凡是要由 JS 写进 CSS 的令牌，CSS 里一律 `var(--x, 0px)` 兜底**（0 就是“不补偿”/“不偏移”的安全默认），别指望它总会存在。相连的另一半：**0 是有效值**（“本引擎不占位”），实测逻辑不能把 0 当“没量到”跳过 —— 否则会给不需要补偿的引擎多减一道（v5.30 就只做对了前一半）。
- **只在某一个引擎里出现的 bug，要能在那个引擎里验收（v5.30/v5.31）**：内置浏览器是 Chromium，Firefox 专属问题（滚动条宽度、`scrollbar-gutter` 行为）在那里根本复现不了 —— 别靠猜。做法：临时目录里 `npm i -D playwright` + `npx playwright install firefox`（不动项目依赖），再用十几行脚本开真实 Firefox、量数值并截图；`.vscode/mcp.json` 里也配了 Playwright MCP（`--browser firefox`），需要反复调试时用它更顺手。两条经验：① **系统里已开的 Firefox 会接管 `--screenshot`/新实例**（要 `--no-remote` + 独立 profile，不如直接上 Playwright）；② **量几何/读令牌，不要只看截图** —— 这次就是靠 `--scrollbar-size` 在两边的实测值（Chromium 10px / Firefox **0**）一眼定案，截图反而让人在“到底差多少”上打转。
- **移动端参考对象是 Salt Player（椒盐音乐）**（v5.32 需求方给定）：算“手机端应该长什么样”时的对照物，与原型同为**参考**而非教条——具体做法仍按本项目自己的令牌与结构落。官网自述里与本项目相关的几条：无首页推荐流、记忆式简易首页（低学习成本）；迷你播放条可显歌词；长按播放键进沉浸模式；封面/壁纸取色分主界面与播放界面两套；平板与横竖屏；通知栏/系统媒体控制。
- **触摸屏上没有“双击”也没有“悬浮”（v5.32）**：行的播放手势是 `@dblclick`、操作键靠 `:hover` 显形 —— 这两样在手机上**都点不出来**（手机的双击是缩放），等于“列表看得到、播不了”。规矩：
  - 判定用**能力**不用宽度：`click` 的 `pointerType === "touch"`（封成 `utils/pointer.ts` 的 `isTouchTap`）决定“点一下就是播这首”；桌面行为保持不变（单击不响应、双击播放）。不要用 `@media (hover:none)` 去改交互——那是给样式用的；
  - 但**样式**要用：`@media (hover: none)` 让靠悬浮显形的操作键**常显**（当兜底与显式入口）。同理，窄窗口的桌面仍能悬浮，**不要**拿宽度查询代替能力查询；
  - 不要自己写位移阈值判断“滑动”，浏览器本来就不会在滚动/拖拽之后派发 `click`。
- **覆盖组件内部的类要抬特异性（v5.32 实测）**：`VolumeControl` 的 `display` 写在它自己的 scoped 样式里（`.vctl[data-v-x]`），与 `global.css` 里 `.pb-ctrls .vctl` **同为 (0,2,0)** —— 而组件样式是运行时注入的，源码顺序更靠后，于是“藏在迷你条里”的规则静默失效（静音键赖着不走）。写法：全局覆盖组件内部类时加一层宿主前缀（`.playerbar .pb-ctrls .vctl` → (0,3,0)）。同一条也解释了为什么“@media 不增加优先级”。
- **布局开关要限定到宿主（v5.43 / v5.44）**：`global.css` 的 `.sidebar { display: none }` 与 `AppSidebar` 里那四条 `.app.collapsed …`，都曾因为写得太通而“跨进抽屉”（抽屉里渲染的是**同一个** `AppSidebar`）——一次让抽屉变成空面板（点不开、只有遮罩），一次把选中项的右圆角与内缩切平。两条：① 以“外壳/宿主状态”为前提的规则，选择器就**从外壳那一层写起**（`.app > .sidebar`、`.app.collapsed > .sidebar …`）；② 复用同一份内容时，**宿主差异（宽度、断点、折叠态）由宿主那层给** —— 比如抽屉里内容层写 `width: 100%` 跟着宿主，而不是指望组件里那两档写死的宽度（写死的 224 落在 208 的抽屉里就是溢出 + 被裁）。
- **手机断点只有一处：`<768px`（RT-01）**：侧栏/迷你条/底栏/管理台提示全用同一个 `max-width: 767px`，别在别处再写 720/780 这类近邻值。列表列宽改 `--row-grid` 时**表头与行要在同断点各自隐藏对应单元格**（`TrackRow` 与 `TrackListHead` 各一份 display:none）——列宽只有一份、单元格对齐靠两边一起藏，否则列会错位。
- **把浏览器 API 拆成“纯函数 + 薄封装”才测得动（v5.32）**：Media Session 一类接口（`navigator.mediaSession` / `MediaMetadata`）在 Vitest 的 node 环境里不存在，所以“该写什么值”必须能脱离浏览器单测：`utils/mediaSession.ts` 里 `buildMetadata` / `buildPositionState` 是纯函数（含“空字段一律省略”“时长未知或位置非法返回 null”这类规则），`applyXxx` / `attachActions` 才是 DOM 调用且**先探测再跳过**。`App.vue` 一类“永远在树上”的根组件才是挂全局副作用（锁屏、快捷键、存档恢复）的地方 —— 挂进布局会在换布局时静默解绑（播放器 store 是单例，控制台页面里音乐照样在播）。
- **改“怎么收起来”之前先问清**作用范围**（v5.34 的教训）**：需求方一句“侧边栏能不能像 Salt Player 收起来”，我按“桌面 + 手机都改”落了地 —— 桌子被推翻，实际只要改手机。两种改法在不同断点上是两件不同的事（手机：底栏→抽屉；桌面：图标条→完全隐藏），**动前先确认改哪一端**，或先把两种效果并排描述一遍再动手。
- **别用 `fixed` 去“对齐”某个流内元素（v5.35）**：想让浮动控件和标题同一行，不要去算 `top: 18px` 猜标题在哪（页面内边距或行高一改就错位，实测差 23px）—— 把它**放进那一行**才稳（这个按钮最后直接渲染进各页 `.page-head`，中线差 0px）。配套两条：① 进页头还顺带解决了“滚动后按钮消失”（页头住在滚动区外面，v4.41 的固定帧）；② 按钮与面板被迫分居两处时（按钮在页头、面板在外壳），把状态提到 `composables/` 的模块级单例（只一个布尔值，不为它引 Pinia；出现第三个消费者再升级）。
- **对齐先选对参照物（v5.35 实测）**：“按钮要和标题一行”实际上要求的是对齐**标题首行的行盒**，而 `align-items: center` 对齐的是**整个标题块**（`<h1>` 里还包着 `.sub` 描述，块高 47～64px），且参照是**同一行里最高的那个元素** —— 页头那组操作按钮在窄屏换行一高，标题就被挤下去（实测 /local 偏低 11px）。两条做法：① 偏移值从**同一组变量**派生（`--page-h1-size` × `--page-h1-leading` 得出行盒高，不写 `-3px` 这种魔法数）；② 同行还有别的东西时，让需要对齐的两端都 `align-self: flex-start`，把“行首位置”固定住，再各自补自己的居中偏移。需要精确到“第几行”时，用 `Range.selectNodeContents(el).getClientRects()[0]` 量那一行（量元素盒子拿到的是整块）。
- **Tab 条窄屏横向滚动，不要换行（v5.47）**：标签排不下时用 `.tabs-wrap { overflow-x: auto }` + `.tab { flex: none; white-space: nowrap }` + `.tabs { width: max-content; min-width: 100% }`（后两条分别防“被压成竖排”与“发丝线断在一半”）。**为什么不换行**：下划线（`.tabs__ink`）是一根横线、只能描述“单行里的位置”，换行后它就没有意义（要退回每格自带下划线，丢掉滑动效果），而且页头会忽高忽低。配套两条：① 横向滚动条隐掉（`scrollbar-width: none` + `::-webkit-scrollbar { display: none }`）—— 它只有几像素高，会压在标签下沿与下划线上；② 选中项要自动滚回可视区（`scrollIntoView({ block: "nearest", inline: "nearest" })`，**block 不能省**，否则整页也会被滚一下）。⚠️ 坑：外层一旦成为滚动容器就是 BFC，**内层子元素的下外边距不再与外层合并** —— 原来靠合并藏在页外的 20px 间距会突然“住进”容器里，指示条 `bottom: 0` 就跟着掉 20px；遇到“滚动化之后某条线错位”先查这一条。
- **首屏不该播“进场”动画（v5.51）**：路由组件是**懒加载**的（`() => import(...)`），首屏先渲染成空、拿到 chunk 之后再挂上 —— Vue 会把这次“从无到有”当成一次普通 enter，于是刷新/直达 URL 也会播“从底部升起”这类进场动画（它的语义本是“从上一页过来”，而刷新根本没有上一页）。做法：根组件里给 `<Transition>` 绑 `:css="allowTransition"`（首屏为 false —— `:css="false"` 让 Vue 跳过过渡类与等待，元素一帧到位），**首个 enter 的 `@after-enter` 里再放开**，另加“第二次导航后也放开”的兜底。已实现排除的两个写法：在 App 的 `onMounted` 放开（App 挂载时 RouterView 还是空的，太早）、用 `router.isReady()`（与首屏渲染谁先谁后取决于微任务顺序，不可靠）。
- **抽屉 / 大面的材质走 `--tray-*` 令牌，跟着材质模式走（v5.45 → v5.46）**：手机左侧抽屉的 `--tray-bg` / `--tray-blur` / `--tray-shadow`，浮岛模式下是玻璃（`rgba(255,255,255,.88)` / `rgba(50,50,54,.80)` + `blur(64px)` + 右向投影），flat 下退回实心（`--plane`、无模糊、无投影）—— **组件不判断模式，只读令牌**（铁律 1/3）。三条量出来的经验：① 玻璃的透明度要按**它透出来的是什么**来定：抽屉下面压着遮罩，透出来的是“被压暗过的页面”，而桌面侧栏岛透出来的是没压暗的页面 —— 照抄同一句透明度，抽屉就比岛暗一截（需求方：“浅色模式下……侧边栏为什么有点暗？”）；② 也不能太透：`backdrop-filter` 在部分环境里根本不参与合成（无头 Firefox、VS Code 自带浏览器实测都不合），太透会糊成两层字，所以抽屉取 .88/.80 而不是小浮层的 .52/.46；③ **背后是同屏控件的“大面”，优先把控件淡出、而不是把面做成实心**（v5.48）：队列底部抽屉背后就是沉浸页那排走带键 —— v5.46 的解法是“它不跟材质模式、固定实心”，但那样在浮岛模式下就丢掉了玻璃；现在改成“抽屉打开时把那排控件与进度行淡出”（`body:has(.q-sheet) .im-ctrls, … { opacity: 0 }`）：控件本来就被抽屉盖住，淡出在视觉上零代价，玻璃背后却干净了 —— 于是**不靠模糊也能看**。用 `:has()` 而不是共享状态：只在手机存在的那个壳才会命中，不会误触桌面浮层。判据：“浮在页面之上”的东西要么**比页面底亮一档**、要么**是玻璃**，别跟被盖住的那层同色（深色下拿页面底色当抽屉底 = 一块黑斑，需求方 v5.45 报过）。
- **图标与文字“看着一样高”要按墨高算，不按盒子（v5.36）**：汉字字形几乎占满 em，而图标集（Phosphor 等）的画布四周留白多、实际墨迹只占 ~80% —— 所以“字号 20px + 图标 20px”看着就是图标小一号（需求方一眼看出）。经验值：图标盒子取字号的 **1.25～1.3 倍**（实测 20px 汉字配 26px 图标才相当）。同理，想让某段文字与**图标**而不是按钮热区对齐，缩进要写 `calc((按钮尺寸 − 图标尺寸) / 2)`（从同一组变量算，不要写 7px）。
- **混合尺寸的按钮排：“居中”按盒子算、“看起来的间距”按图标算（v5.41 复核）**：沉浸页底部一排 = 4 枚 22px 图标 + 中间 56px 的播放键（圆底 56px、图标 32px）。实测 320/360/390/430/540 与横屏 844 **六种宽度**：排面中心与视口中心偏差 **0.0px**、播放键中心同样 0.0px、左右留白完全相等（390 下 75/75），而且与上面进度条的中心是同一条中轴（`barOff` 也 0.0）—— 所以**不要**再手动补 `padding`/`margin` 去“配平”（补了反倒会真的偏）。但两枚图标之间**看起来**的距离不是等距：两端 22px、播放键两侧 38px（图标间距 = 盒间距 + (播放键盒 − 播放键图标)/2 = 盒间距 + 12），这是因为播放键的圆底比图标宽 —— 想调成“图标等距”就得把播放键两侧盒间距压到 10px，圆底会贴到相邻图标上，别为“等距”牺牲这块留白。判据：**先量盒子中心，再决定要不要动**，别凭截图感觉挪。
- **圆角容器的进度环：抄社区标准，别自己发明（v5.37）**：参考物是 CSS-Tricks《Building a Progress Ring, Quickly》（Jeremias Menichelli）+ MDN `pathLength`。落地四条：① 画在 **SVG `<rect>`** 上而不是 `<circle>` —— 环必须跟着容器的轮廓（封面是圆角矩形，圆环会切在四个角上，因为角上离中心最远）；② 外扩多少就 把圆角 +多少（`rx: calc(var(--radius-cover) + 3px)`，用 CSS 属性写，改令牌环自己跟上），四边与四角间距才均匀；③ 弧长用 `pathLength="100"` **归一化**，进度只跟比例有关、与周长/圆角无关 —— 这就是原文评论区“把路径凑成 100”技巧的标准写法，于是 JS 一行几何都不用算（原文要在 JS 里 `2πr` 再写内联样式）；④ 原文的 `rotate(-90deg)` 只适合圆（把起点挪到 12 点），**矩形不能转**（会转歪）。
- **`calc()` 的结果是无单位数，配长度属性时必须自带单位（v5.37 实测）**：`stroke-dashoffset: calc(100 * (1 - var(--p)))` 整条声明会被丢弃（不是“算成 0”），因为 `stroke-dashoffset` 要的是长度 —— 表现是环永远不动。写成 `calc(100px * (1 - var(--p)))` 才对。同族：`var()` 缺值也会让整条声明失效（v5.31），都是“声明静默消失”而不是报错，只能靠**量计算样式**发现。
- **居中 + 负边距会叠加（v5.36 实测）**：给一个栅格/弹性子元素配负数 `margin-top` 来“自己算对齐”时，父级的 `align-items: center` 会先把它居中、再叠加负边距 → 实测偏高 3.5px。两边都要居中时用 `align-items: start`，把定位完全交给那个负边距（与“同时用两个机制会打架”是同一条规矩，v5.15 在侧栏页脚踩过一次）。
- **页头是“标题行 + 描述行”，描述不要塞进 `<h1>`（v5.35）**：`<h1>` 只接**短语内容**，把 `<div class="sub">` 放进去本身就是无效 HTML；而一放进去，描述就只能跟着标题的缩进走（需求方圈图：“这个要左对齐”）。正确结构是让两者当兄弟：`.page-head__title`（`display: grid` + `grid-template-columns: auto minmax(0,1fr)`）里放 `[☰][h1][.sub]`，描述 `grid-column: 1 / -1` 横跨两列 → 自然回到页面内容左边界，与其他内容同一列。
- **挤不下时让“旁边的按钮”换行，不要压标题（v5.35 实测）**：页头给 ☰ 腾出 46px 后，`/local` 的“本地播放”被压成两行（列宽 67px < 文字 88px）—— 标题一换行，按钮按“整行”居中的参照就变成两行（实测偏低 14px）。两条做法：① 手机断点给 `.page-head { flex-wrap: wrap }`，宁可让操作按钮另起一行也不让标题断字；② 依靠“某行”对齐的控件（如标题旁的 ☰）一律按**首行的顶 + 派生偏移**定位，别用 `align-self: center`（它的参照是整行，行内换行就偏）。
- **覆盖式抽屉的落地清单（v5.34）**：① 面板用自己的 `transform: translateX(-104%)` + `visibility: hidden` 收起（比 `v-if` 多了进出动画，又不会留在可聚焦/可读序列里）；② 抽屉里直接装**现成的侧栏组件**，不要另写一份导航（导航项仍然只有 `useNavItems` 一个来源）；③ 触发：一个只在该断点出现的按钮 + 屏幕左缘热区（触摸右滑拉出）；④ 关闭有四条路：遮罩、面板内反向滑、Esc、选完页面自动收起 —— 少一条都会让人觉得“卡住”；⑤ 只在该断点渲染整个组件（`v-if="isMobile"`），桌面端连元素都不存在，就不可能出现“忘了隐藏”的残留。
- **手势只认真实触摸，且要给控件/滚动区让路（v5.33）**：一页里的手势必须回答三个问题——**谁能触发**、**从哪起手**、**到什么程度才算**。
  - 谁能触发：一律 `pointerType === "touch"`（封成 `utils/pointer.ts` 的 `isTouchTap`）。桌面上鼠标拖一下不该切歌、按住播放键也不该算“长按”——桌面既有行为一分不变；
  - 从哪起手：手势区要显式排除**有自己语义**的区域（歌词列表要滚、控件要按、顶栏要关页）——用 `el.closest("header, .im-ctl, .ly, .ly-view")` 一句判掉。否则“滑一下切歌”会变成“想滚歌词却切了歌”；
  - 到什么程度才算：阈值（40px）+ **方向要明确**（横向位移要大于纵向的 1.5 倍），不要猜“差一点点算横还是算竖”；
  - 附带一条：滑动手势落在“本来就行点击”的元件上时，要在处理完后短暂抑制接下的 click（`justSwiped` 400ms），否则“滑一下”会额外触发“点一下”（轻则多翻一首，重则弹出页面）；
  - 触摸元件的 `touch-action: pan-y`：横向手势区要手动把横向留给自己，否则浏览器可能拿去当滚动/返回手势，pointer 事件根本不到你手里。
- **断点判断只在“换内容”时才允许用 JS（v5.33）**：纯样式差异一律留在 CSS 的 `@media` 里（见“手机断点只有一处”）。但两处内容**真的不同**时（迷你条第二行：桌面是“歌手·专辑”、手机是当前歌词），无法靠 CSS 显隐 —— 两个 ScrollingText 同时在树上会各跑一份跑马灯测量。这种做法用 `composables/useMediaQuery`，并且把断点写成导出常量 `MOBILE_QUERY`（与 CSS 那个 767px 同值，改要一起改）。
- **【归档】共享元素过渡（View Transition）已在 v5.26 整体删除**（需求方：“VT 代码你给删除干净吧”）：下面四条描述的实现（自测清单、v5.21 的压动画、v5.22 的选盒子、v5.23 的溢出装饰）都不在代码里了，代码见 git 历史 v5.18~v5.25。留着是因为它们讲的是**带快照的浏览器级过渡**这类机制的通用坑，将来若再用（或改用 `clip-path` 自己做形变）可以直接拄。
- **共享元素过渡（View Transition）的九条自测清单（v5.18 → v5.19）**：用在“同一张封面从小变大”这种场景（播放条 ⇄ 沉浸页）效果很好，但坑很集中：① 两端各挂同名 `.vt-cover`（`view-transition-name: qt-cover`），且**该名字在任一时刻只能有一个元素**——否则浏览器直接跳过整个过渡（我们的两个页面不共存，所以天然成立）；② 回调里要 `await 导航` + `nextTick()`（快照在回调 promise 落地后才拍）；③ **`router.back()`（history traversal）会把手动起的过渡掐掉**（实测 ready 后 11ms 跳完；`push`/`replace` 正常跑满 435ms）——关闭改成 `replace(来路)`；④ 过渡期间在 `<html>` 上挂 `data-vt`，让新页自己的入场动画让位（否则快照拍到的是 opacity 0 的空页）；⑤ 封面这一对要关掉交叉淡化（`::view-transition-old/new(*) { animation: none }`）——但这只在“旧/新确实是同一张画”时成立，换成两个不同的东西就会**两图叠加**（同一次过渡里两端不是同一张画时实测如此）；**但别据此就把整个布局排除在外**：v5.22 起彩胶也参与，靠的是⑥ 那套“只让大位图唱主角”的方向处理（——v5.25 又撤回来了，见⑥ 第二段；现在只有双栏在用）；⑥ **只让大位图那一侧唱主角**：飞行中的快照是**被拉伸的位图**，两端位图分辨率通常差几倍（播放条封面 52px / 沉浸页封面 ~254px）——两侧都画必有一侧是糊图，而**整段交叉淡化**又会让两张半透明的图叠在一起（原型实测“几乎看不见封面”）。定稿（v5.24）：**小位图那一侧在开头/末尾约 28% 内淡出／淡入**（`@keyframes` 只动 0%→28% 与 72%→100% 两段，中间不变），于是中间 ~70% 只有一张大位图，而“换主角”的那一下发生在看不清的一小段时间里。哪一侧是“小”的取决于方向（飞入时 `old` 小、飞出时 `new` 小），所以 `withViewTransition(update, "in" | "out")` 要收方向参数供 CSS 用。
  **为什么要淡化那一下（v5.24 的教训）**：View Transition 只能形变**盒子**，位图本身不换形 —— 两端不是“同一张画”时（彩胶=圆唱片+小标签，播放条=满幅方形封面），快照层被拆掉的那一瞬必然**硬切**（需求方：“从彩胶盘一下子变成方形封面”）。把切换放进 28% 的交叉淡化里就没这一帧了。想让形状真的“圆变方”，得自己在伪元素上动 `clip-path`——那是下一步的活，不是 VT 自带的。
  **但“淡化”也只是急救（v5.25 的裁决）：两端不是同一张画，就不该用它。** 彩胶实打实试了三个版本——方框残影（v5.23 修：光晕被快照盒裁切）→ 落地硬切（v5.24 修：换成头/尾淡化）→ 仍然不够干净（需求方：“如果做不到完美就退回普通过渡效果吧”）。原因是根上的：这一对的两端既不同形（圆唱片 vs 圆角方封面）也不同画（唱片+小标签 vs 满幅封面），而 VT 只能形变盒子、不能换形换画 —— 每修一层就冒出下一层。所以 v5.25 把彩胶从共享元素里挪出去，只走整页交叉淡化（`.vinyl-assembly` 不再挂 `.vt-cover`）。结论：**先问“两端是不是同一张画”，否就不接**；真想让形状变形，那是自己写 `clip-path` 的活，与 VT 无关。
  **方向开关必须写成“继承的自定义属性”，不能写后代选择器（v5.22 实测两次才认）**：`html[data-vt-dir="out"] ::view-transition-new(qt-cover) { opacity: 0 }` 这种写法**永远匹配不到** —— `::view-transition-*(名字)` 不在“元素后代”树里，规则静默失效，页面上表现成“飞出时飞的是播放条那张糊图”（v5.19 当初就这么写，还误记成“已验证”）。判别手段很值、也很快：给 `::view-transition-old/new(qt-cover)` 各画一圈描边（old 红 / new 蓝）再截中途帧，就能直接看见画的是哪一侧；再用一次“两侧同时 `opacity: 0 !important`”确认写法本身有效（那次飞行元素会彻底消失）。正确写法是在 `<html>` 上设变量、在伪元素里读（自定义属性沿树继承，实测拿得到）：`html[data-vt-dir="in"] { --vt-old-anim: vt-cover-head-out var(--vt-cover-dur) linear }` + `::view-transition-old(qt-cover) { animation: var(--vt-old-anim, none) }`——**变量里可以装整条 `animation`（含时长）**，慢放调试时只改 `--vt-cover-dur` 一处，盒子形变与淡化就不会脱节。
  ⑦ **同名元素在任一时刻只能有一个**：否则浏览器直接跳过整个过渡。原型是单页 overlay，两个封面共存，所以它要在回调里把 `viewTransitionName` 从一个小图**动态搬到**另一个（`show ? "none" : "cover"`）——我们的两个页面不共存，天然满足，但若将来改成 overlay 就必须补这一步；
  ⑧ 加一个 1.5s 看门狗 `skipTransition()`（个别环境过渡不结束会把旧页快照永久留在顶层）；⑨ `prefers-reduced-motion` 时连 API 都别调。另：`animation-timing-function` 写在 `::view-transition-group()` 上是**生效**的，但只用 `getComputedTiming().progress` 看不出来（那是动画级缓动），要验就采样**渲染出来的** transform。
- **共享元素要选“不动的那个盒子”，并且把一直在跑的动画在过渡期间停住（v5.22；v5.25 起彩胶已不参与过渡，这条只作原理保留）**：彩胶就是反例教材 —— 盘（`.v-disc`）与中心标签都在 8s/圈 地转，**拿它们当共享元素等于让封面“边飞边转”**（捕获到的四角是斜的，而且角度取决于点击那一刻）。要选**不旋转的外壳**（`.vinyl-assembly`，只管摆放、不管转动），飞出去的四角才是正的。连着还有第二层：快照是**冻结的一帧**，而实况元素在旁边照转，420ms 就是 19°，落地那一下必然跳 —— 所以过渡期间给 `<html data-vt="on">` 加一条 `animation-play-state: paused`（**暂停，不是撤掉动画**：撤掉会让它从 0 相位重播。实测过渡中 `currentTime` 冻在 1512ms、过渡结束从 1512 继续）。**这条要压过组件自己的 `.poster.is-playing .v-disc { running }`**：写全 `html[data-vt="on"] .poster.is-playing .v-disc`（(0,4,1) > scoped 的 (0,4,0)）才生效，别再往选择器里减层级。（v5.25：彩胶不再参与过渡，这条暂停规则也一并删了 —— 不再有快照，盘就该照常转；将来重新启用时记得加回。）
- **共享元素的盒子里不能有“溢出盒子”的装饰（v5.23）**（v5.25 起彩胶不再参与过渡，但这条规律成立：别让将来可能要当共享元素的盒子拥有溢出的装饰）：View Transition 只快照“带名字那个元素”的**边框盒**，盒外的东西一律被硬裁 —— 彩胶的外圈光晕（`inset: -20%`，比盘大 40%）原本是外壳的 `::before`，飞行末段就在盘外露出一圈**直边方影**；落地换成实况的完整柔光，于是“只在飞行中出现、落地即消失”，很容易误判成“落地时闪一下”（需求方原话：“彩胶外部会有可见方形残影包裹”）。缩小到播放条大小时这圈方边还会直接读成“方形封面”（需求方第二个反馈）。规律：**共享元素既要被快照、又要有溢出装饰时，把装饰挪成它的兄弟节点** —— 不进子树就不进快照，四角透明的圆形主体飞起来自然干净。推论两条：① 挪出后**几何必须与改前逐像素一致**（这里靠把新元素的位置尺寸也从 `--vinyl-t/-r/-d` 派生：实测 1.4 倍盘径、圆心偏差 0）；② **不在快照里的东西不用跟着停动画** —— 呼吸/脉动照常跑，只有被快照的那一层才需要 `animation-play-state: paused` 去消除“冻结帧 vs 实况”的错位。
- **`min-width` 给空隙“找地方住”时会破坏对称（v5.41）**：进度行两枚时间各有 `min-width`（给 `4:43` 这种四位数留位），而文字默认左对齐 —— 多出来的那点空隙就全堆在“时间 ↔ 进度条”之间，实测桌面**左 21px / 右 10px**（沉浸页同一个毛病），截图看上去就是两侧缝隙不等（需求方：“进度条左右时间和进度条之间缝隙宽度不一致”）。规律：**成对的数值/标签要贴着它们描述的对象排**（左枚靠右、右枚靠左），盒子多出来的空间放到**外侧**，两侧缝隙才都等于那个 gap（改后 10/10，外侧留白也从 0/11 变成 11/11）。配方写在 `global.css` 的 `.time` 上，两个宿主（播放条 / 沉浸页）共用一份。
- **“同一个左内边距”不等于“同一条中轴”（v5.17）**：图标列宽 19px、品牌标记盒 26px，两者都从 12px 左内边距开始，中轴就差了 (26−19)/2 = 3.5px —— 展开态看着只是“稍微不齐”，**窄栏里（周围只剩图标）一眼就看出 logo 没居中**（需求方圈图指出来）。要按中轴对齐就写成 `calc(12px − (var(--brand-mark-size) − 19px) / 2)`（侧栏 8.5 / 控制台 9.5），顺带让品牌文字与导航文字对齐（68.5 / 69）。规律：**一行里的元素宽度不同时，对齐目标要明确选“左边界”还是“中轴”**，选左边界就得接受中轴偏移，反之亦然。
- **品牌标记用“遮罩 + 变量上色”，不要直接放 `<img>`（v5.16）**：单色 logo 一律做成“透明底单色标记”当遮罩用（`background: var(--accent)` + `mask: url(...) center / contain`）——深浅主题、封面取色自动跟着走，也不用为 HiDPI 出多套图；尺寸统一走 `--brand-mark-size`（侧栏 26 / 控制台 24 / 登录页 30，默认 22）。配套一条：**图片元素不要放进靠行高撑高度的行盒**——它的基线对齐会把图片高度算进行盒（盒子会比预期高），要用 flex 对齐 + 写死行高，否则会重演 v5.12 的“图标瞬跳”（侧栏 logo 盒两态都必须 48px）。
- **抹素材上的第三方水印，优先“裁掉”而不是“涂白”（v5.16）**：AI 生成图的水印通常压在角落。做法是用“只认主体颜色”的严格阈值（只认深色）求 artwork 包围盒 → 按包围盒 + 小边距裁剪，水印自然不在结果里，且不会留下修补痕迹（涂白/模糊在有渐变或纹理的底上一定会露）。动手前先量一下水印像素的实际范围，确认它与包围盒不相交（实测浅灰水印在 `x 631–751 / y 725–753`，artwork 包围盒到 `668/685` 为止）。
- **滚动范围只包住“会无限增长”的那部分，外壳控件一律固定（v5.15）**：侧栏曾经把整列做成滚动容器（`.sb-inner { overflow-y: auto }`），品牌 / 导航 / 歌单 / 页脚全在一条滚动流里 —— 窗口一矮（实测 ≤ 440px）或列表一长，**页脚的「设置 / 折叠侧边栏」就被推到滚动区外面**（300px 高时页脚底 318 > 可视底 174），而且任何“要不要滚动”的变化都会把项与高亮挤窄 10px。正确分工是品牌与页脚 `flex: none` 钉住 + 中段（导航 + 歌单，未来的列表）包进唯一滚动区（shadcn 的 `SidebarHeader/Content/Footer` 同构）。判断标准：**这个内容会不会随数据无限增长、或者说它会不会被用户“滚走”**——外壳控件、导航、页脚都是“永远要能在手边”的那类。播放器侧栏 `.sb-scroll` 与控制台侧栏 `.cs-nav` 用同一套（改动要同步两处）。
- **“内容比盒子高”不等于“能滚”（v6.19 定稿）**：画不画滚动条、以及“宿主是不是住在别人的滚动区里”这两个判断，一律用 `utils/scrollbar.ts` 的 **`canScrollY`**（两条件都要：计算样式为 `auto | scroll` **且** `scrollHeight − clientHeight > 1`，容差 1px）。只看 `scrollHeight` 会给 `overflow: hidden` 的容器也画上一条 —— 而它因为滚不动就永远等不到“内容装得下”那一刻把自己爁掉，表现是**岛上多出一条永远挂在右上的条**（v6.19 需求方报的“两个进度条”就是这个：岛与页框各一条）。相连的一条：**不需要的条要真拆掉，不要只把 `is-on` 拿掉**（`opacity: 0` 不等于不可点，见坑 18）—— 滑坎的 `pointer-events: auto` 是特意留的（淡出后还能抓回来），留着的隐形条就是一条呑点击的 7px 缝。
- **要拖的列表里，“点一下”必须由 `pointerup` 收尾，不能靠 `click`（v6.20 实测抓到）**：给容器 `setPointerCapture` 之后，后续指针事件（含 `pointerup`）会被**重定向到容器**；浏览器据此把随后的 `click` 派发给“按下目标与抬起目标的**最近公共祖先**”—— 也就是容器自己，**行/项上的 `@click` 永远不会触发**（实测落点：`pointerdown: lyline` / `pointerup: ly-list` / `click: ly-list`；需求方报的“点击歌词不跳转”就是这个）。写法：在 `pointerdown` 里先记下“按到了哪一项”（把下标写在元素上，用 `closest()` 取），`pointerup` 时如果没滑动就当场执行点击动作；`@click` 留着给键盘与读屏（它们不走指针），并做**同一项 400ms 去重**（有的浏览器仍会把 click 给到按钮）。
- **`v-memo` 的依赖必须包含“每帧会变”的那个量（v6.20 实测）**：v6.9 为了收窄逐帧重渲染给歌词行加了 `v-memo`，依赖写成 `[i === activeIndex, i < activeIndex, depths[i]]` —— 播放中这三个值**一句之内不会变**，于是当前行整棵子树被原样复用，逐字填充真的**一帧都不会更新**（实测行级 `--p` 在同一句内冻在 0.0078，换句才变）。补法：把“会变的那个量”做成一个 computed（这里是把逐字进度压成一个字符串 `fillKey`），只对**当前行**取它、其余行恒为空串 —— 这样只有当前行每帧重渲染，收窄的目的也保住了。判断这类 bug：**看那个动画其实在跑的东西（内联变量 / 类名）到底有没有变**，别只看“当前行对不对”。
- **时间轴数据的“相对 / 绝对”口径要写在类型旁边（v6.20 实测拓出一个老 bug）**：`LyricWord.start` 是**相对本句开头**的（两个解析器都这么给），而 `currentLineIndex` / `lineProgress` 用的是**绝对秒**。`wordFillProgress` 当初拿绝对时间去比相对起点，任何大于半秒的时间点都让所有字算“已唱完”—— 逐字填充从来没真正亮过，而且旧单测喂的也是相对时间（正好掩盖）。写这类纯函数时：**要么把相对时间当参数名（`insideSeconds`），要么在函数里先减掉行起点**，并在单测里用“绝对时间 + 非零行起点”做一例。
- **需要“随布局变化才出现”的问题，必须去真实且可见的浏览器里验（v6.19）**：这类现象靠本仓那套“后台页面”验证根本出不来 —— 后台标签里 **`ResizeObserver` 与 rAF 一样不触发**（不只是坑 10 说的 rAF），所以“窗口变矮后才多出来的条”永远不会发生。方法：真实浏览器 + **按尺寸扫描**（700 → 300 逐档开一个新页面，每档都重新加载），量 `.os-bar` 的宿主与矩形。本机已有一套可用环境：`%TEMP%\pw-ff`（Playwright + 真实 Firefox，脚本 `probe-heights2.mjs` / `probe-settings.mjs`）。
- **滚动条一律是浮层的，不再为它留宽度（v6.18 定稿，取代 v5.15 / v5.30 / v5.31 那套补偿）**：原生滚动条**占位**，我们曾为它写三套补偿 —— 页框与表头各留一条 `scrollbar-gutter: stable`、侧栏与控制台用 `margin-right: calc(var(--scrollbar-size) * -1)` 把槽挪进内边距、`--scrollbar-size` 启动时离屏实测。现在**全部删掉**：滚动容器挂 `v-overlay-scroll`（或把类名加进 `directives/overlayScroll.ts` 的 `AUTO_TARGETS`，弹层里的容器由 MutationObserver 自动挂上），原生条被藏掉（`scrollbar-width: none` + `::-webkit-scrollbar { width: 0 }`），自绘条浮在内容上、只在滚动 / hover 时出现（闲置 900ms 淡出）。五条记住：
  ① **条挂在滚动容器的父元素上**（绝对定位的子元素属于**被滚动的内容**，挂里面会跟着列表滚走）；父元素拿 `data-overlay-scroll-host` 只为 `position: relative`。
  ② **位置量出来写内联**（`syncBarBox`：滚动区常靠负边距溢出页框，CSS 里的 `top/right/bottom` 会落到内容中间）；只在尺寸 / 内容变化时量，滚动时只算滑块。
  ③ **别往 `AUTO_TARGETS` 里加会包住滚动区的祖先类名**（v6.18 实测踩过：`/library` 上 `.content` 是页框的祖先，它先挂上之后，里面的 `.page-frame__scroll` 被当成“嵌套”跳过 —— 整页退回原生条）。嵌套判据要用**外层是不是真的在滚**（`overflow: auto|scroll`），别用 `scrollHeight > clientHeight`（`overflow: hidden` 的岛内容也可能更高）。
  ④ **滚动仍然走原生**：不接管滚轮 / 触摸 / 键盘；滑块位置一律**由滚动位置反推**（`scrollToThumbOffset` 只写 `scrollTop`）——两个来源各写一次样式会在同一帧里互相拉锯。
  ⑤ **触摸设备整条不画**（`@media (pointer: coarse)`）：iOS / Android 本来就是浮层条，叠一条自己的就是两条。
- **拖拽类手势的“松手”要挂窗口级兜底（v6.18，参考 OverlayScrollbars 的做法）**：只在自己元素上听 `pointerup` 不够 —— 指针捕获可能被系统收走（触控笔、系统手势、元素被重渲染卸载），于是“拖拽中”的状态永远挂着（滑块继续跟指针、条再也不淡出）。做法：`pointerdown` 时同时 `window.addEventListener("pointerup" | "pointercancel", end, { once: true })`，元素上再补一个 `lostpointercapture`；两份监听都到也无妨，收尾函数自己判状态、是幂等的。另：`pointerdown` 上 `preventDefault()` 会连带压掉兼容鼠标事件与随后的 `click`（这正是“拖完不会误触发底下的行”的原因）。他们另外两条本仓**暂时**不需要（已核查：全仓没有 `scroll-snap`，`scroll-behavior` 只出现在 reduced-motion 里被强制成 `auto`）：`scroll-snap` 容器要在拖拽期间临时摘掉吸附（否则写进去的 `scrollTop` 会被吸附回去），以及元素被 transform 缩放时要按 `getBoundingClientRect / offsetHeight` 换算指针位移。将来真加了 `scroll-snap` 或给滚动区套了 transform，记得回来补这两条。
- **`overflow-y: auto` 会顺手把 `overflow-x` 也变成 `auto` —— 动画里会冒横向滚动条（v5.14）**：CSS 规定 `overflow-x/y` 其中一个不是 `visible` 时，另一个的 `visible` 会被算成 `auto`。侧栏内层只写了 `overflow-y: auto`，展开动画中有两三帧“内层还窄、文字已瞬时显形”，于是**底部冒出一条横向滚动条又消失**（实测展开第 25ms：内层 81px、横向溢出 36px、滚动条高 10px），需求方直接看出“底部跳变、像个滚动条”。**要裁切就显式写 `overflow-x: hidden`**（或两边都写全），别指望只写纵向就没事；量这种问题看 `scrollWidth - clientWidth` 与 `offsetHeight - clientHeight`。
- **scoped 样式里不要写 `display`，除非想盖掉全局的响应式规则（v5.10）**：移动端靠 `global.css` 的 `.sidebar { display: none }` 收侧栏，而 scoped 选择器 `.sidebar[data-v-x]` 特异性更高 —— 在组件里随手写一句 `display: flex` 就会让它窄屏又冒出来（网格已经是 `1fr`，会直接盖住内容）。
- **共享指示条/底板是兄弟节点时，内容层必须自己抬起来（v5.9）**：滑动底板写在按钮组的后面（Vue 模板里后写的先不上面，而**同为定位元素时后画的在上**），于是选中项的文字会被那块颜色盖住 —— 看上去像“字体或颜色出了问题”。做法：给真正装内容的元素（`.seg__opt`）`position: relative; z-index: 1`。（Tab 下划线没这个问题：它在文字**下方**。）
- **字符串 `ref="name"` 在 vue-tsc 里不算“使用”（v5.9）**：只在模板里用字符串 ref 绑定的 setup 变量会被 `noUnusedLocals` 报 TS6133（之前没爆是因为脚本里也读了它）。两个办法：在脚本里真读一次，或者改用**函数 ref**（`:ref="setRoot"`）—— 后者更干净，组合式函数把 ref 收在自己内部。
- **靠 DOM 结构写的选择器，动结构后要回头验证（v5.7 踩过一次静默失效）**：`.tabs ~ [role="tabpanel"]` 在 v5.6 给 `TabsList` 裹了一层 `.tabs-wrap` 之后就再没匹配过（面板不再是 `.tabs` 的兄弟），页面**不报错**、只是动画悄悄消失，直到需求方问“内容切换能有过渡效果吗”才发现。所以：用兄弟 / 父子关系选元素时，**加包裹层要同步搜一遍旧选择器**（`grep` 一下 `.tabs ~` 这类写法）；能用自有 class 就优先用 class。
- **要“滑过去”的指示条只能是一条共享元素（v5.6）**：给每个 tab 自己的 `border-bottom` 换颜色，只能原地淡入淡出，切页时看着就是“灭了又亮”；要滑动就得抽出一条 `position: absolute` 的指示条，JS 只量**两个原始值**（当前格的 `offsetLeft` / `offsetWidth`）写成 CSS 变量，滑动与宽度变化交给 CSS 过渡（与取色管线同一条原则）。三个必做的兜底：首帧量完再开过渡（否则开页时会从 0 滑到第一格）、切换与**列表本身变化**（如按身份多出一个 Tab）都要重量、`ResizeObserver` 兜缩放与字体替换；`prefers-reduced-motion` 下不滑。
- **懒挂载的容器：动画要挂在“内容”上，不能挂在“壳”上（v5.5）**：Reka 的 `TabsContent` 为了保住 `aria-controls`，非活动面板会留一个 `hidden` 的空壳，只把内容卸载重挂 —— 所以给“面板壳”加 CSS 动画不会重播（元素一直在，只是切换 `hidden`），要挂在它的子元素上（每次都重新创建）。同类：任何“壳常驻 + 内容 `v-if` / 懒挂载”的组件（弹层、Tab、抽屉）。
- **不要拿“表面色”去做视觉技巧，除非表面色可预测（v4.93）**：进度手柄原来用 `border: 2px solid var(--bg-base)` 描一圈，做出“从轨道里挖出来”的效果——浅色下 `--bg-base` 恰好与播放条同色所以看不出问题，深色下它接近纯黑，就成了一黑圈（需求方：“深色模式下进度条手柄处有圈黑色”）。播放条与沉浸页的底是**玻璃 + 封面渐变**，颜色预测不了，这类“描一圈表面色 / 用底色遮罩”的做法一律不要用；要分离就用**柔光/阴影**（`box-shadow`，主题无关）或不分离。判据很简：**这个颜色在深浅两主题下都确定吗？**不确定就别用。
- **行间分隔：宽列表画线、窄列表用间距（已做成按宽度自动切换，v4.91 定稿）**：需求方：“窄列表不采取细线，宽列表采用细线”（v4.90 曾一度全删，v4.91 按这条回填）。
  - **判据**：细线是一根**引导视线不串行**的对齐辅助线——行横跨的列越多越有用；列少 / 窄的时候它只是装饰，间距更透气。
  - **实现**：`--row-list-gap` 宽屏 6px（+ `.row-sep` 可见）、≤1024px 13px（+ 线 `display: none`）；**两种模式的行距都是 13px**，区别只在那条线。断点**刻意复用“专辑列收起”的 1024px**（列一收就不必画线），不要再造第二条断点。控制台曲库列表同一口径（它的线是行内 `::before`，宽屏 gap 0 / 窄屏 13px）。
  - 线要写成**独立元素或行内伪元素**，**不要**用行的 `border-top`（会沿 12px 圆角拐下去、两端留一段弧）；任何情况下不要“既贴紧又画线”（v4.28：显挤）。
  - **1px 的线必须恒等于 1 个设备像素**（v4.92）：非 100% 缩放（Windows 125%/150%，`devicePixelRatio` 1.25/1.5）下，1px 的 CSS 线是 1.25/1.5 个设备像素，凑整后同一种线会“有的粗有的细”。做法：JS 把 `devicePixelRatio` 写进 `--dpr`（`main.ts` 启动时 + `resize`），CSS 里 `--px-scale: calc(1 / var(--dpr, 1))`，线用 `transform: scaleY(var(--px-scale)); transform-origin: top center`。
  - **行距取 4 的倍数**（v4.92）：否则每条线的设备坐标相位会逐条漂移（实测行距 77 → 设备 y 65 / 161.25 / 257.5 / 353.75），即使厚度对了看着仍不匀。4 在 1 / 1.25 / 1.5 / 1.75 / 2 倍缩放下都是整数设备像素。注意 flex 的 `gap` 在分隔线**两侧各算一次**（v4.92 踩过：少算一侧导致行距 80 而不是 76）。
  - 新增列表照此：宽表格（多列展开）加线，紧凑浮层这类窄列表不画（如队列弹层）。
- **列表是“一层纵向栈”，种类靠配方类区分**（v4.47 定调，参照 Vuetify `v-divider` 的建模）：`.row-list` 里现在只有行（`.row`），将如需分组标题（如按专辑分组）再增量加。新增一种“项”＝ 加一个配方类 + 由 `TrackList` 决定插入时机，**不要另起一套列表结构**。
  但**不引入“类型化的项数组”**（Vuetify 的 `{ type: 'divider', inset }` 那种 API）：那会把数据整形推给每个调用方，而分组逻辑应该落在**带单测的纯函数**里（将来如 `utils/trackItems.ts` 的 `groupByAlbum()` 返回 `TrackListItem[]`）。等真有分组需求时再给 `TrackList` **增量**加参数（`:items` 或 `:groupBy`），现有调用点一行都不用改——这就是现在不提前造 API 的理由（没人用的分支不叫灵活性）。
- **列表页用“固定帧 + 列表内滚”**（v4.36 定稿，**取代** `.sticky-bar` 吸顶做法）：页头与操作区属于“随时要看 / 要用”的上下文，把它们作为固定层（`.page-frame` 的普通子元素），只有列表 / 表格放进 `.page-frame__scroll` 滚动；空态 / 失败态放 `.page-frame__fill` 居中。滚动区用负边距铺到岛边（`margin-inline: calc(var(--island-pad-x) * -1)` + 同样的内边距）让滚动条贴岛，并给 `min-height` 兵底。**宽度对齐不用再补**（v6.18）：滚动条浮在内容上、不占位，滚动区与固定层天然同宽（旧写法是给固定层补 `margin-right: var(--scrollbar-size)`，已删）。**不要**把“整个上部”做成吸顶：页头在带内边距的内容块里，吸顶时盖不住岛全宽，列表会从缝里露出（实拍验证过）。列表表头同理不吸顶（见上一条）。
- **正文铺满内容岛，留白要克制**（v4.34 定稿，推翻 v4.30/v4.32 的 880px 限宽+居中）：页头 / 投放区 / 列表 / 设置卡片都随岛宽铺满，不要再写 `max-width` 把正文收成窄列——窄列会在右侧或两侧留下大片空白（用户原话：“可以留白但是不能留的太多”）。**行内的多余空间要用真实信息填**（例：曲目行的专辑列），不要让一行里出现一个大洞；窄屏优先整列让位（如 ≤1024px 收起专辑列），而不是把歌名挤没。
- 图标只用 `~icons/ph/<name>`（Phosphor）；普通态默认变体，播放/激活态用 `-fill`。
- 空态一律用 `EmptyState`。
- 复杂交互（下拉菜单、右键菜单、Tooltip、Toast、Dialog、Select、Switch）用 **Reka UI**（无样式行为层）。**迁移规则（v4.15 定稿）**：参考 shadcn-vue 系实现时只翻译结构与行为（组件组合、Reka API、collapse/tooltip 门控），**丢弃其 Tailwind utility 类**，样式翻成自有语义类 + 令牌。简单件（Button/Input/滑杆/复选框）继续手写 CSS。
- 禁止引入带样式的 UI 组件库（会破坏令牌体系与玻璃拟态一致性）。

## 7. 测试（PRD 11.2，强制）

- **每个基础函数必须有至少一条单测（正常 + 异常路径），实现与测试同次提交；无用例视为未完成。**
- 框架 Vitest（前后端统一）；HTTP 集成测试用 supertest（建议，非强制但本项目已在做）。
- 用例组织：描述用中文，`it` 里说明行为与预期；测边界（空、非法、越界、时区、超大值）。
- 位置：后端 `server/test/*.test.ts`；前端与被测文件同级 `*.test.ts`。
- 前端目前 `environment: "node"`，只能测纯函数；要测组件需装 jsdom 并改 `client/vite.config.ts` 的 `test.environment`。
