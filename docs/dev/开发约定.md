# 开发约定

> 来源：PRD 5.6 技术规范 + 本项目已落地的实践。**偏离前请先在本文补一条决策记录**，否则后续协作者无法判断哪条是约定、哪条是随手写的。

## 1. 命名与数据格式（PRD 5.6.1）

- **全链路 camelCase**：API JSON 字段、JSON 文件存储、未来的 SQLite 列名（`coverUrl`、`uploadedAt`）——**不做存储层与接口层的命名映射**。
- 时间：ISO 8601 字符串（UTC）；时长：秒（number）；文件大小：字节（number）。
- ID：`nanoid` 随机；在线音源曲目在引用场景用 `provider:id`（如 `netease:123456`）。
- 需求编号是通用语言：注释里写清对应的编号，如 `// AC-03：访客级接口`。

## 2. TypeScript

- **strict 全开**，**禁用 `any`**；确实需要动态类型时用 `unknown` + 类型收窄（现有 `api/http.ts` 的 `isOk<T>` 是范例）。
- 类型导入用 `import type { ... }`（两个包都开了 `verbatimModuleSyntax`）。
- 后端相对导入必须带 `.js` 后缀（`moduleResolution: NodeNext`），例如 `import { sendOk } from "./http.js"`；前端走 bundler 解析，不带后缀。
- 公共导出函数写一行 JSDoc；**注释解释"为什么"而不是"做什么"**（例：`// 载荷不存过期时间——有效期在验签时按当前配置判定`）。
- 不要为了少写类型而放宽 tsconfig；也不要新增 `// @ts-expect-error` 除非同时写明原因。

## 3. 文件与代码组织

- Vue 组件 PascalCase（`PlayerBar.vue`），视图以 `View` 结尾（`LibraryView.vue`），控制台视图放 `views/console/`。
- composable 命名 `useXxx`；其余标识符 camelCase；**文件名与主导出体一致**。
- Pinia store 统一用 **setup 语法**（`defineStore("x", () => { ... })`），返回 ref/computed/函数；派生的布尔量（如 `canUseServer`）放 store 里，不要在每个组件重复推导。
- 一个函数只做一件事；服务端把可测的纯逻辑放 `src/services/`，路由只做"取参 → 调服务 → 回响应"。

## 4. API 设计（PRD 5.6.2）

- 成功 `{ code: 0, data }`；失败用**正确的 HTTP 状态码** + `{ code, message }`（message 给人读）。业务码只在前端需要分支处理时定义（如 `SONG_DUPLICATE`）。
- 分页（LB-08 启用时）：请求 `?page=&pageSize=`，响应 `{ items, total, page, pageSize }`。
- 路径：资源用复数名词（`/songs`、`/playlists`），动作用动词（`/upload`、`/reindex`、`/auth/login`）；音频流走 `/audio`（非 `/api`）。
- 服务端一律用 `sendOk` / `sendFail`，禁止手写 `res.json({code:0,...})`。
- 前端一律经 `client/src/api/*` 封装 + `ApiError`，**不要在组件里直接 `fetch`**。

## 5. CSS（PRD 5.6.5 + VS-08）

- **令牌分组**：`--color-*`（语义色）、`--glass-*`（玻璃拟态）、`--space-*` / `--radius-*` / `--font-*`（当前已落地 `--radius-*` 与 `--glass-*`；新增令牌请归入既有分组风格）。
- 主题变量只定义在 `tokens.css` 的 `:root`（深色默认）与 `:root[data-theme="light"]`；**组件样式只引用变量、不写死颜色**——这是双主题（VS-08）的实现前提。
- **两种材质二选一，不要乱叠**：一级容器（侧栏/内容区/控制台主区/播放条，直接贴着页面背景）用 `.glass`；放在 `.glass` 岛**里面**的卡片用 `.card`（无 backdrop-filter）。玻璃叠玻璃会互相稀释成一片灰糊，也违反 VS-07"模糊层数克制"。`.card` 的投影用 `--card-shadow` 令牌：深色下投影几乎不可见、只当轻压边；浅色下"白卡片 + 白岛面"靠它才能分出层次（去掉投影用户会立刻看得出问题）。
- **悬浮层（弹层/浮窗，如音量条）**：用接近实底的令牌色保证任何内容之上都读得清——`background: color-mix(in srgb, var(--bg-base) 86%, transparent)` + `1px var(--glass-border)` 描边 + `var(--shadow)`，圆角用 `--radius-control`；入场用 `transform: translateY(6px) scale(0.96)` → 归位，曲线 `cubic-bezier(0.32, 0.72, 0, 1)`，显隐同时切 `visibility` 以保证不可点、不进 tab 序。参考 `.vol-pop`（PlayerBar）。
- **悬浮展开的浮层必须“桥接”触发器与面板之间的空隙**：鼠标从触发器移向面板时会经过一段不属于两者的空白，`mouseleave` 会先把浮层收起（用户实测报过这个 bug）。解法：面板上挂一个覆盖空隙的透明伪元素（`::after`，高度=间距），再在底部加一个指向触发器的小三角（旋转 45° 的方块，`background: inherit` + 朝外两条边着色）。不要靠缩小间距来躲这个问题。
- 类名用简化 BEM（`block__element--modifier`）；共用外壳类（`.glass`、`.card`、`.dropzone`、`.app`、`.playerbar`、`.btn`、`.tab`…）放 `global.css`，组件私有样式放 `<style scoped>`。
- **文本可读性优先于原型数值**：深色下正文/说明文字不得低于 `--text-2`；原型里的 `--text-3` 已因实机偏暗上调（v4.16）。
- **取色禁写内联 background**：JS 只写 `--cover-src` / `--cover-src-2`；一切调校在 CSS 用 OKLCH 相对颜色语法派生（每条派生先写降级声明）。
- 新样式同步考虑：深浅双主题、`prefers-reduced-motion`、移动端不崩（RT-08）。

## 5.1 文案（界面上的字）

- **面向使用者，不面向开发者**：不写接口名（`GET /api/xxx`）、不写需求编号（`LB-04`）、不写"下一步接入"这类工程内部语言；编号只留在注释、提交信息与文档里。
- **未接入的功能不假装可用**：不渲染点了没反应的假控件（禁用态的搜索框/按钮一律先不渲染）；必须告知状态时，用一整块空态把"现在是什么 / 以后会怎样"说清楚。
- 空态文案结构：一句短标题（现在没有）+ 一句说明（会自动出现什么 or 怎么开始）。

## 6. 组件

- **长文本溢出的滚动（marquee）**：只在**明显溢出**时才滚（阈值 `MARQUEE_MIN_OVERFLOW_PX` = 24px）——只溢出一两个字就滚，会长时间停在断层上、看着像渲染坏了（v4.25 用户报过），这种情况用省略号 + `title` 悬浮提示；用**离屏探针**量文字宽度（`measureTextWidth()`，比 canvas 可靠），不要为了测量在模板里常驻隐藏元素（v4.22 踩过：多一个隐藏 span 就让 vue-tsc 生成坏代码）；滚动时渲染**两份相同文本 + `translateX(-50%)`** 实现无缝单向循环，间隔用副本自己的 `padding-right`（**不要用 flex `gap`**，否则 -50% 少走半个间隔、接缝处会跳），并给容器加两端 `mask-image` 渐隐；不滚时退回**单行 + 省略号**；时长用 `utils/marquee.ts` 按恒定速度换算并夹区间，靠全局 `prefers-reduced-motion` 降级。统一实现见 `components/ScrollingText.vue`。
- **把“是否需要滚动”变成可预期的**：承载长文本的容器必须是**固定宽度**（如播放条左侧 `--pb-left-width`，封面与信息块都固定），不要用随窗口漂移的弹性列——同一首歌一会儿溢出一会儿不溢出，滚动行为看着就像随机故障（v4.25 用户定稿）。
- **播放状态以 `<audio>` 元素为准**：`playing` 这类状态由 `play`/`pause` 事件驱动，不要只用命令式赋值（会出现“进度在走但图标仍是播放”的脱节，v4.21 踩过）。
- **静音只有一种样子，且不能清灰**：语义上 **音量为 0 就是静音**——`setVolume(0)` 同时置 `muted`，UI 侧统一用 `player.muted || player.volume === 0` 推导“静音”，四处必须一致：斜杠图标、滑杆按 0 显示（旋钮落底 + `--p: 0%`）、读数走百分比（静音时就是“0%”，不另写“已静音”）、**样式保持正常颜色**（降透明度/去饱和会被当成“禁用、点不了”，v4.23 用户反馈）；静音后再点静音键是**恢复音量**（`lastAudibleVolume`），不是再翻一次 `muted`。
- **进度条只在真正进行时出现**：不要给“等待中/已完成/失败”的行都摊上一条空进度条——一整排长灰线既无信息也无美感（v4.26 用户反馈）；进度与状态共用一列，空闲时只显示文字，行内也不因出现进度条而抽动。
- 图标只用 `~icons/ph/<name>`（Phosphor）；普通态默认变体，播放/激活态用 `-fill`。
- 空态一律用 `EmptyState`。
- 复杂交互（下拉菜单、右键菜单、Tooltip、Toast、Dialog、Select、Switch）用 **Reka UI**（无样式行为层）。**迁移规则（v4.15 定稿）**：参考 shadcn-vue 系实现时只翻译结构与行为（组件组合、Reka API、collapse/tooltip 门控），**丢弃其 Tailwind utility 类**，样式翻成自有语义类 + 令牌。简单件（Button/Input/滑杆/复选框）继续手写 CSS。
- 禁止引入带样式的 UI 组件库（会破坏令牌体系与玻璃拟态一致性）。

## 7. 测试（PRD 11.2，强制）

- **每个基础函数必须有至少一条单测（正常 + 异常路径），实现与测试同次提交；无用例视为未完成。**
- 框架 Vitest（前后端统一）；HTTP 集成测试用 supertest（建议，非强制但本项目已在做）。
- 用例组织：描述用中文，`it` 里说明行为与预期；测边界（空、非法、越界、时区、超大值）。
- 位置：后端 `server/test/*.test.ts`；前端与被测文件同级 `*.test.ts`。
- 前端目前 `environment: "node"`，只能测纯函数；要测组件需装 jsdom 并改 `client/vite.config.ts` 的 `test.environment`。

## 8. Git（PRD 5.6.3）

- Conventional Commits：`feat` / `fix` / `docs` / `test` / `refactor` / `chore` / `style` + 作用域（如 `feat(player):`、`docs(dev):`）。
- main 直接开发；里程碑完成打 tag（`m1` / `m2` / `m3`）。
- 粒度：实现与测试同次提交；文档变更用独立 `docs:` 提交（仓库历史即如此）。
- 提交前跑 `npm.cmd run typecheck; npm.cmd run test`。

## 9. 文档（PRD 5.6.6）

- 图表分工：**Mermaid** 用于时序图、状态机、逻辑流程、小 ER 图（文档内嵌、Git 可渲染）；**drawio** 用于架构总览与界面线框（`docs/design/*.drawio`）；**高保真界面**用 HTML mockup（`docs/design/mockup/`，也是样式的唯一事实来源）。
- 新增文档放 `docs/dev/`（开发类）或 `docs/design/`（设计类）；`docs/test-reports/` 留给里程碑测试报告（PRD 11.4）。
- 改需求前先改 `音乐软件需求文档.md` 并在其「修订记录」追加一行（现有 v0.1~v4.15 条目是范例：写清决策、理由与影响范围）。
