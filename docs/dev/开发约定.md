# 开发约定

> 来源：PRD 5.6 技术规范 + 本项目已落地的实践。**偏离前请先在本文补一条决策记录**，否则后续协作者无法判断哪条是约定、哪条是随手写的。

## 1. 命名与数据格式（PRD 5.6.1）

- **全链路 camelCase**：API JSON 字段、JSON 文件存储、未来的 SQLite 列名（`coverUrl`、`uploadedAt`）——**不做存储层与接口层的命名映射**。
- 时间：ISO 8601 字符串（UTC）；时长：秒（number）；文件大小：字节（number）。
- ID：`nanoid` 随机；在线音源曲目在引用场景用 `provider:id`（如 `netease:123456`）。
- 需求编号是通用语言：注释里写清对应的编号，如 `// AC-03：访客级接口`。

## 2. TypeScript

- **strict 全开**，**禁用 `any`**；确实需要动态类型时用 `unknown` + 类型收窄（现有 `api/http.ts` 的 `isOk<T>` 是范例）。
- 类型导入用 `import type { ... }`（两个包都开了 `verbatimModuleSyntax`）。
- 后端相对导入必须带 `.js` 后缀（`moduleResolution: NodeNext`），例如 `import { sendOk } from "./http.js"`；前端走 bundler 解析，不带后缀。
- 公共导出函数写一行 JSDoc；**注释解释"为什么"而不是"做什么"**（例：`// 载荷不存过期时间——有效期在验签时按当前配置判定`）。
- 不要为了少写类型而放宽 tsconfig；也不要新增 `// @ts-expect-error` 除非同时写明原因。

## 3. 文件与代码组织

- Vue 组件 PascalCase（`PlayerBar.vue`），视图以 `View` 结尾（`LibraryView.vue`），控制台视图放 `views/console/`。
- composable 命名 `useXxx`；其余标识符 camelCase；**文件名与主导出体一致**。
- Pinia store 统一用 **setup 语法**（`defineStore("x", () => { ... })`），返回 ref/computed/函数；派生的布尔量（如 `canUseServer`）放 store 里，不要在每个组件重复推导。
- 一个函数只做一件事；服务端把可测的纯逻辑放 `src/services/`，路由只做"取参 → 调服务 → 回响应"。

## 4. API 设计（PRD 5.6.2）

- 成功 `{ code: 0, data }`；失败用**正确的 HTTP 状态码** + `{ code, message }`（message 给人读）。业务码只在前端需要分支处理时定义（如 `SONG_DUPLICATE`）。
- 分页（LB-08 启用时）：请求 `?page=&pageSize=`，响应 `{ items, total, page, pageSize }`。
- 路径：资源用复数名词（`/songs`、`/playlists`），动作用动词（`/upload`、`/reindex`、`/auth/login`）；音频流走 `/audio`（非 `/api`）。
- 服务端一律用 `sendOk` / `sendFail`，禁止手写 `res.json({code:0,...})`。
- 前端一律经 `client/src/api/*` 封装 + `ApiError`，**不要在组件里直接 `fetch`**。

## 5. CSS（PRD 5.6.5 + VS-08）

- **令牌分组**：`--color-*`（语义色）、`--glass-*`（玻璃拟态）、`--space-*` / `--radius-*` / `--font-*`（当前已落地 `--radius-*` 与 `--glass-*`；新增令牌请归入既有分组风格）。
- 主题变量只定义在 `tokens.css` 的 `:root`（深色默认）与 `:root[data-theme="light"]`；**组件样式只引用变量、不写死颜色**——这是双主题（VS-08）的实现前提。
- **两种材质二选一，不要乱叠**：一级容器（侧栏/内容区/控制台主区/播放条，直接贴着页面背景）用 `.glass`；放在 `.glass` 岛**里面**的卡片用 `.card`（无 backdrop-filter）。玻璃叠玻璃会互相稀释成一片灰糊，也违反 VS-07"模糊层数克制"。`.card` 的投影用 `--card-shadow` 令牌：深色下投影几乎不可见、只当轻压边；浅色下"白卡片 + 白岛面"靠它才能分出层次（去掉投影用户会立刻看得出问题）。
- **悬浮层（弹层/浮窗）**：样式配方已按 v4.59/v4.60 更新，看上面“复杂交互件用 Reka UI”那条的第 ④⑤ 点（行为层用 Reka，样式自己写；材质按“背后有没有内容”选 chrome 玻璃或实底）。旧的“近实底 + 描边 + 投影”手写方案、以及音量浮层那个 `::after` 透明桥接补丁**都已退役**，不要再写回来：Reka HoverCard 的开合延迟 + 可交互内容判定已经把那个 bug 解决了。
- **悬浮反馈用“光”，不用“动”（v4.67）**：控件悬浮时**不要放大/位移**（鼠标刚落上去目标就变，像在躲；且位移会带动周边布局观感）。改用主题色柔光：`filter: drop-shadow(0 0 6px var(--glow-halo))`（**SVG 图标只能用 drop-shadow 上光**，`text-shadow` 对图标无效；`filter` 不改盒子尺寸，天然不扑布局）。注意：一个元素上两条 `filter` 会互相覆盖（`brightness()` 与 `drop-shadow()` 必须写在同一条里）。
- **光效只表达状态（v4.67）**：`--glow-ring` / `--glow-halo` 只用在“可交互（悬浮/聚焦）”与“播放中/选中”两种状态上，两套令牌由 `--accent` 派生（别再写一份 `color-mix(… var(--accent) …)`）。不要用光做纯装饰（光条、光斑、随机的呼吸光），那是 v4.30 “颜色只用于表达状态”的反面。
- **不要旋转原生 `input[type=range]`（v4.64 实测）**：旋转后**点击映射正确、但拖动不跟手**——浏览器用未旋转的几何算拖动位移，看起来就是“拖不动”。需要竖向滑杆就**自绘**（pointer 事件 + 自己算比例，参考 `VolumeControl` 与播放条进度条），并自己补键盘（↑↓/←→/Home/End）与 `role="slider"` + `aria-valuenow`/`aria-orientation`：原生输入框的 a11y 是随旋转一起丢的。`writing-mode: vertical-lr` 是现代替代方案，但 Firefox 兼容性待查，暂不用。
- **换自绘时把原生“白送”的东西逐个对一遍（v4.65 教训）**：换成自绘的那一次，我漏了**底轨**（灰轨本来是原生 range 的轨道，靠 tokens.css 画，自绘后不画就没有），需求方一眼看出“音量轨道不显示了”。清单：底轨 / 已完成填充 / 滑块 / 焦点环 / 键盘 / `role`+`aria-*` / 命中区宽度。
- **复杂交互件用 Reka UI（铁律 1，v4.59 首次落地）**：弹层 / 对话框 / Tab / 菜单 / Tooltip 这类“行为比样式难”的件，行为层一律用 Reka，样式自己写（它是无样式行为层，不是组件库）。落地细则：① 触发元素由**调用方**经插槽传入（Reka 的 `as-child`），不要为了包一个弹层就在新组件里复制一份触发按钮的样式（`QueuePopover` 就这么做的，参考它）；② 列表内滚仍用原生滚动，不要引 `ScrollArea`——全站滚动条是一套自绘样式，两套会打架；④ **弹层的样式必须写在非 scoped 的 `<style>` 里**（v4.60 实测纠正）：Reka 把内容 Teleport 到 body，**Vue 的 scoped 属性不会跟过去**——类名在、选择器带 `[data-v-x]` 永远匹配不上，表现是“弹层能弹出来但完全没样式”（本次两个弹层都因此静默失效过）。隔离靠类名前缀（如 `q-` / `vol-pop-`），一个 SFC 里可以同时存在一个 scoped 块 + 一个非 scoped 块；
  ⑤ **材质是阶梯，不是二选一（v4.60 → v4.63 修正）**：页面底 → 岛 / 播放条（`--chrome-bg` / `--chrome-blur`）→ **弹出的临时面板**（`--panel-bg` / `--panel-blur`，更实一档、糊得更强、带 `--panel-sheen` 内高光与自己的 `--panel-shadow`）。越靠上的层越实，这是 iOS 的做法。
  **v4.60 我写过“背后是平坦底色就用实底 `--plane-2`”，那个结论是错的**：真正的毛病是**面板与它下面的层用了同一个填充值**（音量面板浮在同样是 `--chrome-bg` 的播放条上），同色叠同色等于没画。修正后两处弹层都用 `--panel-*`，仍然是玻璃。
  另：`--shadow` 在 flat 模式被归零（那是“岛浮起来”的语言）——**浮层的投影不要用它**，用 `--panel-shadow`（“浮层该浮起来”在两种材质模式下都成立）。④ 浮层材质用 `--chrome-bg` / `--chrome-blur`（内容会从它下面经过，玻璃在这里才成立）。
- **列表内滚动不要包 ScrollArea**：同上一–②。
  - `--shadow` = “岛浮在页面上”（页面级、大扩散）；`--card-shadow` = “这张卡片是表面上的一个分组”（岛内、贴边）。撤页面级投影时**不要顺手把 `--card-shadow` 也归零**（需求方 v4.56 当场指出）——但**影与边不是二选一**：影管深度、边管边界。
  - **几何事实（别再踩）**：我们的投影全是**朝下**的偏移（`0 1px 2px` / `0 10px 22px -16px`），所以**上边缘永远没有影**。白卡落在白面板上时，上半部分必然融进背景（需求方 v4.57 实拍：“卡片上部阴影不清楚”）；白色没法再提亮，这条边界只能由描边给。别用“给投影加负偏移造上影”去糊——那会把下边缘的深度感一起做脏。
  - **判据：看相邻两层的色差**。色差足够大（白岛 vs 灰页）不用线；色差为零（白卡 vs 白岛）必须有线。深色下卡面 `--plane-2` 比岛面亮一档，色差本身就说明分组，细线只负责收边。
- **沉浸页三布局只放版式，页面级差异写进一张表**（v4.74）：`views/ImmersiveView.vue` 用 `LAYOUTS` 表把“组件 + 该布局要不要页面级右下环境光”一起声明（海报布局下彩胶的有机光晕是画面唯一主光源，右下那束同色环境光会读作色渍，PRD v4.3）。**不要**让布局组件盖一层不透明底去关掉页面背景——那会在顶栏/底栏处留一条接缝；也**不要**给 `<html>` 挂 `data-im-layout` 用类切换布局（v4.0 决策：布局是组件切换，不是类切换）。
- **位置与尺寸必须“同源派生”**（v4.75，通用规则）：一个元素（彩胶盘、背景光晕、任何吸附角落的装饰）**只能有一个尺寸驱动源**，偏移量再从该尺寸派生（`calc(var(--d) * -0.31)`）。混用 `vh` / `vw` / `min(...)` 会让“尺寸”“上偏移”“右偏移”各有各的缩放率，窗口纵横比一变就各漂各的（实测：彩胶盘心在窗口宽的 88%～94.8% 之间摆，需求方描述为“到处跑”）。需求方说“位置飘 / 到处跑”时先查这条。窄屏媒体查询里**只改尺寸**，偏移跟着派生，不要手写第二份。
- **取色管线的三条落地规则**（v4.77，VS-02 落地时实测得出）：
  - **JS 只写原始色源**（`--cover-src / --cover-src-2`），调校全在 CSS（铁律 3）；`--accent/-2/-soft`、`--glow1/2`、`--cv1/2`、`--vinyl-gradient` 全是派生，不许 JS 写。
  - **主题色的彩度地板要比彩胶高**（0.11 vs 0.07）：主题色落在悬浮行 / 进度 / 主按钮这类小面积交互件上，灰调封面取出来的暖灰会把整页染“脏”，连“这是个按钮”都读不出来；彩胶是大面积装饰色，按 PRD 保持“不强行提艳”（晨雾那类低饱和配色有理）。两者诉求不同，不要用一个书。
  - **填在主题色底上的文字用 `--on-accent`，不要写 `white`**：主题色现在由封面决定，深色主题下它是浅色，白字实测只有 1.91:1；`--on-accent` 取主题底色（深色主题近黑 / 浅色主题纯白），实测 ≥ 5.3:1。
- **渐隐遮罩（mask）只能罩「内容」，不能罩「浮在内容上的控件」**（v4.79）：上下渐隐那层 `mask-image` 原来挂在歌词外壳上，结果底部的「回到当前句」按钮被一起淡掉（实测几乎看不见）。拆成两层——外壳只负责定位并承载按钮、内层 `.ly-view` 负责渐隐与裁剪。同类的地方（列表渐隐 + 悬浮操作条 / 回到顶部按钮）都按这个来。
- **歌词引擎：机制参考，代码自己写（v4.86）**：歌词的渲染、景深、填充、交互与弹簧都是我们自己的代码（`components/immersive/LyricsView.vue` + `utils/lyrics.ts` / `utils/spring.ts` / `utils/lyricEmphasis.ts`）。AMLL 的作用是**参系对象**：v4.82 对照它的机制自研、v4.85 按需求方意思“拄代码”、v4.86 又把拄来的部分改成**按公式/按效果自行实现**（弹簧是阻尼简谐振子的解析解、辉光爆发按峰形曲线自己生成）。规则：**想做一个效果，先看它怎么做（思路可以学），然后按自己的数据模型与令牌写（代码不要拄）**——这样许可干净、后续也能随便改。
- **依赖许可每次都要查（铁律 9）**：本项目不含 AGPL / GPL 代码（现状：无 `LICENSE`、`package.json` 无 license 字段）。装新依赖前先 `npm view <pkg> license`，确认宽松许可；**强拷贝依赖一个都不要引入**。
- **遮罩渐隐带与「留白 / 内缩」必须同源（v4.82 → v4.83 修正）**：写了渐隐遮罩的地方，若还需要留白来避开这条带，**宽度只能有一份**（写成 CSS 变量，JS 用 `getComputedStyle` 读同一个值，不要在 JS 里另写一份）。**但更根本的解法是不留白**（v4.83）：上一版为了把当前句推出顶端渐隐带，在列表顶部垫了 57px 留白，结果在标题与第一句之间凭空多出一条空当（需求方圈图，DevTools 直接圈出 `padding-top: 57px`）。现在的做法：**顶端渐隐按需开关**（`--ly-fade-top`，列表没滚动就完全不淡——顶上本来就没有正在离开的行），留白随之取消；留白只在真的有用途的地方才加（列表底部半屏，是为了让末句能走到中线）。教训：**用空白去规避一个视觉副作用之前，先问这个副作用在当前状态下是否真的存在**。
- **歌词列表的位移口径：正值 = 列表上移（v4.86 实测踩坑）**：`centerShift` / `clampManualShift` 的位移都是**正值代表列表往上走**（DOM 那边写 `translateY(-shift)`），取值范围 `[0, 可达上限]`。**上限不是“内容总高 − 窗口高”**：列表末端垫了半屏留白（为了让末句能走到中线），末句到中线时内容反而比窗口矮，那样算出来的上限是 0——表现为整个列表永远不动（自动居中与手动滚动一起废）。正确口径：**上限 = 末句中心到窗口中线所需的位移**（`lastCenter − viewH/2`）。同类“列表靠 transform 位移”的场景照此办理。
- **封面的动效语言：摆正 + 用缩放表达状态（v4.89）**：音乐播放器的封面参考实现（AMLL 的 `react-full/Cover`，Apple Music 同形态）都是**平面**的——没有 rotate、没有指针跟随，也不做“呼吸浮动”；播/停的差别用**缩放**说（暂停 `scale(0.9)` + 投影收紧，曲线带一点回弹）。3D 倾斜/视差是**影音与电视类**封面的语言，不要搬到音乐封面上。圆形彩胶盘的旋转是另一回事（海报布局的专属视觉层）。
- **同一列内的文字只能有一条左边界（v4.88）**：沉浸页的标题与歌词共用同一个横向内缩令牌（`--im-text-pad-x`）——两处各写一份 padding 迟晚会错开。想给某一块“加呼吸”就改令牌，不要只改那一块。
- **带模糊/发光的内容配 `overflow` 裁剪时，裁剪框要比内容宽出一圈（v4.88）**：写法是“负外边距 + 等量内边距”（内容位置分毫不动），否则模糊出来的软边会被齐着切掉、在边缘形成一道硬线。同理，裁剪框不要紧贴文字。
- **导入外部文本文件一定要做编码回退（v4.87）**：中文歌词文件相当一部分是 GBK（老播放器导出的都是），硬按 UTF-8 读是满屏乱码。统一口径：先认 UTF-16 的 BOM → 试 UTF-8 → 出现替换字符（U+FFFD）就换 GBK 再试一次；解码器不存在时宁可返回原文也不要抛出去（实现见 `utils/lyricsLibrary.ts` 的 `decodeLyricsBytes`，有单测）。同类的“用户提供的文本文件”场景（导入、粘贴、拖入）照此办理。
- **跨页面传递不可序列化的东西（File / Blob / 类实例）用一次性交接 store**（v4.80，LC-07）：不塞路由 query、不塞 URL、也不靠模块级全局变量裸传——本地页 `queue(files)`、上传页挂载时 `take()` 取走并清空，刷新或后退都不会重复触发。**与它配套的登记处（如原始 File）生命周期必须与它标记的资源对齐**：`releaseTrack()` 里 `revokeObjectURL` 的同时忘掉 File，否则会拿着一个早已移除的曲目的文件去上传。
- **本地图片资源放 `client/src/assets/<主题>/`，CSS 里用相对 `url()` 引用**（v4.74，如彩胶四张素材）：Vite 会构建期哈希打包、路径跟着文件走；别写 `/public` 绝对路径（改目录就断），也别内联 base64（大图会撑爆 CSS）。
- **材质的可读性只加一层**（v4.74）：沉浸页已经有页面级薄雾保证文字可读，布局**不要**再加第二层方向性遮罩——多层叠起来既会把主视觉（如彩胶左缘）掠白，也违反“同一页面只保留一套分隔/压暗语言”。
- **材质双模式（v4.55，不要新增第三种写法）**：`<html data-material>` 只有 `islands`（默认，玻璃浮岛）与 `flat`（中性底色 + 实心面板）两个值，**只在 `client/src/styles/material.css` 里按模式重定义令牌**（`--bg-base` / `--plane` / `--glow*` / `--shadow` / `--card-shadow`），并只覆盖三个外壳类：`.glass`（页面级容器）、`.card`、`.playerbar`。规则：① 组件不得用 `data-material` 选择器分叉自己的样式，也不得写死颜色——想“在两种材质下都好看”就只用令牌；② `.glass` 是“页面级容器”，玻璃在该模式下不成立时就由 material.css 统一改成实心面板，不要在组件里另写一套；③ **玻璃只用在“内容会从它下面经过”的层**（浮层、沉浸页浮件）——玻璃后面没有高频细节（平滑渐变背景）时，模糊等于没有，效果只剩描边+投影，那就成了卡片，不是玻璃（v4.55 实测结论）；④ 新颜色一律先用 `--plane` / `--chrome-*` 之类的语义令牌，不要往组件里写 `#fff`。
- **悬浮展开的浮层必须“桥接”触发器与面板之间的空隙**：鼠标从触发器移向面板时会经过一段不属于两者的空白，`mouseleave` 会先把浮层收起（用户实测报过这个 bug）。解法：面板上挂一个覆盖空隙的透明伪元素（`::after`，高度=间距），再在底部加一个指向触发器的小三角（旋转 45° 的方块，`background: inherit` + 朝外两条边着色）。不要靠缩小间距来躲这个问题。
- 类名用简化 BEM（`block__element--modifier`）；共用外壳类（`.glass`、`.card`、`.dropzone`、`.app`、`.playerbar`、`.btn`、`.tab`…）放 `global.css`，组件私有样式放 `<style scoped>`。
- **文本可读性优先于原型数值**：深色下正文/说明文字不得低于 `--text-2`；原型里的 `--text-3` 已因实机偏暗上调（v4.16）。
- **取色禁写内联 background**：JS 只写 `--cover-src` / `--cover-src-2`；一切调校在 CSS 用 OKLCH 相对颜色语法派生（每条派生先写降级声明）。
- 新样式同步考虑：深浅双主题、`prefers-reduced-motion`、移动端不崩（RT-08）。

## 5.1 文案（界面上的字）

- **面向使用者，不面向开发者**：不写接口名（`GET /api/xxx`）、不写需求编号（`LB-04`）、不写"下一步接入"这类工程内部语言；编号只留在注释、提交信息与文档里。
- **未接入的功能不假装可用**：不渲染点了没反应的假控件（禁用态的搜索框/按钮一律先不渲染）；必须告知状态时，用一整块空态把"现在是什么 / 以后会怎样"说清楚。
- 空态文案结构：一句短标题（现在没有）+ 一句说明（会自动出现什么 or 怎么开始）。
- **文案自检四条**（v4.76 定稿，写完逐条对照，改不动就删掉整句）：① 有没有**需求编号**（`VS-08`、`AC-01/03`）或**里程碑名**（“M2”）；② 有没有**实现细节**（“CSS 变量”“接口”“state”）；③ 有没有**承诺尚未实现的能力**（实例：说明里写着“盘面颜色跟着封面走”，而取色管线还没接——需求方一句“这个还没做吧”就抓住了）；④ 有没有**与控件重复的说明**（缩略图/标签已经把选项讲清了，不要再逐条列一遍）。控件与说明各管一件事：控件说“能选什么”，说明只说“选了会怎样”。

## 6. 组件

- **长文本溢出的滚动（marquee）**：只在**明显溢出**时才滚（阈值 `MARQUEE_MIN_OVERFLOW_PX` = 24px）——只溢出一两个字就滚，会长时间停在断层上、看着像渲染坏了（v4.25 用户报过），这种情况用省略号 + `title` 悬浮提示；用**离屏探针**量文字宽度（`measureTextWidth()`，比 canvas 可靠），不要为了测量在模板里常驻隐藏元素（v4.22 踩过：多一个隐藏 span 就让 vue-tsc 生成坏代码）；滚动时渲染**两份相同文本 + `translateX(-50%)`** 实现无缝单向循环，间隔用副本自己的 `padding-right`（**不要用 flex `gap`**，否则 -50% 少走半个间隔、接缝处会跳），并给容器加两端 `mask-image` 渐隐；不滚时退回**单行 + 省略号**；时长用 `utils/marquee.ts` 按恒定速度换算并夹区间，靠全局 `prefers-reduced-motion` 降级。统一实现见 `components/ScrollingText.vue`。
- **把“是否需要滚动”变成可预期的**：承载长文本的容器必须是**固定宽度**（如播放条左侧 `--pb-left-width`，封面与信息块都固定），不要用随窗口漂移的弹性列——同一首歌一会儿溢出一会儿不溢出，滚动行为看着就像随机故障（v4.25 用户定稿）。
- **播放状态以 `<audio>` 元素为准**：`playing` 这类状态由 `play`/`pause` 事件驱动，不要只用命令式赋值（会出现“进度在走但图标仍是播放”的脱节，v4.21 踩过）。
- **静音只有一种样子，且不能清灰**：语义上 **音量为 0 就是静音**——`setVolume(0)` 同时置 `muted`，UI 侧统一用 `player.muted || player.volume === 0` 推导“静音”，四处必须一致：斜杠图标、滑杆按 0 显示（旋钮落底 + `--p: 0%`）、读数走百分比（静音时就是“0%”，不另写“已静音”）、**样式保持正常颜色**（降透明度/去饱和会被当成“禁用、点不了”，v4.23 用户反馈）；静音后再点静音键是**恢复音量**（`lastAudibleVolume`），不是再翻一次 `muted`。
- **进度条只在真正进行时出现**：不要给“等待中/已完成/失败”的行都摊上一条空进度条——一整排长灰线既无信息也无美感（v4.26 用户反馈）；进度与状态共用一列，空闲时只显示文字，行内也不因出现进度条而抽动。
- **“添加文件”不占一行**（v4.37 定稿）：列表 / 队列已有内容时，添加动作并进**页头操作组**（`.page-head__actions`，如 `[选择文件] [清空列表]`），不要再渲染“紧凑投放条”——那只是把同一个按钮换成换一种流式占用：一行。投放卡只留给空态（它承载格式 / 上限 / 重名 / 隐私这类**一次性说明**）；拖入反馈改用 `.drag-veil` 浮层（`position: absolute; inset: 0`，**必须 `pointer-events: none`**，不然会吞掉拖拽事件）：不挤动列表、拖拽结束即消失。拖拽监听挂 `window` 并先判 `event.dataTransfer.types.includes("Files")`，否则以后的页内拖拽（如排序）会被误接管。
- **表头与行共用一套栅格**（v4.38 定稿）：列宽写在全局 `--row-grid`（含 ≤1024px 的同断点覆盖），`TrackRow` 与 `TrackListHead` 都读它——各写一份 `grid-template-columns` 一定会漂。**最后一列用固定宽，不要用 `auto`**：`auto` 会随“本行有几个操作键”变化，有操作键的行把 `fr` 列挤窄、表头（空单元格）另行计算，实测列左边界差 27~46px。**表头住在滚动区外面**（v4.41 定稿，取代 v4.38 的“吸顶 + 不透明底”）：表头是“说明”，放进固定帧的普通子元素（`.page-frame` 直子）即可——标签常驻、列表在它下面滚，而且**不需要底色**（没有重叠就不需遮挡）。吸顶路线已废弃：吸顶必须有不透明底，而岛是玻璃材质，任何不透明色都会在岛面上露成一条**色带**（用户实拍：“是不是有个背景色”“不然看着很突兵”）。
  宽度对齐靠 **`scrollbar-gutter: stable`**，不要写滚动条宽度的魔数：滚动区与表头各留同一条 gutter，两边内容宽度天然相等（表头需要 `overflow-y: hidden` 让 gutter 生效）。实测：只给滚动区加 gutter 时，表头与行的列左边界差 11px（就是滚动条的宽度）；两边都加后完全一致（135 / 647 / 955 / 1033）。表头只放“说明”，排序 / 筛选入口统一放工具栏。表头**不给封面列留空位**：封面不是可读的信息列，“曲目”应当直接用 `grid-column: 1 / 3` 跨过封面列、与封面左边缘对齐（顶着一个空格子看着像漏了内容）。
- **破坏性动作要红 + 二次确认**（v4.46 修订，**取代** v4.38 的“就地改写按钮区”）：批量或不可逆动作（清空列表、批量删除、单曲删除）用 `btn-danger`，确认统一走 `utils/confirm.ts` 的 `confirmAction(message)`（文案带**数量 / 名字**，别让用户猜删的是哪首）。**不要**各页面自己弹窗，也不要再写 `.confirm-hint` 那套就地确认：确认必须有唯一入口，否则将来换成应用内弹窗要一处处改、还会出现两套确认语言。当前实现是原生对话框（**占位**），内部用 `globalThis.confirm`，且在环境里没有对话框时按**取消**处理（宁可不删，不可误删）。
- **主操作按钮不铺不透明主题色块**（v4.52 定稿）：播放/上传这类主操作用**半透明软件色底**表达——`--accent-soft` 底 + `--accent` 图标 + 一圈极淡描边 + 一层主题色光晕（与 `EmptyState` 的圆徽同一套语言，光晕参数按控件尺寸缩，不要照搬）。悬浮只 `brightness(1.12)`，不要叠更重的底色（软底本身就是主题色，会发闷）。光晕要**克制**：本项目最终用的是 `0 3px 14px -7px accent 45%`（半径小、不透明度低），它只是“坐得稳一点”的一层，不要做成发光按钮。**不可用/空闲态要把软底与光晕一起收掉**：一个有色却点不动的按钮最像“坏了”（用户之前就根过“一排灰按钮 + 一个点不动的亮色主按钮”）。
- **ResizeObserver 回调里不要改布局**（v4.53）：回调里插入/移除元素、改宽高都会让本帧的 RO 通知“送不出去”，控制台刷 `ResizeObserver loop completed with undelivered notifications`。需要量尺寸就**合并到下一帧**再量（`rAF` + 合并，卸载时 `cancelAnimationFrame`）——`ScrollingText` 的离屏探针就是踩过这个坑的实例。
- **全局 reset 的边界**（v4.51）：`global.css` 只做**最小 reset**——`* { box-sizing: border-box; margin: 0; padding: 0 }` + `button/input/select` 继承字体与颜色 + `a { color: inherit; text-decoration: none }`；其余 UA 默认（`select` 外观、`h1` 字号、`line-height`）**有意保留**，由组件自己定。改样式前先看一眼这里：比如给某元素加 padding 时不要假定 `box-sizing: content-box`（全站都是 border-box）；正文里真要有下划线的链接，给那个链接单独加类，别把 `a` 规则改回去。
- **服务端数据落盘**（v4.49）：索引写 JSON 一律**先写 `.tmp` 再 `rename`**（原子替换，半路被杀不会留半个 JSON）；每次请求现读现写，**不上内存缓存**（文件小，缓存失效的坑更贵）；**删除先写索引再删文件**——最坏留个孤儿文件（`reindex` 能捞回），反过来会留下指向已删文件的鬼影。
- **不要用 `express.static` 托管 `uploads/`**（v4.49）：否则 `/covers/x.mp3` 就能直接拿到音频，绕过 AC-03 的访客级门禁。媒体统一走 `/audio`、`/covers`，先过文件名形状白名单（挡 `../`）再查扩展名。
- **multipart 里的中文文件名要转码**（v4.49）：busboy/multer 按 latin1 读 `filename`，`BEYOND-海阔天空` 会变 `æµ·éå¤©ç©º`。统一过 `services/metadata.ts` 的 `decodeUploadFileName()`（取回字节再按 UTF-8 解），别在每个路由里各写一遍。
- **解析失败要回退，不要编造**（v4.49）：元数据解析失败 -> 退到**文件名解析**（与客户端共用 shared 的 `parseTrackFileName`）；索引重建时原文件名已无从得知，就只能退到落盘名——这是诚实的降级，不要凭空造句。
- **错误呈现三原则**（v4.27 定稿，上传队列为范例）：① **结果紧贴对象**——成功/失败的结果行就叠在文件名下面，不要让用户横跨整行去找原因；② **区分可重试**——文件不合规（400/413/415）不给重试按钮（重试永远不会成功），网络/5xx/429 才给，并提供「全部重试」；③ **给汇总**——顶部一句话说清“完成 x · 重复 y · 失败 z”（有失败标警示色）并挂 `aria-live`，别让用户逐行数。
- **表头与行的几何全部走共享令牌**（v4.38/v4.41/v4.44）：列宽 `--row-grid`、列间距 `--row-gap`、行内边距 `--row-pad-x`，`TrackRow` 与 `TrackListHead` 都读同一份（各写一份就会漂）；列表容器统一用 `TrackList`（它的根元素带 `.row-list`：`flex` 列 + `gap: var(--row-list-gap)`，行间**只靠间距分隔、不画线**，见下面那条）。高亮/在播曲目**按 id 判定**（`activeId`），不要用索引——列表被搜索/排序后索引会错位。表头的宽度对齐由 `.page-frame > *` 的统一补偿给（见“固定帧”那条），别再单独写一份。
- **列表行节奏：先分清两个旋钮**（v4.48）：① **行盒子高**＝封面 + 上下内边距（`min-height` 64px / `padding` 10px）——它决定悬浮/选中底色块的大小；② **行与行的间距**＝`.row-list` 的 `gap`（`--row-list-gap`，13px；它同时承担“行距”与“行间分隔”两件事）。这档调过 2 → 10 → 6 → **13**（v4.90 去掉 1px 分隔线后把 gap 从 6 补到 13，行距一格没变）。用户说“拥挤”时，指的很可能是 ②，而我只动了 ①，把行拱到 76px 反而“行高太大”——两个旋钮一定要分清。行内呼吸（两行文字 5px、列间距 `--row-gap` 20px）另算，不要再硬改 `padding`。封面 44px 正好填满封面列。
- **列表行节奏统一**：带两行文字的行（歌名+歌手、文件名+结果、标题+副标题）行高**不少于 76px**、上下内边距 12px、封面 44px，两行文字之间留 5px（v4.42/v4.43 从 62px/8px/3px 两次上调——用户连提两次“拥挤”：**行高与行内呼吸是两件事**，只加行高、不放开行内的行间距与列间距，看着依旧挤）；**任何行列表都用这一套行节奏**——队列弹层的行距就是 `.q-list` 的 flex `gap: 6px`（v4.73，用户报“这个挨的有点紧了”：两行底色贴在一起），**别改成给行加 `margin`**（首尾会多出半格、滚动位置也不好算）；列间距（曲目列表 20px）写在共享令牌 `--row-gap` 里，表头与行必须同值，否则列对不上；单行表格行可以矮些；行与行**用间距或底色分隔，不要又贴紧又画 1px 细线**（贴紧 + 细线会显挤，v4.28 用户反馈）；有底色的行必须给悬浮反馈，否则看着像点不动。
- **简约优先的检查顺序**（v4.30 定调）：先问“这块信息能不能靠**层级 / 间距**解决” → 再考虑**一条分隔线** → 最后才是底色 / 描边 / 图标；同一页面只保留一套分隔语言；颜色只用于表达状态，不做装饰；每加一个元素都要能回答“它承载什么信息”，答不出就删掉。
- **同一类控件只留一份视觉配方（v4.95）**：进度条与音量条是同一件东西（轨道 + 填充 + 手柄），配方写在 `global.css` 的一条共用规则里（`.progress .knob, .vol-pop__thumb`），两个宿主**各自只写定位**。分开写的后果实测过两次：v4.93/v4.94 刚把进度条那枚修好（去黑圈、加播放光晕），音量条那边仍是 6px 轨道 + 13px 无光圆点（需求方：“音量条样式也优化一下吧”）。同一个组件的两份实现也是同理（音量控件本身在 v4.62 就因为两处各写一套而走偏过）。
- **“呼吸光 / 光晕”用合成层动画：只动 `transform` 与 `opacity`（v4.94）**：进度手柄的播放光晕是一个 `::after` + `radial-gradient(var(--accent-soft), transparent)`，动画只改 `transform: scale()` 与 `opacity`；**不要动 `box-shadow`**（每帧重绘）或 `filter: blur()`（每帧重算）——这是“呼吸光”最常见的性能坑。另外两条：只让**播放中**呼吸（v4.30：动效只表达状态），并在 `prefers-reduced-motion` 下降级为**静态**光晕（状态仍可见）。
- **滑杆手柄默认不显示，指针在轨道上 / 键盘聚焦 / 拖动中才出现（v4.96）**：常驻圆点会把注意力从“进度/音量本身”拽到那个点上。可见性**写成一条共用规则**（两个滑杆共用，别在组件里各写一份）：`.progress:hover .knob`、`.progress:focus-within .knob`、`.progress.seeking .knob`（音量条同理换成 `.vol-pop__track`）。**拖动那一条必须有状态类兜底**——指针捕获不保证 `:hover` 还在，按住手柄拖到轨道外时手柄会凭空消失（实测过）。出现/消失用 0.15s `opacity` 过渡；`prefers-reduced-motion` 下直接切换。
- **同一条轨道上的光效共用同一份配方（v4.97）**：进度条“走过的部分”在播放中散一圈柔光（`.progress.playing .fill { box-shadow: 0 0 8px var(--accent-soft) }`），**与手柄的柔光是同一个值**——手柄是灯芯、走过的部分是灯身，同一画面里两个光值不一致会显脏（顺带：长条形的柔光要比 9px 圆点更宽/更亮才“看起来一样亮”，真嫌淡就**两处一起调**，别给轨道单开一个值）。只做“亮/不亮”的 0.3s 过渡，**不做呼吸**：一幅画面只让一个东西脉动（要呼吸的是手柄那层 `::after`），而 `box-shadow` 逐帧动就是逐帧重绘（见上一条）。
- **通用悬停规则要排除主按钮（v4.98）**：`.ctl` 是全站图标按钮的通用类，播放条与沉浸页的主按钮是 `.ctl.play`。`.ctl:hover:not(:disabled) { color: var(--text-1) }` 这类“顺带把文字色提一档”的规则会**连主按钮一起改**（(0,3,0) 压过 `.ctl.play` 的 (0,2,0)），表现是鼠标一放上去主题色图标就变成近黑/近白（需求方：“鼠标放在播放按钮上时中间图标的颜色不应该变成白色或者黑色”）。写法：通用规则加 `:not(.play)`；主按钮的悬停反馈**只有光**（`filter: drop-shadow(...)`），不换色、也不叠 `brightness()`（乘性提亮同样属于“颜色变了”）。
- **`drop-shadow` 的浓度跟着内容的 alpha 走（v4.98）**：给**半透明软底**的元素加光时，一层大 blur 几乎看不见——shadow 的有效 alpha ≈ 内容 alpha × 光色 alpha，散开就被摊平（`.ctl.play` 的圆盘只有 14% 不透明度，实测单层 10px 在浅色主题峰值差只剩 4/255）。做法是**两层同一令牌**：4px 贴着轮廓（把浓度压在边上）+ 14px 向外散（实测峰值差 60/255、5100+ 像素可见）。反过来，不透明的图标（旁边那几枚 6px 光）本来就看得见，别把两处的参数混着抄。
- **“透不透”是面板色与背后底色的对比问题，不是 alpha 问题（v5.2）**：平坦底色上把 alpha 从 0.74 降到 0.55 只差 4/255（面板色与背景几乎同色，透不透一个样）；只有背后真有色块/文字（封面渐变、列表、封面图）时 alpha 才看得出来（沉浸页平均差 22/255）。所以**“浮在上面”这件事交给描边 + 投影 + 一圈主题色光晕**，不要靠把填充堆得更实（v4.60 的老结论“面板不能和底下的玻璃同一个填充值”仍然成立，只是解法换了）。另外：`--panel-*` 是所有浮层面板（音量、队列）**共用的一份材质**，改一处三处一起变。**主题色光晕的浓度要按“最亮的那一档封面”定（v5.3）**：`--accent` 的亮度跟着封面变，同一个浓度在黄/亮色封面上看着比深色封面浓很多（需求方实拍黄色封面：“光效再低一点”）——所以浮层面板的光晕只留 25%/30% 这种“暖边”量级，真正需要“亮”的地方（播放按钮悬停）才堆层数。
- **悬浮反馈“进慢出快”（v5.0）**：`transition` 取的是**目标状态**那份声明，所以“亮起”与“熄灭”可以给不同时长——静止态写熄灭那一程（`filter 0.12s ease`，移开立即收、不黏手）、`:hover` 里写亮起那一程（`filter 0.22s ease-out`，快起慢收）。注意：`:hover` 里重写 `transition` 是**整条替换**，其它还要过渡的属性（如 `color`）得一起写上，否则一进 hover 那个属性就失去过渡、直接跳变。
- **“光更明显”靠加层与收紧，不要指望 HDR / 超白（v4.99）**：先把事实记清楚 —— ① 浏览器只对**视频与图片**做真 HDR 输出（PQ/HLG），CSS 颜色一律映射回 SDR，“只让某个元素进 HDR”是做不到的；② `(color-gamut: p3)` / `(dynamic-range: high)` 要按设备判断，`color(rec2100-pq …)` 目前在 Chrome 不支持（实测本机三个都是 false）；③ `oklch(1.2 …)` 这种“超白”语法**会被接受但会被裁到屏幕白点**，在 SDR 屏上等价于**加白**。所以在 SDR 上做“灯丝感”的办法是**同一颜色多铺几层**（`.ctl.play` 的悬停光是 2px 灯芯 + 9/20/32px 三层 `--glow-halo`：亮核 / 过渡 / 散开），而不是去找一个“更亮的颜色”。**“再亮点”的标准配方是“灯芯加密 + 最外再铺一层”（v5.1）**：只把半径推大反而会因为摊薄而**变暗**（实测峰值 88 → 74）；灯芯（同一颜色、浓度 55% → 90%）管“亮”、最外那层管“大”，两个旋钮各管一头。另：量悬停光效时**先确认过渡已停稳**（相隔 220ms 的两张截图完全一致）再取数，否则量到的是 0.22s 动画的中间态（v5.1 实测过一次，深色峰值差被读成 66 而不是 77）。配套经验：**加白的亮芯只在深色主题成立** —— 浅色主题里的“光”是暗色的主题色，白芯落在浅色圆盘上看不见（实测浅色峰值反而从 60 掉到 46），所以要么两主题都用彩色层，要么就明确“灯丝只在深色主题”。
- **验证颜色 / 过渡时先看页面可不可见（v4.97、v5.8 各误判过一次）**：页面 `hidden`（面板被挡住、窗口切走）时 **CSS transition 不推进**，`getComputedStyle` 读到的是过渡的**起点**。最典型的一次：切换主题后 `.set-card > b` 的颜色“恰好落后一个主题”—— 其实 `body { transition: color 0.3s }` 冻在原值上，看着很像 bug。要读真实值就先确认 `document.visibilityState === "visible"`，或者用 `document.getAnimations()` 看过渡本身在不在。
- **两种状态用不同字号时，把 `line-height` 写死（v5.12）**：字号一变，默认行高（`normal`）跟着变，盒子高度就变 —— 侧栏折叠态把 logo 字号 17 → 20px，logo 盒子 44 → 48，**下面所有图标在点击那一帧瞬跳 4px**（实测 `[38, 86.4]` → `[38.5, 90.4]`），肉眼看就是“图标在跳”。需要不同字号又要布局不动，就给容器一个确定的盒（写死 `line-height` 或固定 `height` + `align-items: center`）。
- **同一类列表项用同一个“项间距”（v5.11）**：贴在一起时，悬浮/选中的圆角底色会上下连成一块（侧栏折叠态最明显，需求方：“又挤在一起了”）；而同一份 UI 里两种节奏并存（主体 0、页脚 2px）只会让人当成 bug。侧栏取 4px（对齐 shadcn 的 `SidebarMenu` 的 `gap-1`），并**写成一条共用规则**给导航与页脚。
- **宽度动画期间内容会跟着回流：让内层宽度跟着一起动画，而不是“点一下换布局”（v5.10 → v5.13 修正）**：侧栏折叠是网格列 224 → 68。第一版把内层宽度**瞬时**切成 68（想避免文字回流），结果选中高亮（项自己的底色）在点击那一帧从 200px 瞬变 44px —— “高亮的背景会前后动”。正确解法：**让内层宽度与内边距跟列宽用同一时长/缓动一起动画**（文字仍然不会回流，因为标签 `nowrap` + 外层 `overflow: hidden` 会把多出来的部分裁掉）；并且折叠态**只改宽度**，任何 `justify-content` / `padding` / 外边距的切换都会让元素在点击那一帧横跳（实测：分组标题一藏，右上角加号被 `space-between` 推到最左，一跳 161px —— 最后按 shadcn 的做法在 icon 态直接 `display: none`）。
- **别用“过渡期间覆盖 animation、结束后撤掉”来压动画（v5.21）**：写 `html[data-vt="on"] .im { animation: none }`，过渡结束时把 `data-vt` 一撤 —— 被取消的动画会**从第一帧重新开播**（需求方看到的就是“动画结束后闪一下”）。压动画要用**持久标记**：把“要不要动画”在页面创建时定下来（`ImmersiveView` 在 setup 里读一次 `data-vt`，是就给自己挂 `no-enter`），而不是跟着某个变量的生死开关。同一条也适用于任何“临时给元素加个类或属性去改动画”的写法。
- **看得见的入口必须真的能进（v5.20）**：侧栏在未登录时也显示「设置」，但 `/settings` 当时没有 `meta.anonymous` —— 点进去就被守卫送到登录页要密码（需求方：“为什么点击设置需要密码？”）。规矩：**渲染出来的入口**（导航、按钮、卡片里的链接）与**路由可达性**必须一致：要么按角色把它藏掉，要么让目标页面在未登录下也能进（并把服务端相关的分组/块按角色裁掉）。代价是“本地偏好”类页面（主题/布局/快捷键）不该被门禁挡住 —— 未登录模式（AC-01）同样需要它们。另：身份变化会把分组抽走，**当前选中项若不存在要退回默认项**，否则面板会停在一个不存在的值上（白屏）。
- **共享元素过渡（View Transition）的九条自测清单（v5.18 → v5.19）**：用在“同一张封面从小变大”这种场景（播放条 ⇄ 沉浸页）效果很好，但坑很集中：① 两端各挂同名 `.vt-cover`（`view-transition-name: qt-cover`），且**该名字在任一时刻只能有一个元素**——否则浏览器直接跳过整个过渡（我们的两个页面不共存，所以天然成立）；② 回调里要 `await 导航` + `nextTick()`（快照在回调 promise 落地后才拍）；③ **`router.back()`（history traversal）会把手动起的过渡掐掉**（实测 ready 后 11ms 跳完；`push`/`replace` 正常跑满 435ms）——关闭改成 `replace(来路)`；④ 过渡期间在 `<html>` 上挂 `data-vt`，让新页自己的入场动画让位（否则快照拍到的是 opacity 0 的空页）；⑤ 封面这一对要关掉交叉淡化（`::view-transition-old/new(*) { animation: none }`）——但这只在“旧/新确实是同一张图”时成立，换成两个不同的东西就会**两图叠加**（彩胶实测），那种情况宁可不参与；⑥ **只画大位图那一侧快照**：飞行中的快照是**被拉伸的位图**，两端位图分辨率通常差几倍（播放条封面 52px / 沉浸页封面 ~254px），所以要在 `::view-transition-old/new(*)` 里把“小”的那一侧 `opacity: 0`——而哪一侧是“小”的取决于方向（飞入时 `old` 小、飞出时 `new` 小），所以 `withViewTransition(update, "in" | "out")` 要收方向参数、写成 `html[data-vt-dir]` 供 CSS 用。既不交叉淡化（两张半透明的图叠在一起会“几乎看不见封面”，原型实测如此）、也不两侧都画（其中一侧必定是糊图）；
  ⑦ **同名元素在任一时刻只能有一个**：否则浏览器直接跳过整个过渡。原型是单页 overlay，两个封面共存，所以它要在回调里把 `viewTransitionName` 从一个小图**动态搬到**另一个（`show ? "none" : "cover"`）——我们的两个页面不共存，天然满足，但若将来改成 overlay 就必须补这一步；
  ⑧ 加一个 1.5s 看门狗 `skipTransition()`（个别环境过渡不结束会把旧页快照永久留在顶层）；⑨ `prefers-reduced-motion` 时连 API 都别调。另：`animation-timing-function` 写在 `::view-transition-group()` 上是**生效**的，但只用 `getComputedTiming().progress` 看不出来（那是动画级缓动），要验就采样**渲染出来的** transform。
- **“同一个左内边距”不等于“同一条中轴”（v5.17）**：图标列宽 19px、品牌标记盒 26px，两者都从 12px 左内边距开始，中轴就差了 (26−19)/2 = 3.5px —— 展开态看着只是“稍微不齐”，**窄栏里（周围只剩图标）一眼就看出 logo 没居中**（需求方圈图指出来）。要按中轴对齐就写成 `calc(12px − (var(--brand-mark-size) − 19px) / 2)`（侧栏 8.5 / 控制台 9.5），顺带让品牌文字与导航文字对齐（68.5 / 69）。规律：**一行里的元素宽度不同时，对齐目标要明确选“左边界”还是“中轴”**，选左边界就得接受中轴偏移，反之亦然。
- **品牌标记用“遮罩 + 变量上色”，不要直接放 `<img>`（v5.16）**：单色 logo 一律做成“透明底单色标记”当遮罩用（`background: var(--accent)` + `mask: url(...) center / contain`）——深浅主题、封面取色自动跟着走，也不用为 HiDPI 出多套图；尺寸统一走 `--brand-mark-size`（侧栏 26 / 控制台 24 / 登录页 30，默认 22）。配套一条：**图片元素不要放进靠行高撑高度的行盒**——它的基线对齐会把图片高度算进行盒（盒子会比预期高），要用 flex 对齐 + 写死行高，否则会重演 v5.12 的“图标瞬跳”（侧栏 logo 盒两态都必须 48px）。
- **抹素材上的第三方水印，优先“裁掉”而不是“涂白”（v5.16）**：AI 生成图的水印通常压在角落。做法是用“只认主体颜色”的严格阈值（只认深色）求 artwork 包围盒 → 按包围盒 + 小边距裁剪，水印自然不在结果里，且不会留下修补痕迹（涂白/模糊在有渐变或纹理的底上一定会露）。动手前先量一下水印像素的实际范围，确认它与包围盒不相交（实测浅灰水印在 `x 631–751 / y 725–753`，artwork 包围盒到 `668/685` 为止）。
- **滚动范围只包住“会无限增长”的那部分，外壳控件一律固定（v5.15）**：侧栏曾经把整列做成滚动容器（`.sb-inner { overflow-y: auto }`），品牌 / 导航 / 歌单 / 页脚全在一条滚动流里 —— 窗口一矮（实测 ≤ 440px）或列表一长，**页脚的「设置 / 折叠侧边栏」就被推到滚动区外面**（300px 高时页脚底 318 > 可视底 174），而且任何“要不要滚动”的变化都会把项与高亮挤窄 10px。正确分工是品牌与页脚 `flex: none` 钉住 + 中段（导航 + 歌单，未来的列表）包进唯一滚动区（shadcn 的 `SidebarHeader/Content/Footer` 同构）。判断标准：**这个内容会不会随数据无限增长、或者说它会不会被用户“滚走”**——外壳控件、导航、页脚都是“永远要能在手边”的那类。播放器侧栏 `.sb-scroll` 与控制台侧栏 `.cs-nav` 用同一套（改动要同步两处）。
- **稳定滚动条槽要挪进内边距，不要让它吃内容（v5.15）**：`scrollbar-gutter: stable` 能治“滚动条出现/消失时内容跳一下”，但它默认是**永久把内容盒窄 10px**（侧栏就变成左边 12px、右边 22px，一眼就歪）。配一条 `margin-right: calc(var(--scrollbar-size) * -1)` 把槽挪进容器的内边距里，内容盒宽度就与不滚动时**完全一致**（展开 200 / 折叠 44），滚动条落在面板边缘 2px 处、永远不压住项与高亮 —— 思路与 `.page-frame` 的“负边距铺到岛边”同源。实测：注入 40 条歌单令列表溢出的前后，导航项都是 `[26, 200]`。
- **`overflow-y: auto` 会顺手把 `overflow-x` 也变成 `auto` —— 动画里会冒横向滚动条（v5.14）**：CSS 规定 `overflow-x/y` 其中一个不是 `visible` 时，另一个的 `visible` 会被算成 `auto`。侧栏内层只写了 `overflow-y: auto`，展开动画中有两三帧“内层还窄、文字已瞬时显形”，于是**底部冒出一条横向滚动条又消失**（实测展开第 25ms：内层 81px、横向溢出 36px、滚动条高 10px），需求方直接看出“底部跳变、像个滚动条”。**要裁切就显式写 `overflow-x: hidden`**（或两边都写全），别指望只写纵向就没事；量这种问题看 `scrollWidth - clientWidth` 与 `offsetHeight - clientHeight`。
- **scoped 样式里不要写 `display`，除非想盖掉全局的响应式规则（v5.10）**：移动端靠 `global.css` 的 `.sidebar { display: none }` 收侧栏，而 scoped 选择器 `.sidebar[data-v-x]` 特异性更高 —— 在组件里随手写一句 `display: flex` 就会让它窄屏又冒出来（网格已经是 `1fr`，会直接盖住内容）。
- **共享指示条/底板是兄弟节点时，内容层必须自己抬起来（v5.9）**：滑动底板写在按钮组的后面（Vue 模板里后写的先不上面，而**同为定位元素时后画的在上**），于是选中项的文字会被那块颜色盖住 —— 看上去像“字体或颜色出了问题”。做法：给真正装内容的元素（`.seg__opt`）`position: relative; z-index: 1`。（Tab 下划线没这个问题：它在文字**下方**。）
- **字符串 `ref="name"` 在 vue-tsc 里不算“使用”（v5.9）**：只在模板里用字符串 ref 绑定的 setup 变量会被 `noUnusedLocals` 报 TS6133（之前没爆是因为脚本里也读了它）。两个办法：在脚本里真读一次，或者改用**函数 ref**（`:ref="setRoot"`）—— 后者更干净，组合式函数把 ref 收在自己内部。
- **靠 DOM 结构写的选择器，动结构后要回头验证（v5.7 踩过一次静默失效）**：`.tabs ~ [role="tabpanel"]` 在 v5.6 给 `TabsList` 裹了一层 `.tabs-wrap` 之后就再没匹配过（面板不再是 `.tabs` 的兄弟），页面**不报错**、只是动画悄悄消失，直到需求方问“内容切换能有过渡效果吗”才发现。所以：用兄弟 / 父子关系选元素时，**加包裹层要同步搜一遍旧选择器**（`grep` 一下 `.tabs ~` 这类写法）；能用自有 class 就优先用 class。
- **要“滑过去”的指示条只能是一条共享元素（v5.6）**：给每个 tab 自己的 `border-bottom` 换颜色，只能原地淡入淡出，切页时看着就是“灭了又亮”；要滑动就得抽出一条 `position: absolute` 的指示条，JS 只量**两个原始值**（当前格的 `offsetLeft` / `offsetWidth`）写成 CSS 变量，滑动与宽度变化交给 CSS 过渡（与取色管线同一条原则）。三个必做的兜底：首帧量完再开过渡（否则开页时会从 0 滑到第一格）、切换与**列表本身变化**（如按身份多出一个 Tab）都要重量、`ResizeObserver` 兜缩放与字体替换；`prefers-reduced-motion` 下不滑。
- **懒挂载的容器：动画要挂在“内容”上，不能挂在“壳”上（v5.5）**：Reka 的 `TabsContent` 为了保住 `aria-controls`，非活动面板会留一个 `hidden` 的空壳，只把内容卸载重挂 —— 所以给“面板壳”加 CSS 动画不会重播（元素一直在，只是切换 `hidden`），要挂在它的子元素上（每次都重新创建）。同类：任何“壳常驻 + 内容 `v-if` / 懒挂载”的组件（弹层、Tab、抽屉）。
- **不要拿“表面色”去做视觉技巧，除非表面色可预测（v4.93）**：进度手柄原来用 `border: 2px solid var(--bg-base)` 描一圈，做出“从轨道里挖出来”的效果——浅色下 `--bg-base` 恰好与播放条同色所以看不出问题，深色下它接近纯黑，就成了一黑圈（需求方：“深色模式下进度条手柄处有圈黑色”）。播放条与沉浸页的底是**玻璃 + 封面渐变**，颜色预测不了，这类“描一圈表面色 / 用底色遮罩”的做法一律不要用；要分离就用**柔光/阴影**（`box-shadow`，主题无关）或不分离。判据很简：**这个颜色在深浅两主题下都确定吗？**不确定就别用。
- **行间分隔：宽列表画线、窄列表用间距（已做成按宽度自动切换，v4.91 定稿）**：需求方：“窄列表不采取细线，宽列表采用细线”（v4.90 曾一度全删，v4.91 按这条回填）。
  - **判据**：细线是一根**引导视线不串行**的对齐辅助线——行横跨的列越多越有用；列少 / 窄的时候它只是装饰，间距更透气。
  - **实现**：`--row-list-gap` 宽屏 6px（+ `.row-sep` 可见）、≤1024px 13px（+ 线 `display: none`）；**两种模式的行距都是 13px**，区别只在那条线。断点**刻意复用“专辑列收起”的 1024px**（列一收就不必画线），不要再造第二条断点。控制台曲库列表同一口径（它的线是行内 `::before`，宽屏 gap 0 / 窄屏 13px）。
  - 线要写成**独立元素或行内伪元素**，**不要**用行的 `border-top`（会沿 12px 圆角拐下去、两端留一段弧）；任何情况下不要“既贴紧又画线”（v4.28：显挤）。
  - **1px 的线必须恒等于 1 个设备像素**（v4.92）：非 100% 缩放（Windows 125%/150%，`devicePixelRatio` 1.25/1.5）下，1px 的 CSS 线是 1.25/1.5 个设备像素，凑整后同一种线会“有的粗有的细”。做法：JS 把 `devicePixelRatio` 写进 `--dpr`（`main.ts` 启动时 + `resize`），CSS 里 `--px-scale: calc(1 / var(--dpr, 1))`，线用 `transform: scaleY(var(--px-scale)); transform-origin: top center`。
  - **行距取 4 的倍数**（v4.92）：否则每条线的设备坐标相位会逐条漂移（实测行距 77 → 设备 y 65 / 161.25 / 257.5 / 353.75），即使厚度对了看着仍不匀。4 在 1 / 1.25 / 1.5 / 1.75 / 2 倍缩放下都是整数设备像素。注意 flex 的 `gap` 在分隔线**两侧各算一次**（v4.92 踩过：少算一侧导致行距 80 而不是 76）。
  - 新增列表照此：宽表格（多列展开）加线，紧凑浮层这类窄列表不画（如队列弹层）。
- **列表是“一层纵向栈”，种类靠配方类区分**（v4.47 定调，参照 Vuetify `v-divider` 的建模）：`.row-list` 里现在只有行（`.row`），将如需分组标题（如按专辑分组）再增量加。新增一种“项”＝ 加一个配方类 + 由 `TrackList` 决定插入时机，**不要另起一套列表结构**。
  但**不引入“类型化的项数组”**（Vuetify 的 `{ type: 'divider', inset }` 那种 API）：那会把数据整形推给每个调用方，而分组逻辑应该落在**带单测的纯函数**里（将来如 `utils/trackItems.ts` 的 `groupByAlbum()` 返回 `TrackListItem[]`）。等真有分组需求时再给 `TrackList` **增量**加参数（`:items` 或 `:groupBy`），现有调用点一行都不用改——这就是现在不提前造 API 的理由（没人用的分支不叫灵活性）。
- **列表页用“固定帧 + 列表内滚”**（v4.36 定稿，**取代** `.sticky-bar` 吸顶做法）：页头与操作区属于“随时要看 / 要用”的上下文，把它们作为固定层（`.page-frame` 的普通子元素），只有列表 / 表格放进 `.page-frame__scroll` 滚动；空态 / 失败态放 `.page-frame__fill` 居中。滚动区用负边距铺到岛边（`margin-inline: calc(var(--island-pad-x) * -1)` + 同样的内边距）让滚动条贴岛，并给 `min-height` 兵底。**宽度对齐只在 `.page-frame > *:not(.page-frame__scroll)` 这一处补**（`margin-right: var(--scrollbar-size)`）：滚动区里的内容总是窄一条滚动条，固定层的块（页头/工具条/投放卡/表头）必须同样收窄，否则同一岛上两块宽度不一致（用户实拍：“两个宽度不一致”）。**用 margin 不要用 padding**：padding 只收窄内容盒，块自己的底色与描边仍然满宽，卡片还是对不齐。滚动条宽度必须是确定值：Chromium 里设了 `scrollbar-color` 会让它改用原生滚动条、忽略 `::-webkit-scrollbar` 的宽高（实测 16px），所以两个引擎分开写。**不要**把“整个上部”做成吸顶：页头在带内边距的内容块里，吸顶时盖不住岛全宽，列表会从缝里露出（实拍验证过）。列表表头同理不吸顶（见上一条）。
- **正文铺满内容岛，留白要克制**（v4.34 定稿，推翻 v4.30/v4.32 的 880px 限宽+居中）：页头 / 投放区 / 列表 / 设置卡片都随岛宽铺满，不要再写 `max-width` 把正文收成窄列——窄列会在右侧或两侧留下大片空白（用户原话：“可以留白但是不能留的太多”）。**行内的多余空间要用真实信息填**（例：曲目行的专辑列），不要让一行里出现一个大洞；窄屏优先整列让位（如 ≤1024px 收起专辑列），而不是把歌名挤没。
- 图标只用 `~icons/ph/<name>`（Phosphor）；普通态默认变体，播放/激活态用 `-fill`。
- 空态一律用 `EmptyState`。
- 复杂交互（下拉菜单、右键菜单、Tooltip、Toast、Dialog、Select、Switch）用 **Reka UI**（无样式行为层）。**迁移规则（v4.15 定稿）**：参考 shadcn-vue 系实现时只翻译结构与行为（组件组合、Reka API、collapse/tooltip 门控），**丢弃其 Tailwind utility 类**，样式翻成自有语义类 + 令牌。简单件（Button/Input/滑杆/复选框）继续手写 CSS。
- 禁止引入带样式的 UI 组件库（会破坏令牌体系与玻璃拟态一致性）。

## 7. 测试（PRD 11.2，强制）

- **每个基础函数必须有至少一条单测（正常 + 异常路径），实现与测试同次提交；无用例视为未完成。**
- 框架 Vitest（前后端统一）；HTTP 集成测试用 supertest（建议，非强制但本项目已在做）。
- 用例组织：描述用中文，`it` 里说明行为与预期；测边界（空、非法、越界、时区、超大值）。
- 位置：后端 `server/test/*.test.ts`；前端与被测文件同级 `*.test.ts`。
- 前端目前 `environment: "node"`，只能测纯函数；要测组件需装 jsdom 并改 `client/vite.config.ts` 的 `test.environment`。

## 8. Git（PRD 5.6.3）
